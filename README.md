# B612

『어린왕자』와 『슈퍼마리오 갤럭시』를 축으로 한, 우주 배경의 카툰풍 3D 플랫포머 컨셉 데모입니다.
작은 행성마다 중력이 있어서 행성을 한 바퀴 걸어서 돌 수 있고, 약한 중력 속에서 점프하며 행성 사이를 건넙니다.

목표 게임의 기본 기획과 검토 사항은 [기본 게임 기획](Docs/GameDesign.md)에 정리되어 있습니다. 아래는 현재 컨셉 데모의 안내입니다.

![밤 전경](Assets/Captures/B612_Night.png)

## 시작하기

1. **Git LFS 설치** — 모델과 텍스처가 Git LFS로 올라가 있습니다. <https://git-lfs.com> 에서 설치한 뒤 한 번만 실행하세요.
   ```
   git lfs install
   ```
2. **받기**
   ```
   git clone https://github.com/hpc99jtzqd-dot/B612.git
   ```
3. **Unity Hub에서 열기** — 반드시 같은 버전 **Unity 6000.3.23f1** (Unity 6.3, URP)로 엽니다.
   처음 열 때는 Library 폴더를 새로 만드느라 몇 분 걸립니다.
4. `Assets/B612/Scenes/B612_Night.unity` 를 열고 ▶ Play.

| `B612_Diorama` | 낮 버전 |

### 바오밥 스폰 시제품 실행

`Assets/B612/Scenes/B612_EmptyPlanet.unity`를 열고 Play를 누릅니다. 120초 동안 약 3초마다 싹을 생성하되 동시에 존재하는 싹은 최대 6개입니다. 생성 수가 적은 구역을 우선하고 싹 사이에 최소 1.4m 간격을 두어 옆면과 밑면까지 분산합니다. 화면 상단의 바와 숫자로 남은 시간, 현재 활성 수와 누적 생성 수를 확인할 수 있습니다. 아래의 별도 `BAOBAB THREAT` 바가 100%가 되면 게임 오버입니다.

행성에 가려진 싹은 해당 방향의 지평선 근처에 싹 아이콘 말풍선으로 표시됩니다. 싹이 보이면 표시를 숨깁니다. 지평선이 화면 밖인 방향은 화면 가장자리에 표시합니다. 6개가 차면 생성을 건너뛰며, 양이 싹을 먹으면 다음 생성 시점에 빈자리를 채웁니다.

`Baobab Surge`의 Inspector에서 시간, 생성 기회 수(`Target Sprouts`), 동시 상한(`Max Active Sprouts`), 최소 간격, seed를 조절합니다. 기본은 Play마다 다른 seed입니다. 행성의 `PlanetSurfaceGrid`를 선택하고 Scene 뷰의 Gizmos를 켜면 80개 구역의 경계가 보입니다. 구역은 논리 데이터이며 지형의 모양은 바꾸지 않습니다.

이번 시제품에는 양의 싹 먹기와 카드 회수가 있습니다. 작물·양털·특성·퀘스트·행성 파괴는 아직 구현하지 않았습니다. 40번의 생성 기회·1.4m 등은 첫 테스트용 수치입니다. 세부 구현과 아직 제안 상태인 범위는 [행성 생성 설계](Docs/PlanetGenerationDesign.md)를 참고하세요.

### 바오밥 위험도와 게임오버

- 살아 있는 싹 각각의 위험량은 `min(25, 2 + 0.15×생존 초 + 0.005×생존 초²)`입니다. 합산한 위험량을 행성의 고정 한계량 100으로 나누어 게이지를 표시합니다. 오래된 싹일수록 상한 전까지 빠르게 성장합니다.
- 양이 먹는 동안도 위험량은 증가하며, 먹기가 끝나서 싹이 제거되면 그 싹의 위험량이 사라집니다. 먹는 싹의 말풍선을 숨기는 규칙은 유지합니다.
- 120초는 **신규 생성의 종료 시간**입니다. 이후에도 남은 싹은 성장하고 패배할 수 있습니다. 전부 제거하면 `PLANET SAFE`가 표시되며, 수확 단계로의 이동은 아직 없습니다.
- 100%에서 생성·성장·양 먹기·소환·플레이어 및 카메라 조작을 정지합니다. **TRY AGAIN 버튼 / Enter**로 현재 씬과 카드·타이머·게이지를 초기화합니다.
- `Assets/B612/Settings/PrototypeBaobabProfile.asset`에서 고정 한계량, `BasicBaobab.asset`에서 싹 성장 수치를 조절합니다. 설정은 실행 시작 시 복사되므로 변경한 밸런스는 새 시도부터 적용됩니다. 생성 수량은 계속 `Baobab Surge` Inspector에서 조절합니다.

기본 설정을 방치하면 약 48.47초에 패배합니다. 최종 난이도가 아닌 첫 검증값입니다. 구현 선택과 검증 결과는 [바오밥 위험도 설계](Docs/BaobabThreatDesign.md)를 참고하세요.

### 양 카드 조작

- 하단에 양 카드 4장을 들고 시작합니다. **휠 / 숫자 1~4**로 선택하고 **Q**로 지면에 소환합니다.
- 선택한 카드가 올라오며 예상 먹기 범위가 지면에 표시됩니다. 가까운 싹이 금색 원으로 표시되면 그 싹을 우선으로 배치합니다.
- 양은 20초간 머물고, 범위 안의 싹을 10초에 한 개씩 먹습니다. 기본 범위는 1.7m이고 거리 경계에 작은 여유를 둡니다. 같은 싹은 여러 양이 중복으로 먹지 않습니다.
- 만료된 양은 작아져 약간 떠서 회전합니다. 가까이 걸어가면 회수하고 같은 카드가 손패로 돌아옵니다.
- 먹는 양 위의 원형 파이로 싹 하나를 먹는 진행도를 확인합니다. 지평선 너머나 대기·만료 상태에는 이 진행 표시가 나오지 않습니다.
- 행성 뒤의 회수용 양은 양 아이콘 말풍선으로 안내합니다. 싹·양 말풍선은 실제 대상이 가까우면 크게, 멀면 작게 보입니다.
- 이 씬의 카메라는 **마우스 드래그 / Z·C**, 줌은 **Ctrl+휠**입니다. 다른 데모 씬의 조작은 아래 기존 표를 따릅니다.

시간·먹기 범위·초기 카드 수는 `Lamb Card Hand` Inspector에서 조절할 수 있습니다. [양 시제품 설계와 검증](Docs/LambPrototypeDesign.md)에 소스와 동작 기준을 정리했습니다.

카메라는 행성 중심을 기준으로 자세를 유지하고, 일반 점프에는 자동 줌·공중 자동 회전을 적용하지 않습니다. 점프 높이는 일정 여유 안에서 화면 속 움직임으로 보여주며, 큰 상승·낙하만 추적합니다. 장애물에 접근하면 즉시 안전 거리로 당기고 천천히 복귀합니다. 수동으로 조절한 시야 각도도 유지합니다. 조절값과 전후 비교는 [카메라 안정화 설계와 구현](Docs/CameraStabilityDesign.md)을 참고하세요.

## 데모에 있는 것

- 메인 행성 B-612: 집(안에 들어가면 벽이 반투명해짐), 화산 3개, 장미, 바오밥 새싹
- 반대편의 바오밥 숲 (등불, 빛나는 버섯, 숨은 별)
- 징검돌을 건너 가는 시계 별, 돌아올 때는 발사 별(Space)
- 별 6개 모으기
- 왕자를 따라다니는 여우 (멈추면 앉아서 왕자를 바라봄)
- 절차적 밤하늘 (은하수, 별, 초승달, 별똥별)

## 폴더 구조

```
Assets/B612/
  Scenes/      씬
  Scripts/     게임 코드 (중력, 이동, 카메라, 애니메이션, 집 내부, 발사 별 …)
  Shaders/     밤하늘, 반딧불 셰이더
  Models/      왕자(Meshy), 여우(Blender) 모델
  Generated/   빌더가 만든 메시·재질·프리팹 (직접 수정하지 말 것)
AgentScripts/  씬과 모델을 생성하는 스크립트
  B612Builder.cs           씬 전체를 다시 만드는 빌더 (Unity CLI로 실행)
  blender/                 캐릭터 모델 생성 스크립트 (Blender 5.2)
  runtime/                 Assets/B612/Scripts 원본
```

> 씬과 `Generated/` 는 `AgentScripts/B612Builder.cs` 가 처음부터 다시 만듭니다.
> 씬을 손으로 수정한 뒤 빌더를 다시 실행하면 수정 내용이 덮어써지니, 이 점을 맞춰서 작업해 주세요.
