# 챕터별 이동 성장과 타일 기반 절차적 지형 설계

2026-11-09 최초 작성, 2026-11-11 후속 구현. 다른 게임의 공개 개발 자료와 현재 B612 코드를 바탕으로 한 **기술 설계안**이다. 후속 요청으로 **15절의 1~4단계 시제품**을 구현했다. 기본 기획은 `GameDesign.md`, 논리 격자는 `PlanetTileDensityImplementationSpec.md`, 이동 규칙은 `PlayerTraversalImplementationSpec.md`를 따른다. 실제 규격·검증은 `TraversalTestCourseStage1Results.md`, `ProceduralTerrainStage2Results.md`, `ProceduralTerrainStages34Results.md`를 참고한다. 아래의 폭넓은 미래 계약과 현재 시제품 구현 범위는 구분한다.

16절의 실제 플레이 적용은 구현 기록이다. **2026-11-14 지형 외관 개선의 새 구현 범위와 완료 조건은 [17절](#17-지형-외관-개선-구현-명세)에 있다.** 이번 변경은 코드 조사와 명세 작성이며, 17절의 기능은 아직 구현하지 않았다. 외관·높이 합성 관련 과거 제안과 충돌하면 17절을 우선하고, 16절의 검수 규격·필수 배치·이동 검증은 유지한다.

## 1. 사용자 요구와 설계의 결론

사용자가 제시한 방향:

- 항성계 진행을 크게 3개 챕터로 구성한다.
- 진행하면서 대쉬·더블점프·활공 등을 해금해 이동 능력이 성장한다.
- 골짜기·강·높은 언덕 때문에 초반에는 우회하지만, 능력을 얻으면 더 쉽게 건너는 경험을 만든다.
- 타일별 가중치와 노이즈를 이용해 자연스럽게 지형을 생성한다.

권장 구조는 **이동 동선 설계 + 연속 지형 노이즈 + 검수한 장애물 조합 + 실제 이동 검증**이다. 타일마다 독립적으로 높이와 장애물을 추첨하는 방식은 피한다.

```text
챕터·진입 능력 확정
  → 큰 지형의 노이즈 필드
  → 필수 공간·우회로·능력 지름길 계획
  → 여러 타일에 걸친 지형 요소 배치
  → 연속된 지면 메시·Collider 생성
  → 현재 능력으로 검증·수정
  → 최종 생성 지점과 콘텐츠 배치
```

3챕터 구성과 성장 방향은 사용자 요구다. 아래 해금 순서·노이즈 수치·가중치·지형 개수·경사와 여유 기준은 **검증 전 제안값**이다. 챕터와 항성계의 일대일 대응, 챕터별 행성 수와 정확한 해금 이벤트는 미정으로 둔다.

## 2. 다른 게임에서 참고할 점

공개 자료에서 확인한 사실과 B612에 적용하는 판단을 구분한다. 다른 게임의 내부 지형 알고리즘을 그대로 재현한다는 뜻은 아니다.

### Dead Cells: 동선의 역할을 정한 뒤 지형 조각을 조합

리드 디자이너 Sébastien Bénard는 큰 세계 구조와 경로 해금 요소, 목적별 수작업 방, 바이옴별 연결 그래프를 먼저 정하고 그 조건에 맞는 방을 조합하는 방식을 설명한다. 완전 무작위와 완전 수작업의 중간을 택한 사례다. [개발자 글](https://deepnight.net/tutorial/the-level-design-of-dead-cells-a-hybrid-approach/)

**적용 판단:** '이 타일은 언덕'보다 먼저 '여기는 우회로, 저기는 능력으로 줄이는 길'을 정한다. 검수할 대상도 단일 바위보다 '골짜기 + 양쪽 착지대 + 옆의 우회 경사로' 같은 작은 플레이 구간이 적합하다. 2D 방 그래프를 구면에 그대로 붙이는 것은 아니다.

### Spelunky Classic: 먼저 통과할 수 있는 경로를 만든다

Darius Kazemi의 원본 게임 수정·분석 도구는 방 연결로 통과 경로를 먼저 만들고 나머지 방을 채우는 과정을 보여준다. 이는 개발사 자체 문서가 아니라 원본 코드를 직접 수정한 생성 과정 분석이다. [실행 가능한 분석 도구](https://tinysubversions.com/spelunkyGen/)

**적용 판단:** 노이즈가 만든 지형이 우연히 통과 가능하기를 기대하지 않는다. 필수 우회로를 예약하고 이후 생성 단계가 그 통로를 막지 못하게 한다. 타일 개수가 늘어도 같은 원칙을 유지한다.

### A Short Hike: 우회도 탐험이고 높은 곳은 새로운 관점이 된다

Adam Robinson-Yu는 작은 오픈 월드에서 명백한 길과 반대로 움직여도 탐험이 보상되도록 설계했고, 정상에서 쉬며 다른 관점으로 풍경을 보는 경험을 중요하게 다뤘다고 설명한다. [개발자 글](https://blog.playstation.com/2021/08/05/crafting-a-tiny-open-world-a-look-behind-the-scenes-at-the-creation-of-a-short-hike/)

**적용 판단:** 초반 우회로에도 풍경·작물·대화 등 의미가 있어야 한다. 능력 해금은 우회로를 무의미하게 만드는 것보다 '이제 어디서 길을 줄일지 내가 고를 수 있다'는 경험을 주는 편이 동화적 분위기에 맞는다. 이 사례를 절차적 지형 생성 사례로 소개하는 것은 아니다.

### No Man's Sky: 지형 생성 파이프라인의 참고

Hello Games의 Innes McKendrick은 GDC에서 행성의 절차적 생성, 복셀에서 메시·텍스처·개체 배치로 이어지는 생성 파이프라인과 실시간 연속 생성 구조를 설명했다. [GDC 발표 소개](https://www.gdcvault.com/play/1024265/Continuous_World_Generation_in__No_Man_s_Sky_)

**적용 판단:** 행성의 지형 형상과 표면 개체 배치를 단계로 분리한다. 다만 B612는 한 번에 작은 행성 하나를 준비하므로 복셀·동굴·실시간 스트리밍까지 도입할 필요는 없다. 아래 구면 노이즈 수식은 B612용 제안이며 이 게임의 내부 수식을 인용한 것이 아니다.

## 3. 성장 체감은 같은 장애물을 다른 방식으로 통과할 때 생긴다

장애물은 처음부터 '지금은 절대 못 가는 벽'보다 **느린 기본 경로와 빠른 능력 경로의 쌍**으로 설계한다.

```text
                    기본 점프 + 완만한 우회길
시작 지점 ──────→ 골짜기 가장자리 순환 ──────→ 목적지
    └──────── 대쉬/더블점프 지름길 ─────────┘
```

첫 설계에서는 핵심 목적지를 연결하는 기본 동선을 보행·일반 점프로 유지하는 안을 권장한다. 능력이 필요한 필수 구간은 나중에 챕터의 진입 보유 능력이 확정된 뒤 별도 도전 구간으로 추가한다. 보너스 작물·전망대 같은 선택 구역은 능력별 접근 조건을 둘 수 있다.

### 해금 순서 제안

| 구간 | 제안 능력 | 지형 경험 |
| --- | --- | --- |
| 1챕터 도입 | 보행·일반 점프 | 낮은 능선과 우회길을 읽고 안전하게 이동 |
| 1챕터 초반 이후 | 대쉬 | 좁은 골짜기·물길을 수평으로 짧게 가로지름 |
| 2챕터 초반 이후 | 더블점프 추가 | 익숙한 높은 턱·고지대를 위로 올라 길을 줄임 |
| 3챕터 초반 이후 | 활공 추가 | 전망대·언덕에서 낮은 반대편으로 내려가며 지형을 넘음 |

해금 전후를 한 행성에서 비교하는 작은 구간을 넣으면 좋다. 예를 들어 능력을 받으러 갈 때 골짜기를 우회하고, 받은 뒤 돌아올 때 같은 골짜기를 건넌다. 해금 장소는 그 능력 없이 도달할 수 있어야 한다.

현재 행성 간 이동은 단방향이다. 이미 떠난 행성에 나중에 돌아갈 수 있다고 전제하지 않는다. 같은 행성의 왕복 구간과 이후 행성에서 반복되는 익숙한 지형을 통해 성장 체감을 만든다.

### 난이도가 성장 체감을 상쇄하지 않게 한다

- 2챕터에서도 1챕터에서 보던 폭·높이의 지형을 일부 유지한다.
- 능력 해금에 맞춰 모든 강을 더 넓히고 모든 언덕을 더 높이면 편해진 느낌이 사라진다.
- 후반의 새 도전은 일부 구간에서 능력 조합·접근 방향·착지 선택으로 만든다.
- 우회길은 실패에 대한 벌보다 다른 풍경과 자원을 만나는 길로 만든다. 바오밥 대응 중에는 과도한 우회 시간을 요구하지 않는다.

## 4. 지형 요소는 타일 하나보다 큰 단위로 설계한다

| 지형 요소 | 능력이 적을 때 | 능력이 생긴 뒤 | 생성 시 필수 조건 |
| --- | --- | --- | --- |
| 골짜기 | 옆으로 돌아 완만한 연결부를 이용 | 점프+대쉬 또는 더블점프로 단축 | 양쪽 진입·착지 공간, 추락 후 복귀 경사 |
| 높은 언덕·단차 | 둘레의 경사로·중간 턱을 이용 | 더블점프로 높은 턱에 직접 올라감 | 정상에서 고립되지 않고 내려오는 길 |
| 강·물길 | 여울·땅으로 이어진 우회 횡단부 이용 | 폭이 맞으면 대쉬/점프로 횡단 | 연속된 물길, 기본 횡단부, 안전한 물가 |
| 고지대와 낮은 맞은편 | 계곡 쪽 기본 길로 내려갔다 올라감 | 높은 곳에서 활공해 낮은 착지대로 이동 | 출발 높이와 하강 여유, 보이는 착지대 |
| 후반 조합 구간 | 기본 동선 유지 또는 선택 구역 | 더블점프→대쉬→활공 등으로 단축 | 자원 조건을 포함한 실제 통과 검증 |

대쉬는 상승 능력이 아니다. 높은 벽의 해법을 대쉬만으로 정하지 않는다. 활공도 상승 비행이 아니므로 같은 높이의 먼 지점에 무조건 닿는다고 판단하지 않는다. 현재 활공은 하강 중 사용·시간 제한이 있는 동작이다.

지형 요소의 폭·높이는 월드 거리로 정하고, 여러 논리 타일에 걸칠 수 있게 한다. 예를 들어 강은 '물 타일 몇 개'가 아니라 여러 타일을 통과하는 중심선과 폭을 가진다. 타일에는 해당 요소와의 교차 범위·우세한 지형 정보가 기록된다.

구면에서의 표면 거리 근사는 `R × acos(clamp(dot(u, v), -1, 1))`로 계산할 수 있다. 지형 요소의 범위에는 이 거리를 사용하고, 점프 중의 이동·충돌에는 실제 3D 궤적을 사용한다. 큰 구간의 구면 거리와 직선 거리를 혼용하지 않는다.

작은 행성에 검수한 크기의 지형이 들어가지 않으면 그 요소를 제외하거나 다른 요소를 택한다. 단순히 행성 배율을 곱해 강을 좁히면 일반 점프로도 건너져 의도한 능력 구간이 사라질 수 있다.

## 5. 타일·연속 지형·장애물의 역할을 나눈다

현재 논리 타일은 기본 1배 80개·1.5배 180개·2배 320개다. 이는 배치·조회 단위이며 지형 메시의 해상도와 다르다.

```text
논리 타일           : 지역 분류, 인접 관계, 보호 구역, 지형 요소 소유/교차
연속 높이 필드      : 인접 타일 사이에 끊김 없는 지면 형상
지형 요소           : 골짜기·언덕·물길·착지대·우회 경사로
촘촘한 이동 표본    : 같은 타일 내부까지 포함한 실제 통과 가능성
배치 지점          : 검증 완료 지면 위 작물·NPC·바오밥 후보
```

- 타일마다 별도 지면 프리팹을 무작위 회전시켜 붙이는 방식부터 시작하지 않는다. 구면에서 높이·법선·곡률 경계가 맞지 않기 쉽다.
- 같은 메시 정점에는 동일한 높이 함수를 사용한다. 경계를 공유하면 정점 위치와 최종 법선도 일치해야 한다.
- `Plain/Hill/Valley` 같은 기본 지역과 `River` 같은 물길, `SafeRoute/Shortcut` 같은 이동 역할은 별도 층으로 관리한다. 언덕에 물길이 있다고 한 정보를 덮어쓰지 않는다.
- 큰 골짜기 하나는 여러 타일에 걸쳐도 지형 요소 하나다. 타일 수가 갑자기 80→180개로 바뀌었다고 골짜기 수도 두 배로 늘리지 않는다.

## 6. 노이즈는 구면 전체에서 연결되게 계산한다

위도·경도로 펼친 2D 노이즈보다 **행성 로컬 3D 방향에서 연속 노이즈를 표본화**하는 안을 권장한다. 극점과 경도 이음선 처리를 피하기 쉽다.

```text
u = 행성 중심에서 표면을 향하는 단위 방향
R = 명목 반경
x = R × u

E(u) = w_large × N_large(x / λ_large + seedOffsetA)
     + w_medium × N_medium(x / λ_medium + seedOffsetB)

H_free(u) = H_base(u) + amplitude × (2 × E(u) - 1)
```

여기서는 N을 0~1 범위의 3D 연속 노이즈로 가정한다. 실제 구현의 출력 범위에 맞춰 정규화한다. `H_base`는 명목 반경 R에 대한 원본 형상의 월드 단위 높이 차다. 지형 요소와 통로 보정을 적용한 최종 높이 `H_final`로 `p = center + planetRotation × ((R + H_final(u)) × u)`를 계산한다. 이는 개념식이며 실제 합성·초기값은 17절을 따른다. 이전 예시의 고주파 높이 10% 항은 삭제하고 미세 디테일은 재질로 분리한다.

최종 반경 `R + H_final`은 충분한 양수 하한을 갖게 한다. 골짜기가 중심을 뚫거나 지나치게 좁은 폭에서 큰 높이 차를 만들어 충돌 삼각형이 퇴화하지 않도록 최소 반경·변형 폭·경사를 제한한다.

- 저주파: 큰 언덕·넓은 낮은 지대. 행성 전체 인상을 만든다.
- 중주파: 지역 안의 능선과 완만한 굴곡.
- 고주파: 재질의 시각적 거칠기만 담당하며 지면 높이·Collider에는 추가하지 않는다.
- 별도 seed 흐름으로 고도 E, 거칠기 Q, 습윤도 M 같은 필드를 만든다. 모든 속성을 같은 값 하나로 정해 '높으면 무조건 거칠고 건조함'이 되게 하지 않는다.
- λ는 월드 거리 기준 파장이다. 행성 반경이 커져도 같은 너비의 작은 언덕을 만들 수 있다. 큰 지역의 파장은 반경과 지역 개수 제한도 함께 고려한다.
- 타일별 난수는 주로 후보 선택·미세한 배치 변주에 쓴다. 높이를 셀 ID의 독립 난수로 정하지 않는다.
- 선택적으로 낮은 강도의 좌표 왜곡을 적용할 수 있다. 경로 예약과 지형 요소 배치 전에 필드를 확정하고, 보호 통로의 위치를 사후에 다시 왜곡하지 않는다.

### 월드 단위와 기존 scale 처리

현재 `GroundSurface`에는 행성 배율이 적용되고, 격자·플레이 개체의 기준 Transform은 배율 1이다. 높이 변위를 월드 미터로 정했다면 지면 로컬 정점에 넣을 때 해당 Transform을 통해 변환한다. 높이를 로컬에 더한 뒤 Transform에서 한 번 더 확대하는 실수를 피한다.

원본 메시/높이 입력은 고정해 두고 매번 거기서 계산한다. 이전 행성이나 직전 변형 메시를 다시 변형해 높이가 누적되지 않게 한다.

## 7. 타일별 가중치는 노이즈와 제약에서 만든다

노이즈가 후보 지역을 정하고, 타일에서 이를 요약해 지형 종류를 선택한다.

```text
score(type, cell) = chapterBias
                  + noiseAffinity
                  + elevation/moisture/slopeFit
                  + regionContinuity

선택 확률 ∝ exp(score), 단 hardConstraint를 만족하는 후보만 사용
```

표의 상대 가중치를 사용할 때 `chapterBias = log(baseWeight)`로 변환한다. 65 같은 값을 그대로 exp의 입력으로 넣지 않는다. 가중치 0은 후보 제외로 처리하고, 다른 점수 항의 범위도 조절 가능하게 둔다.

hardConstraint 예:

- 필수 통로·스폰 보호 영역에는 급경사 골짜기를 배치하지 않는다.
- 강은 물길 계획의 중심선 주변에서만 허용한다. 습윤도만 높다고 고립된 강 타일을 만들지 않는다.
- 높은 언덕이 스폰·NPC 상호작용 공간을 덮지 못하게 한다.
- 고지대 지름길에는 실제 착지 가능한 공간이 있어야 한다.
- 해당 행성 크기와 능력별 통과 범위에 맞지 않는 요소는 후보에서 제외한다.

### 초기 가중치 예시

| 챕터 | 평지 지역 | 언덕 지역 | 골짜기 지역 |
| --- | ---: | ---: | ---: |
| 1 | 65 | 25 | 10 |
| 2 | 50 | 30 | 20 |
| 3 | 45 | 30 | 25 |

이는 **후보 선택을 위한 상대 가중치**다. 실제 면적 비율이나 타일 비율의 보장이 아니다. 물길은 별도 층에서 습윤도·연속 중심선·물길 예산으로 선택하므로 지역과 겹칠 수 있다. 필수 통로·요소별 상한과 군집 조건이 우선한다. 수치는 플레이 검증 전 시작점이다.

독립 추첨만 하면 높은 가중치 지역도 얼룩처럼 흩어질 수 있다. 먼저 연속 필드에서 중심 지역을 선택하고, 이웃 적합도를 보며 구역을 확장한다. 정해진 순서의 제한된 확장/완화 단계로 패치를 만든 뒤 실제 지형 요소를 배치한다. seed와 반복 순서가 같으면 결과도 같아야 한다.

주요 장애물의 예산은 단순 타일 수가 아니라 사용 가능한 표면적·실제 점유 폭·예상 우회 시간으로 제한한다. 작은 행성은 주요 요소 0~1개, 넓은 행성은 1~2개부터 검증하는 안을 권장한다. 배치에 실패했다고 보호 통로를 침범해 개수를 채우지 않는다.

## 8. 우회로와 지름길을 먼저 예약한다

1. 스폰·목적지·향후 NPC/핵심 작물·해금 장소의 방향과 안전 공간을 정한다.
2. 이 공간을 잇는 기본 연결 그래프를 만든다. 구면 거리와 큰 고도 필드를 참고한다.
3. 연결 일부에 '장애물을 돌아가는 길 + 가로지르는 길'의 쌍을 지정한다.
4. 기본 길에는 통행 폭·경사·머리 공간·착지 여유를 예약한다.
5. 지름길에는 해당 능력의 출발대·횡단 폭/높이·착지대를 예약한다.
6. 그 밖의 공간에서 가중치 기반 지형 패치를 배치한다.

기본 통로의 최대 경사는 우선 약 30도처럼 현재 모터 한계보다 보수적으로 시작한다. 실제 허용값은 경사 이동 검증으로 확정한다. 넓이는 캡슐 지름만 확보하지 말고 방향 전환과 카메라 시야의 여유도 둔다.

노이즈와 지형 요소 적용 후에는 보호 통로를 완만하게 보정한다. 17절의 외관 개선에서는 잔무늬를 재질에만 두고 통로의 미세 대비도 낮춘다. 물길과 기본 통로가 교차해야 한다면 검수한 여울·지형 연결부를 함께 계획한다. 단순 평탄화로 물길을 무작정 끊거나 통로 위에 다시 강을 그리지 않는다.

### 통로의 가치도 검증한다

지름길은 선으로 존재하는 것만으로 충분하지 않다. 같은 지형에서 능력별 예상 이동 시간을 비교한다.

```text
gain = T_baseRoute / T_withUnlockedAbilities
```

초기 목표 예는 해당 장애물 구간에서 1.3~1.8배 정도의 시간 이득이다. 전체 행성의 통과 시간을 같은 비율로 줄여야 한다는 뜻은 아니다. 절대 우회 시간도 제한해 작은 장애물 하나 때문에 오랫동안 행성 반대편으로 돌아가지 않게 한다. 수치와 허용 시간은 바오밥 대응 시뮬레이션에서 조절한다.

기본 길에도 짧은 전망·자원·이야기를 배치해 지나갈 이유를 남긴다. 지름길이 모든 플레이에서 유일한 정답이 되지 않아도 된다.

기본 길은 흙길·낮은 풀·꽃 군집 같은 자연스러운 표식으로 읽히게 하고, 능력 경로는 넓은 출발 가장자리와 착지대의 형태를 반복해 학습시킨다. 작은 행성의 지평선 때문에 착지대가 완전히 가려진 구간을 좋은 지름길로 계산하지 않는다. 현재 카메라에서 출발점과 도착 방향을 이해할 수 있는지도 검수한다.

## 9. 강과 골짜기는 연속된 지형 요소로 만든다

### 골짜기

중심선과 폭·깊이·양쪽 가장자리 형태를 가진 지형 변형을 사용한다. 구면 위 중심선까지의 거리로 영향량을 계산해 여러 타일에 걸쳐 지면을 낮춘다. 골짜기 끝·옆에는 완만한 우회 연결을 두고, 내부에 떨어져도 현재 최소 능력으로 빠져나올 수 있어야 한다.

### 언덕

넓은 완만한 밑면과 구분되는 정상부를 만든다. 기본 경사로와 능력으로 오르는 짧은 턱을 다른 방향에 두면 하나의 언덕에 두 경험을 줄 수 있다. 높은 곳이 활공 출발점이라면 낮은 착지대와 시야도 함께 계획한다.

### 강

- 1차 구현은 고지대에서 낮은 분지로 향하는 짧은 중심선을 정하고 강바닥·물가를 만든다. 중심선은 완만하게 휘게 하고 주변 지형과 연결한다.
- 구형 행성에서는 월드 Y 높이가 아니라 중심으로부터의 거리/방사 방향 고도를 사용한다. 물 표면도 행성 곡률에 맞춘다.
- 강 하류는 더 낮은 지형이나 작은 호수에서 끝나게 한다. 닫힌 구에는 모든 곳에서 계속 내리막인 흐름이 존재할 수 없으므로 분지·종점을 허용한다.
- 깊은 물·수영·유체 시뮬레이션을 한꺼번에 도입하지 않는다. 우선 물가·강바닥과 기본 횡단부의 이동 관계부터 검증한다. 첫 물길은 보행 감속 지형으로 시작하고 여울·우회길을 더 빠르게 두는 안을 권장한다. 감속 배율은 미정이며 물가에서 고립되지 않아야 한다. 깊은 물과 복귀 정책은 별도 확장이다.
- 물길이 행성 전체를 가르는 폐쇄 장벽이 되지 않게 기본 동선 연결을 검사한다.

현재 바닥 조회는 해당 지면 Collider의 방사 방향 Raycast를 사용한다. 강 위 실제 다리·동굴처럼 같은 방향에 여러 층의 바닥이 생기면 이 조회와 이동 검증을 확장해야 한다. 첫 구현은 **한 방향에 하나의 기본 지면이 있는 형태**와 여울·지형 우회 연결로 제한하는 것이 현실적이다.

## 10. 능력별 통과 가능 거리를 실제 모터로 보정한다

`PlayerTraversalAbilities`에는 이미 대쉬·공중 점프·활공과 자원 제한이 구현되어 있다. 하지만 챕터 성장 데이터와 해금 시스템이 구현되어 있다고 가정하지 않는다. 현재 코드의 Allow 플래그는 개발 기능 제어와 연결되어 있으므로 정식 해금 기록과 분리해야 한다.

제안하는 `TraversalCapabilityProfile`은 다음을 포함한다.

- 보행·일반 점프와 각 해금 능력.
- 실제 실행 설정의 속도·가속·중력·점프·대쉬·활공 매개변수.
- 같은 체공 중 추가 점프·대쉬 횟수, 활공 시간, 착지 회복 조건.
- 플레이어 캡슐 크기와 착지·충돌 여유.

기본 점프, 점프+대쉬, 더블점프, 조합+활공을 실제 모터로 시험해 `최대 고도/안전 횡단 폭/필요한 착지대` 범위를 얻는다. 평지뿐 아니라 해당 행성 반경·경사·높이 차이를 바꿔 검사한다.

- 평면 탄도식과 `속도 × 지속 시간`은 초기 추정에만 쓴다. 구형 중력의 방향 변화·대쉬 감속·활공 진입·충돌 때문에 실제 값이 다르다.
- 현재 코드 기본값의 활공 2.6m/s × 2.5초 = 6.5m도 단순 곱일 뿐 안전 도달 거리 보장이 아니다. 실제 씬 설정과 진입 속도를 확인한다.
- 일반 점프로 간신히 실패하고 새 능력으로 간신히 성공하는 매우 좁은 범위만 있다면 해당 장애물을 채택하지 않는다. 폭·높이뿐 아니라 착지 안전 여유까지 충분한 차이가 필요하다.
- 같은 높이 차이·반경에서의 간단한 채택 조건은 `기본 능력 한계 + 차별 여유 < 장애물 폭 ≤ 새 능력 한계 × 안전 계수`다. 이 구간이 비어 있으면 폭을 억지로 정하지 말고 높이 차이·지형 형태를 바꾸거나 다른 요소를 선택한다.
- 능력 경로는 측정한 성공 한계의 약 70~80% 수준부터 검토한다. 반면 기본 능력으로는 정말 다른 길이 유리한지 대조한다. 이 비율은 검증 전 제안이다.
- 점프 후 대쉬가 가능해도 대쉬가 추가 점프나 활공 예산을 다시 채우면 안 된다. 연속 공중 간선을 각각 완전히 충전된 상태로 검사하지 않는다.
- 작은 행성에서는 이동 거리가 반지름에 비해 커진다. 평면에서 검증한 수치를 모든 행성에 동일하게 통과 판정으로 쓰지 않는다.

정식 해금과 개발 허용은 별개 입력으로 두는 안을 권장한다. 예: 실제 허용은 `progressionUnlocked && developerAllow`로 결정하고, 개발 Toggle을 켠 것만으로 해금 기록을 바꾸지 않는다. 잠긴 능력을 강제로 해금하는 별도 개발 기능은 이번 범위가 아니다.

## 11. 인접 타일 그래프만으로 이동 가능성을 판단하지 않는다

타일 두 개가 이웃이어도 경계에 절벽이 있으면 걸어갈 수 없다. 반대로 같은 타일 안에 강이 지나가 양쪽 지면이 갈라질 수도 있다.

검증은 촘촘한 지면 표본과 통과 지점으로 구성한 **방향 있는 이동 그래프**를 사용한다.

- 보행 간선: 캡슐 여유·경사·단차·충돌 검사.
- 점프 간선: 실제 점프 궤적과 착지 후보 검사.
- 능력 간선: 해당 해금·남은 자원과 조합의 실제 궤적 검사.
- 낙하/활공 간선: 고도 차이와 도착 뒤 복귀 가능성까지 구분.

각 챕터의 진입 최소 능력으로 필수 목표가 연결되는지 검사하고, 첫 시제품의 기본 길은 일반 점프까지로 통과 가능하게 유지한다. 보상만 있는 선택 구역과 필수 구역을 구분한다. 해금 장소는 **해금 전** 능력으로 검사한다.

점프·대쉬·활공이 이어지는 구간은 실제 착지가 확인된 지점에서만 자원을 회복한 것으로 판정한다. 좁은 장식이나 바오밥 모델을 무한 체공용 회복 발판으로 사용하지 않는다.

같은 행성을 기본/대쉬/더블점프/전체 능력 프로필로 비교하면 지형 변경 없이 길이 어떻게 달라지는지 확인할 수 있다. 향후 바오밥 스킵과 함께 반복 검증하기 좋은 개발 시나리오다.

## 12. 생성 파이프라인과 실패 복구

1. 챕터 정의·진입 최소 능력·seed·행성 크기·노이즈/지형 프리셋을 확정한다.
2. 논리 타일의 구면 경계·이웃만 준비한다. 현재 `Prepare()`는 실제 지면 후보 생성까지 수행하므로 지형 계획용 topology와 최종 슬롯 준비를 분리하거나 같은 불변 topology를 공유한다.
3. 큰 고도·거칠기·습윤도 필드를 계산한다.
4. 필수 공간과 기본 동선·지름길의 관계를 정하고 보호 영역을 예약한다.
5. 타일 가중치를 요약하고 제한된 영역 확장으로 지역을 만든다.
6. 검수한 지형 요소를 실제 크기·우회 시간 예산 안에서 배치한다.
7. 전역 높이 + 지형 요소 변형 + 보호 통로 보정으로 연속 지면을 확정한다. 물길/물 표면은 별도 단계에서 준비한다.
8. 지형 메시·노멀·Collider를 만든다. 이동 검증이 사용하는 형상과 화면의 착지 지형이 일치해야 한다.
9. 현재 최소 능력과 비교 프로필로 연결성·시간 이득·추락 복귀를 검증한다.
10. 실패하면 보호 길 확장 → 경사 완화 → 횡단부 보완 → 우선순위 낮은 장애물 제거 순으로 제한된 수정 후 다시 검사한다.
11. 여전히 실패하면 검수한 안전 지형 템플릿으로 대체하고 원인·seed를 기록한다. 무한 재생성하지 않는다.
12. 최종 Collider 확정 후 `Physics.SyncTransforms`와 표면 후보 준비를 수행하고 정적 콘텐츠/바오밥 후보를 배치한다. 그 뒤 플레이어 도착과 바오밥 시계를 시작한다.

수정 횟수는 예를 들어 최대 3회부터 시작해 측정한다. 수정 결과도 seed와 규칙 버전에 따라 재현되게 한다. 후보를 바꾸는 실패 재시도가 지도에서 이미 공개한 크기·색·NPC 계획까지 새로 추출하면 안 된다.

### 메시와 런타임 소유권

- 논리 타일보다 촘촘한 표시/충돌 메시가 필요하다. 좁은 통로·착지대·물가를 표현할 표본 간격을 기준으로 해상도를 정한다.
- 가이드 예: 표본 간격을 `min(보호 통로 폭/4, 가장 작은 중요 지형 폭/6)` 이하부터 검토한다. 이것이 물리 검증을 대체하는 것은 아니다.
- 공유 원본 Mesh/Material을 직접 변형하지 않는다. 현재 행성 소유의 생성 메시·Collider 참조를 관리하고 실패/행성 전환 때 해제한다.
- 한 행성을 플레이하는 동안 지형을 다시 생성하지 않는다. 능력 해금은 지형을 바꾸는 대신 사용할 수 있는 경로를 바꾼다.
- 처음부터 동굴·오버행·다층 다리·파괴 지형·실시간 침식까지 구현하지 않는다. 현재 방사 방향 높이 지형과 조회 계약을 유지할 수 있는 범위부터 만든다.

## 13. 바오밥과 양 때문에 추가되는 제약

바오밥은 시간제 대응 콘텐츠이므로 '어딘가에 길이 있다'만으로 충분하지 않다.

- 첫 시제품의 바오밥 후보는 기본 동선에서 대응 가능한 지면으로 제한한다. 미해금 능력 전용 고지대·활공 후 복귀 불가 지점에 생성하지 않는다.
- NPC·작물·양 소환 공간과 주요 이동 통로의 충돌 여유를 보호한다.
- 지형 때문에 양의 먹기 범위가 강 건너까지 닿는 등 의도하지 않은 상황이 생기는지 확인한다. 현재 거리 판정이 새 지형의 벽·물길을 이해한다고 가정하지 않는다. 필요하면 실제 도달/시야·지형 경계를 고려한 먹기 정책을 별도로 정한다.
- 각 능력 프로필의 바오밥 대응 이동 시간과 기존 먹기 시간을 함께 비교한다. 위험도·성장 속도를 유지한 상태로 새 지형이 필연적 패배를 만드는지 검사한다.
- 행성이 커지거나 타일이 늘었다는 이유로 장애물·바오밥 수량을 함께 자동 증가시키지 않는다.
- 세 챕터의 해금은 긴장 구간을 편하게 만드는 보상도 되어야 한다. 매 챕터마다 그 이득을 더 긴 우회·더 많은 위협으로 전부 상쇄하지 않는다.

## 14. 최소 데이터 확장 제안

새로운 필드를 전부 현재 DTO에 바로 추가하기보다 지형 계획을 별도 객체로 분리하는 안이다. 아래는 아직 구현되지 않은 계약이다.

```text
  abilityUnlockScheduleRef        : 해금 장소/시점 규칙, 순환 잠금 방지
  regionWeightProfileId

  routeSafetyProfileId

PlanetTerrainGenerationPlan

  features[]                      : 종류·중심선/영역·폭·높이·착지 조건
  repairDecisions[]                : 재현 가능한 보완 기록

```

- 지형과 지름길은 행성 생성 설정에 확정한다. 플레이어가 능력을 해금하거나 디버그 Toggle을 바꿨다고 지형 seed를 다시 추출하지 않는다.
- 챕터의 보장 능력과 현재 플레이어의 해금 기록을 구분한다. 실제 진입 시 보유 능력 검증도 필요하다.
- 지형 계획·이동 연결은 cell ID 하나만 저장해서 복구하지 않는다. seed·설정·논리 격자·생성기 버전과 연결한다.
- 후속 2단계는 생성기 3 / `terrain.lowFrequency.v1`이었다. 현재 3~4단계는 생성기 4 / `terrain.regional.v1`이며 데이터 형식은 1이다. 이전 버전 입력은 거부한다. 구체적인 생성 계획·검증과 저장 기능 미구현 범위는 각 단계의 결과를 따른다.

## 15. 단계별 도입과 검증

### 1단계: 수작업으로 '성장하면 편해지는 지형' 검증

고정 테스트 행성에 골짜기 1개와 우회로, 높은 턱과 경사로, 활공 출발대와 낮은 착지대를 각각 만든다. 기본/대쉬/추가 점프/전체 능력으로 실제 모터를 비교한다. 이 단계에서 재미와 안전한 규격을 찾는다.

**후속 구현 완료:** `B612_TraversalTest`에 반경 12m의 고정 지형을 만들었다. 기존 F12 능력 체크박스·1~3 구간 선택·R 재연습과 기본 우회로를 제공한다. 골짜기 폭 4.2m/깊이 2m, 턱 높이 2m, 활공 기준 간격 7m를 실제 모터와 키 입력으로 비교했다. 구체적인 조건·수치·한계는 [1단계 구현·검증 기록](TraversalTestCourseStage1Results.md)을 따른다.

### 2단계: 저주파 지형 + 검수한 요소의 무작위 배치

평지·언덕·골짜기만 도입하고 1~2개 검수한 요소의 위치·방향을 바꾼다. 필수 동선을 예약하고 최종 지면과 슬롯을 검증한다. 강은 우선 마른 물길 형태로 검증할 수 있다.

**후속 구현 완료:** 공통 행성 준비에 저주파 높이 필드와 골짜기/턱의 seed 배치, 보호 통로·최종 Collider 모터 검사·안전 후보 필터를 연결했다. 반경 12m 기준의 `B612_ProceduralTerrainTest`를 추가했으며, 작은 기존 행성은 요소를 축소하는 대신 제외할 수 있다. 유한 보완·버전·크기별 실제 결과는 [2단계 구현·검증 기록](ProceduralTerrainStage2Results.md)을 따른다. 물길은 이번에 추가하지 않았다.

### 3단계: 가중치 노이즈·지역 확장·물길 연결

연속 필드와 타일 가중치로 지역을 묶고, 예산과 보호 마스크를 적용한다. 강바닥·물 표면과 횡단 정책을 연결한다. 이 단계도 복잡한 침식 시뮬레이션은 필요 없다.

**후속 구현:** 독립 E/Q/M 필드, 챕터 가중치, 타일 이웃을 통한 연결 지역 확장과 연속 곡면 형상화를 공통 생성에 연결했다. 강은 습윤도 기반 후보에서 하류 분지로 이어지는 얕은 중심선·강바닥·별도 물 메시를 만들고 보호 통로에 여울을 둔다. 수중 보행 0.65배, 수영·침식·다층 바닥은 제외한다. 생성기 4 / 프로필 `terrain.regional.v1` / 데이터 형식 1이다.

### 4단계: 3챕터와 정식 해금·선택 경로

보장 능력·해금 장소·챕터별 지역 가중치를 연결한다. 익숙한 장애물과 일부 새 조합 구간을 섞고 실제 바오밥·작물·NPC의 이동 비용과 맞춘다.

**후속 구현:** `B612_ChapterJourney`에 3챕터와 현장 E 해금, 누적 해금 기록·개발 허용 분리, 챕터 간 지도 이동을 연결했다. 3챕터에는 높은 활공 출발대·낮은 착지대와 기본 복귀길을 추가한다. 바오밥 후보는 최종 검증 지면에 두고 작물 조사·안내 상호작용 지점의 실제 방문 시간·거리를 기록한다. 작물/양털/퀘스트 경제 전체는 이 단계의 이동 시제품에 포함하지 않는다. 검증 범위와 남은 밸런스 판단은 [3~4단계 결과](ProceduralTerrainStages34Results.md)를 따른다.

검증 항목:

- 0.7/1/1.5/2배와 다양한 seed에서 지형/타일 경계·극점·경도 이음선에 균열이 없다.
- 모든 필수 목표와 해금 장소가 해당 시점 능력으로 도달 가능하며, 편도 낙하·골짜기·물가에서 고립되지 않는다.
- 같은 지형에서 능력을 더한 프로필의 이동 시간·접근 선택지가 실제로 개선된다. 체공 예산을 잘못 회복해 성공한 것은 제외한다.
- 1배 부근의 타일 개수 단계 변화가 장애물 수·크기·난이도를 갑자기 두 배로 만들지 않는다.
- 필수 경로의 경사·캡슐 충돌·카메라 시야·시각적 착지 지형이 일치한다. 기존 능선 접지/걷기 문제를 재발시키지 않는다.
- 목표 배치와 바오밥 후보가 최종 수정된 지면을 사용한다. 격자 준비/지도 재열기/디버그 표시가 지형을 재생성하지 않는다.
- 실패 수정 횟수와 준비 시간이 유한하며 안전 템플릿 복귀가 동작한다. seed·설정·생성기 버전으로 문제를 재현할 수 있다.

15절의 구현 결과 문서에는 각 시제품의 이동 검증 조건과 측정값이 기록되어 있다. 후속 적용은 16절을 따른다.

## 16. 실제 플레이 적용

2026-11-11 후속 구현 명세. 사용자는 고정 테스트에서 골짜기 폭·언덕 높이·착지대 크기가 재미있는 규격으로 검수됐다고 가정하고, 같은 지형을 실제 게임 진행에서 경험하도록 요청했다. 적용 대상은 기존 3챕터 캠페인 `B612_ChapterJourney`로 정한다. 각 챕터의 시작 행성에서 그 챕터가 해금하는 능력의 대표 지형을 한 번씩 만나는 배치 정책을 사용한다.

현재 생성기는 세 지형의 형상을 이미 사용한다. 후보 배치와 최종 이동 검사에서 개별 지형을 생략할 수 있고, 현재 빌드의 첫 씬은 `B612_Night`다. 이번 작업은 캠페인 시작 경로와 챕터별 필수 배치 정책을 연결하는 것이다. 현재 생성 및 해금 경로는 [3~4단계 구현 기록](ProceduralTerrainStages34Results.md)을 참고한다.

### 적용 규격

| 기존 챕터 해금 | 시작 행성의 대표 지형 | 검수 규격 | 기본 이동 경로 |
| --- | --- | --- | --- |
| 1챕터 대쉬 | 골짜기 | 기준 폭 4.2m, 깊이 2m | 가장자리 우회로와 골짜기 바닥 탈출 경사 |
| 2챕터 더블점프 | 높은 언덕의 턱 | 방사 높이 2m, 전면 전이 폭 0.2m | 측면 경사로와 정상에서 내려오는 경로 |
| 3챕터 활공 | 높은 출발대와 낮은 착지대 | 기준 간격 7m, 출발·착지 높이 +2.6m·+0.4m. 중앙 착지 평탄부는 진행 방향 약 2.85m, 횡방향 2.0m | 계곡 우회로와 바닥에서의 복귀 경사 |

폭·간격·착지 평탄부 치수는 기준 구면의 호 길이 좌표이며 높이는 방사 방향 월드 미터다. 활공의 중앙 착지 평탄부는 기존 형상에서 진행 좌표 `5.15~8.0`, 횡좌표 `-1.0~1.0`에 해당한다. 구간 형상·시작점·목표점·우회로는 `TraversalTestCourseGeometry`에 있는 값을 공통으로 사용한다. [고정 코스의 규격과 검증](TraversalTestCourseStage1Results.md)

캠페인 시작 행성의 기존 1배·기준 반경 12m 조건에서 대표 지형을 배치한다. 검수 형상은 같은 월드 단위로 계산하고, 실제 행성 반경에 맞춰 지표 방향을 변환한다. 일반 행성에서는 크기와 배치 가능 면적에 맞는 지형을 후보로 사용한다.

### 캠페인 생성에 연결

1. 플레이용 빌드의 시작 씬을 `B612_ChapterJourney`로 연결하고 README의 기본 플레이 경로도 해당 씬으로 안내한다. 에디터에서는 이 씬에서 Play하면 기존 캠페인이 시작된다.
2. `PlanetWorldInstance.Prepare`에서 캠페인의 시작 행성과 `spec.unlock`을 확인해 필수 지형 종류를 기존 `ProceduralPlanetTerrain` 계획에 전달한다. 해금 능력이 대쉬·더블점프·활공일 때 각각 골짜기·높은 턱·활공 구간을 선택한다. 지도 분기 선택 전에 방문하는 시작 행성을 사용하므로 이후 경로와 관계없이 세 구간을 만난다.
3. 필수 지형과 양쪽 연결로를 우선 예약한다. 기존 생성 예산의 남은 자리에서 seed에 따른 일반 지형·지역·물길을 배치한다. 보호 영역에는 구간의 출발점, 착지대, 기본 우회로, 추락 복귀 경로와 연결로가 포함된다.
4. 기존 해금 지점에서 기본 이동으로 대표 구간 입구까지 이어지는 길을 확보한다. 기존 안내·조사 동선에서 구간을 찾을 수 있도록 표시하고, 출구를 다시 기본 경로에 연결한다. 해금 장소에는 보행으로 도달한다. 해금 뒤에는 같은 출발점과 목표점 사이에서 기본 우회로와 능력 지름길을 선택한다.
5. 최종 지면 메시와 Collider에서 `TerrainTraversalVerifier`를 사용해 연결로, 우회 왕복, 추락 복귀, 대응 능력 지름길을 검사한다. 기본 점프의 직진은 실패하고, 대응 능력의 직진은 안정적으로 착지하며, 지름길 시간은 우회보다 짧아야 한다. 화면에서 읽히는 착지대와 검사하는 착지 공간을 일치시킨다.
6. 최종 검증이 끝난 뒤 해금·안내·조사 지점과 바오밥 후보를 투영한다. 구간 진입과 복귀에 필요한 공간을 생성 후보에서 제외하고 월드를 확정한 뒤 기존 바오밥 시계를 시작한다.

### 배치 실패 처리

- 필수 지형의 배치·이동 검사 실패 시 기존 시도 상한 안에서 후보 방향과 연결로를 다시 선택한다. 공간이 겹치면 일반 지형이나 물길을 우선 조정한다.
- 마지막 후보는 시작 행성의 기준 반경에서 검증한 고정 배치로 준비한다. 이 배치도 해당 지형·우회로·해금 장소·기존 진입 경로를 포함하며 같은 최종 Collider 검사를 거친다. 행성 seed·크기·색과 챕터 진행은 기존 데이터에 따른다.
- 필수 지형이 포함된 최종 지면만 해당 시작 행성의 준비 성공으로 처리한다. 최종 후보가 실패하면 기존 월드 준비 실패 경로를 사용한다. 챕터 전환에서는 이전 행성으로 복귀할 수 있어야 한다.
- 일반 행성의 선택 지형은 현재의 크기 적합성, seed 배치, 검사 후 생략 규칙을 적용한다. 확정된 배치와 보완 내역은 기존 생성 계획에서 확인할 수 있게 한다.

### 완료 조건

- 기본 실행 경로에서 1챕터에 들어가 기존 E 해금과 M 이동을 사용해 3챕터까지 진행할 수 있다. 챕터 시작 행성마다 해당 지형이 실제 메시와 Collider에 등장한다. 빌드 시작 씬 설정과 에디터 Play 경로를 함께 확인한다.

- 일반 이동으로 각 지형의 우회로와 복귀 경로를 통과하고, 기존 해금 조작 뒤 대응 능력으로 지름길을 통과한다. 활공은 낮은 착지 평탄부에서 유효 접지를 확인한다.
- 보행으로 해금·조사·안내 지점에 도달할 수 있고, 바오밥은 우회로·출발대·착지대의 보호 범위 바깥에 배치된다. 지도 이동·리스폰·바오밥 대응·양 회수는 기존 캠페인 경로에서 함께 검증한다.
- 기존 `ChapterJourneyValidation`과 `ChapterJourneySceneValidation`을 활용한다. 결과에 실제 플레이한 씬, seed, 챕터별 생성 지형, 우회 및 지름길 통과, 고정 배치 사용 여부를 기록한다.

### 17.2 적용 범위와 우선순위

1. **재질부터 개선:** 노이즈 재질 인덱스 배정을 제거하고 하나의 지면 재질에서 넓은 색 변화·고도·경사를 연속 블렌딩한다. 미세 종이 질감은 약하게, 멀리서는 감쇠한다.
2. **큰 지형 개선:** 기존 2층을 큰 덩어리/중간 언덕으로 명확히 나누고 평탄부가 넓은 커브와 연속 지역 가중치를 적용한다. 고주파 높이는 0이다.
3. **코스 외곽 개선:** 검수 핵심 영역·우회/복귀·연결로를 보호하면서 주변 지형과의 합성 띠를 둥글고 불규칙하게 만든다.
4. **선택 옵션:** 낮은 강도의 도메인 워핑과 지역 제한 ridged 능선은 독립 설정으로 제공하되 기본값은 0부터 비교한다. 기본안이 충분하면 활성화할 필요 없다.

이번 필수 범위는 1~3과 아래 검증이다. 대륙/바다/설산 바이옴, 유체·침식, 새 LOD, 이동 모터·챕터 규칙 변경은 포함하지 않는다. 작은 동화풍 행성에서 사실적인 고산을 늘리는 것보다 넓은 쉼터와 몇 개의 읽히는 지형이 우선이다. 민트 경로선·출발/착지 표식은 현재 길찾기를 위해 유지하며, 외관 평가 캡처에서만 별도로 숨길 수 있다.

### 17.3 높이 필드 계약

- 입력은 정규화된 **행성 로컬 방향** `u`, 명목 반경 `R`, seed, 준비 시 복사한 설정이다. 월드 Y 고도를 쓰지 않는다. 크기 변화는 `R`에서 한 번만 반영한다.
- 현재 `Noise`는 이미 0~1이다. `(noise+1)/2`를 다시 적용하지 않는다. ridged가 필요하면 먼저 `signed=2*noise-1`로 변환한다.
- 큰 형태는 `N(u*fMacro+offsetA)`로 행성당 적은 수의 넓은 덩어리를 유지한다. 중간 형태는 `N((R*u)/hillScaleMeters+offsetB)`로 월드 크기를 유지한다. 여기서 scale은 주기 노이즈의 정확한 파장이 아니라 noise 좌표 1단위의 월드 길이다.
- 높이 합성의 개념은 `hFree = macroAmplitude*C(macro) + hillAmplitude*hillMask*(2*hill-1) + ridgeAmplitude*mountainMask*ridge`다. `C`는 0~1을 부호 있는 높이 비율로 보내는 단조 커브이며, 넓은 중간 평탄부와 양·음의 높이를 모두 허용한다. `Pow(h,1.8)`만으로 평야 면적이나 경사를 보장하지 않는다.
- `TerrainRegions`의 기존 연속 패치 가중치를 공용 함수로 추출해 `hillMask`, 분지 성향, 재질에 재사용한다. 새 필드 합성 후 예전 `Shape`를 다시 더해 진폭을 이중 적용하지 않는다. 논리 지역 분류는 배치 메타데이터이며 메시의 타일 경계를 만들지 않는다.
- 기본 진폭 예산 `A=min(0.55m,0.08*R)` 안에서 macro/hill을 80:20으로 시작한다. 예시 커브의 `(입력,출력)`은 `(0,-1),(.30,-.12),(.65,.12),(1,1)`이며 단조 보간과 overshoot 방지를 적용한다. 커브의 작은 기울기는 플레이 가능한 경사 보장의 대체물이 아니다.
- `fMacro=1.2`, `hillScaleMeters=3.2`를 첫 비교값으로 둔다. 작은 행성에서 중간층이 큰 형태보다 더 넓어지지 않게 `hillScaleMeters<=R/fMacro`로 제한한다. 수치는 필수 코스 치수와 무관하며 시각 비교 후 조절한다.
- 선택 ridged는 `ridge=(1-abs(2*N-1))²`로 만들고 별도의 저주파 지역 마스크 안에서만 적용한다. 활성화 시 기존 A의 일부를 재배분하고 총 변형 예산을 늘리지 않는다. 산지 면적 10~25% 같은 일반론을 게임 규칙으로 강제하지 않는다.
- 선택 warp는 seed가 분리된 세 저주파 필드로 자유 지형의 샘플 좌표만 약하게 변형한다. 보호 코스·통로·강의 좌표와 폭은 변형하지 않는다. 처음부터 FBM 다중 octave와 warp를 동시에 켜지 않는다.

최종 순서는 **자유 지형 → 보호 통로와 검수 코스 합성 → 기존 강바닥/여울 → 최종 메시·Collider → 이동 검증 → 표면 후보/상호작용 배치**다. 강은 합성된 `BaseHeight`를 기준으로 계획하고 기존 보호 조건을 통과해야 한다. 셰이더에서 정점을 움직이지 않는다.

참고 예제의 `Mathf.SmoothStep(0.6f,0.8f,value)`는 임계값 마스크가 아니다. Unity 함수는 from/to 사이를 보간한다. CPU에서는 기존 `Smooth(a,b,value)` 또는 아래 헬퍼를 사용하고 shader의 `smoothstep(a,b,value)`와 결과를 맞춘다.

```csharp
// 계약: b > a. 잘못된 설정은 준비 시 거부한다.
static float ThresholdSmooth(float a, float b, float value)
{
    float t = Mathf.Clamp01((value - a) / (b - a));
    return t * t * (3f - 2f * t);
}
```

### 17.4 검수 코스를 자연스럽게 연결하기

`TraversalTestCourseGeometry`는 고정 실험실의 기준으로 유지한다. 코스 전체에 warp·평활화·높이 커브를 적용하지 않는다. 캠페인 합성기 쪽에 **고정 핵심 영역과 외곽 전이 영역**을 명시한다.

- 고정 영역은 시작/목표 평탄부만이 아니라 검수한 단차·횡단면, 캡슐 폭과 여유를 포함한 전체 지름길, 기본 우회로·추락 복귀로, 연결로 접속부를 포함한다. 기존 `Start/Goal/BasicRoute`, 경계 표본, 검사 경로를 함께 사용하고 영역을 Gizmo로 표시한다.
- 이 영역에서는 기존 코스 높이와 보호 통로 높이를 그대로 평가한다. 골짜기 폭 4.2m·깊이 2m, 턱 2m/전이 0.2m, 활공 간격 7m·출발 +2.6m·착지 +0.4m와 중앙 평탄부를 보존한다. 특히 평활화로 절벽을 보행 경사로 바꾸지 않는다.
- 외곽은 직사각형 `max` 거리 대신 둥근 윤곽/거리 필드와 완만한 전이 가중치로 잇는다. 전이 폭은 1.5~3m부터 비교하며, 저주파 변화는 고정 영역 바깥에서만 허용한다. 넓어진 전이 전체를 기존 배치 예약·겹침 검사에도 포함한다.
- 기본 통로의 안전 반폭 `ProtectedHalfWidth=1.25m`와 스폰 보호 범위를 축소하지 않는다. 바깥 어깨 폭만 완만하게 변화시킨다. 이번에는 경로 중심선 자체를 재설계하지 않는다.
- 외곽 높이는 `lerp(hFree,hCourse,weight)`처럼 한 번 합성한다. 겹치는 요소의 높이를 무조건 더하지 않는다. 기존 예산과 예약을 우선하고 전이 공간이 부족하면 선택 요소를 생략한다.
- `BuildReviewedMesh`의 정확한 경계 표본을 유지한다. 두 메시 경로 모두 최종 높이에서 일관된 법선을 생성하되, 검수한 날카로운 단차까지 전역 평활화하지 않는다. 필요한 표시 정점 분리는 허용하지만 충돌 위치·삼각형 형상은 동일해야 한다.
- 고정 예비 배치에서는 기존처럼 자유 지형과 강을 끄고 검수 코스를 유지한다. 재질은 새 연속 재질을 사용할 수 있다. 외관 개선 실패를 이유로 필수 코스를 삭제하거나 검증을 생략하지 않는다.

### 17.5 연속 색상과 표면 디테일

절차적 지면 전용 URP 재질을 추가한다. 다른 모델과 고정 코스의 `B612/Traversal Course` 재질을 전역 수정하지 않는다.

1. 두 메시 빌더의 노이즈 기반 정수 재질 선택을 제거하고 절차적 지면은 기본적으로 **1 submesh / 1 소유 재질**을 사용한다. 기존 비절차적 지면은 원본 재질 경로를 유지한다.
2. 색은 `spec.terrain.groundColor`를 중심으로 낮은 채도의 흙·풀·암석 계열 명암을 연속 혼합한다. 모든 행성을 초록·흰색으로 통일하지 않는다. 눈은 이번에 자동 추가하지 않는다.
3. 방사 고도 `length(positionLocal)-R`, 최종 기하 법선과 방사 방향의 경사, 연속 지역 가중치, 강가 정보를 사용한다. 경사는 `acos(clamp(dot(normal,radial),-1,1))`의 각도로 조절하고 normal map 적용 전 값으로 계산한다. 월드 공간에서 계산한다면 normal과 radial을 모두 동일 공간으로 변환한다.
4. 고도 색 구간은 프로필의 고정 미터 범위를 사용한다. seed마다 min/max로 재정규화해 작은 요철이 극단적 색 대비를 만드는 일을 피한다. 급경사에는 암석 비중을 늘리고 강가에는 흙색을 보탠다. 낮은 고도 전체를 물가로 취급하지 않는다.
5. 큰 색 변화는 저주파 전용 필드로 넓고 약하게 넣는다. CPU에서 연속 마스크를 vertex color/UV 채널로 굽는 방식을 우선하고 채널 의미를 기록한다. shader에서 CPU의 모든 지형·물길 탐색을 픽셀마다 재실행하지 않는다. 시각용 seed는 지형·배치 난수 흐름과 분리한다.
6. 종이 질감은 **행성 로컬 위치·기하 법선의 triplanar**로 샘플링한다. 행성 이동/회전에 따라 무늬가 미끄러지지 않고, 극점/경도 UV 이음선에 의존하지 않아야 한다. 월드 미터와 같은 로컬 scale=1 계약을 유지한다.
7. 처음에는 triplanar albedo만 적용하고 미세 normal 강도 0으로 비교한다. 이후 0~0.15에서 검수하고, 정상 플레이 거리부터 저대비로 보이며 원거리에는 더 약하게 한다. 알베도 세부 대비는 약 5%부터, smoothness는 0.1 전후에서 시작한다. 거리 감쇠·mipmap을 사용하고 프레임마다 반짝이는 패턴을 없앤다.
8. normal map을 활성화한다면 각 투영축의 normal을 같은 공간으로 재구성해 블렌딩한다. tangent가 없는 현재 메시에서 일반 tangent-space 샘플을 그대로 섞지 않는다. 축 전환·반대편·극점에서 방향을 검증한다.
9. 현재 URP의 주광·환경광·그림자와 필요한 depth pass를 지원한다. 실루엣·바닥 그림자·카메라 depth를 실제 씬과 빌드에서 확인한다. 조명·노출 변경은 재질 비교 뒤 필요할 때만 국소 조절하고 다른 씬의 전역 조명을 바꾸지 않는다.

Play 중 설정 에셋을 바꿔 이미 준비된 지형의 높이 조회/중력/재질 마스크가 달라지면 안 된다.

### 17.7 구현 순서와 완료 조건

**비교 기준부터 확보한다.** 동일 seed·카메라·조명에서 원본, 단색+normal 없음, 새 재질만, 새 재질+높이/접합 개선을 비교한다. 실제 플레이 거리와 행성 전체 실루엣을 각각 캡처한다. 기존 UI/경로 표시를 끈 이미지와 실제 플레이 이미지를 따로 남겨 예쁜 전경만으로 완료하지 않는다.

최소 검증 범위:

- 여정 seed `612101/1/77`, 크기 `0.7/1/1.5/2`, 챕터 1~3의 36개 계획에서 유한 값·결정성·진폭·보호 영역·물길 규칙을 확인한다. 실제 행성 seed도 결과에 기록한다. 설정 에셋 참조만 같다는 이유로 동일 입력이라고 판단하지 않는다.
- 최종 월드는 챕터별 시작 행성 3종과 일반 행성 크기 4종을 포함한다. 기준 반경 12m 캠페인과 5.3m 기존 공통 경로를 모두 점검한다. 고정 예비 배치 3종과 강 생략/월드 준비 실패 경로도 확인한다.
- `TerrainTraversalVerifier`와 기존 `ChapterJourneyValidation/SceneValidation`, 지형 2단계 회귀 검사를 활용한다. 기본 양방향 우회·추락 복귀·연결로·해금 장소 도달, 기본 직진 실패/대응 능력 성공, 지름길 시간 이득, 착지 자원 회복을 재검증한다. 실패를 숨기기 위해 검사 조건을 완화하지 않는다.
- 두 메시 경로에서 표시/Collider 형상 일치, 극점·cube face·경도 이음선의 균열과 색/법선 이음선, 물 표면과 강바닥의 관계를 확인한다. 지면 공유 원본과 다른 씬의 재질은 바뀌지 않아야 한다.
- 외관 판정: 원거리에서 작은 얼룩보다 큰 높낮이가 먼저 읽히고, 정상 플레이 거리에서 사각형 재질 칸·UV 늘어짐·종이 노멀 번쩍임이 없어야 한다. 코스 외곽의 직사각형 테두리는 줄이되 출발/착지 가장자리와 우회로는 읽혀야 한다. 단색 비교로 실제 형상 개선도 확인한다.
- 평지/언덕 가중치를 면적 비율로 보고하지 않는다. 표본 면적 가중으로 경사 0~15/15~30/30도 초과 비율과 고정 코스 영역을 별도로 기록해 전후 비교한다. 숫자 하나를 맞추려고 검수 장애물을 깎지 않는다.
- 지도 재열기·F12·E 해금·R은 지형을 재생성하지 않는다. 3챕터 전환, 바오밥 후보 보호, 양 소환/먹기/회수, 물속 보행 감속이 유지된다.
- 같은 환경에서 생성 시간·정점/삼각형 수·재질 수·프레임 비용·소유 객체 해제를 전후 측정한다. 재질 개선 때문에 메시 해상도를 올리지 않는다. 이미 큰 메시 생성 비용이 있으므로 warp/능선의 추가 샘플 비용도 보고한다.
- 에디터와 플레이어 빌드에서 shader 누락·분홍 재질·그림자/depth 오류를 확인한다. 빌드를 실행하지 못했다면 미검증으로 기록한다.

CLI 검증의 적용 설정, 전후 화면, seed별 회귀 결과, 비용과 확인 범위는 [구현 결과](TerrainAppearanceImplementationResults.md)에 기록했다.

참고 API: [Unity Mathf.SmoothStep](https://docs.unity3d.com/kr/current/ScriptReference/Mathf.SmoothStep.html), [Unity Triplanar 노드](https://docs.unity3d.com/kr/Packages/com.unity.shadergraph%4010.8/manual/Triplanar-Node.html). 후자는 투영/법선 합성 개념 참고이며 프로젝트 Unity 6000.3.23f1에 설치된 URP/Shader Graph 소스를 실제 구현 기준으로 사용한다. 위 미술 방향과 수치는 B612용 제안이다.

## 18. 큰 지형 형태와 색 구분 보완

2026-11-18 작성. 사용자가 17절 구현 화면의 단조로운 지형을 확인하고 명세 수정을 요청했다. **문서만 수정한 후속 구현안**이다. 목표는 잔무늬가 적으면서도 넓은 언덕·분지·쉼터가 읽히는 동화풍 소행성이다. 아래 수치는 비교 실험의 시작값이며 최종 밸런스가 아니다.

### 18.1 진단과 변경 원칙

- 현재 `FreeHeight`의 큰 층은 최대 0.55m의 80%에 커브를 곱한다. 커브 입력 0.30~0.65에서는 출력이 −0.12~+0.12이므로 큰 층의 변위가 약 ±0.053m에 그친다. 이것이 모든 seed의 실제 높이 범위라는 뜻은 아니지만, 중앙값 주변이 과도하게 눌리는 구조다.
- 1차 결과의 94.01% 완경사는 검수 기준 영역을 제외한 면적 통계다. 보호 길도 포함하므로 이를 자유 지형 전체의 단조로움이나 재미의 단독 증거로 쓰지 않는다. 후속 통계는 고정 코스·보호 통로·자유 지형을 구분한다.
- 현재 셰이더는 대표색에 비슷한 RGB 배율을 곱한 흙·풀·돌을 섞는다. 연속성은 개선됐지만 실제 야간 조명에서는 색 구분이 약할 수 있다. 화면상의 단색 인상을 단순 shader 미적용으로 판단하지 않는다.
- 지형 높이를 전체적으로 몇 배 올리는 것만으로 해결하지 않는다. **적은 수의 넓은 지형 덩어리를 먼저 만들고 저주파 노이즈는 형태의 변주로 사용한다.** 고주파 displacement·강한 종이 normal은 다시 추가하지 않는다.
- 스크린샷의 파란 삼각형은 정체 미확인이다. 물·안내 메시·다른 오브젝트 중 무엇인지 렌더러를 분리해 재현한 뒤 처리한다. 진단 전 메시 구멍이나 강 오류로 확정하지 않는다.

### 18.2 자유 지형의 큰 덩어리

기존 타일/지역/코스 생성은 유지하고 `Plan`에 자유 지형용 큰 형태 목록을 추가한다. 검수 이동 요소인 `features`와 별개이며, 언덕이 추가됐다고 능력 장애물 예산을 소모하거나 늘리지 않는다.

1. 필수 코스·통로·스폰 예약 뒤, 기존 지역 패치 중심을 후보로 사용해 넓은 언덕과 낮은 분지의 중심·영향 반경·높이를 정한다. 별도 파생 seed와 안정된 순서로 선택한다. 큰 지역이 필요하면 인접 패치들을 묶을 수 있으며 셀마다 독립 높이를 만들지 않는다.
2. 반경 12m의 비보호 자유 지형에는 우선 **넓은 언덕 1~2개와 낮은 분지 1개**를 시도한다. 작은 행성/예약이 많은 시작 행성에서는 0~1개로 줄일 수 있다. 억지로 보호 영역을 침범하지 않고 생략 이유를 기록한다. 최소한 대표 비교 seed 중 자유 지형 공간이 충분한 일반 행성에서 이 구성을 실제로 보여야 한다.
3. 중심에서의 구면 호 거리 `d=R*acos(clamp(dot(u,centre),-1,1))`, 영향 반경 `L`로 `t=clamp01(d/L)`를 구한다. 시작 커널은 `K=(1-t*t)^2`이며 d>=L이면 0이다. 중심과 외곽에서 기울기가 0인 넓은 돔/분지를 만든다. 원형 도장처럼 반복되면 제한된 타원형 범위 또는 서로 다른 L로 변주하되 먼저 단순 커널을 검증한다.
4. 반경 12m의 첫 비교 범위는 언덕 높이 +0.8~1.4m / 영향 반경 5~8m, 분지 깊이 −0.4~−0.8m / 영향 반경 4~7m다. 더 작은 행성은 길이·높이를 `s=clamp(R/12,0.3,1)`로 함께 줄인다. 더 큰 행성에서도 개별 지형을 끝없이 키우지 않는다. 이는 자유 지형에만 적용하며 검수 코스 치수는 고정 월드 단위다.
5. 중첩 시 높이를 무제한 합산하지 않는다. 같은 종류의 기여는 정규화한 부드러운 가중 평균 등으로 한 덩어리처럼 섞고, 분지와 언덕도 제한된 예산 안에서 합성한다. 날카로운 max/min 경계와 마지막 hard clamp로 만든 평평한 잘림을 피한다.
6. 자유 지형의 첫 안전 예산은 `abs(hFree)<=min(1.6m,0.14*R)`다. 검수 코스 높이는 이 상한으로 자르지 않는다. 경사/도달성 실패 시 해당 덩어리의 높이를 낮추거나 영향 폭을 넓힌 뒤 유한하게 재검증한다.

위 수치에서 경사 안전이 자동 보장되지는 않는다. 특히 보호 길에 가까운 큰 언덕은 합성 어깨가 급해질 수 있으므로 예약 거리와 최종 Collider 검사로 걸러야 한다.

### 18.3 노이즈와 평지의 역할 재조정

- 자유 지형 합성은 `hFree = broadShapes + residualMacro + maskedHills`로 바꾼다. 기존 `A` 하나에 모든 항을 나누는 구조 대신 큰 형태 높이와 잔여 노이즈 진폭을 별도 설정으로 둔다. 기존 `Shape`를 추가로 중복 적용하지 않는다.
- 잔여 큰 노이즈의 진폭은 `0.15~0.25m*s`, 중간층은 `0.04~0.10m*s`부터 비교한다. 큰 노이즈 주파수 1.2와 중간 scale 3.2m는 우선 유지한다. 위 합산 결과도 자유 지형 예산 안에 있어야 한다.
- 잔여 큰 층의 커브는 우선 선형 `(0,-1),(1,1)`로 두고, 전역 중앙 구간을 ±0.12로 압축하던 커브는 기본값에서 제외한다. 평지는 전역 커브로 전체 행성을 눌러 만들지 않고 기존 Plain 가중치에 따라 중간층을 약화하거나 국소 쉼터를 만든다.
- 평지는 방사 높이 0에만 있을 필요가 없다. 완만한 언덕 위의 넓은 쉼터도 허용한다. 단, 기존 보호 통로·스폰의 높이는 이번에 바꾸지 않는다.
- warp/ridged는 계속 기본 0이며 이번 필수 구현에서 켤 필요 없다. 큰 형태가 부족한 문제를 octave 증가나 산맥 추가로 대체하지 않는다.

### 18.4 코스와 보호 길의 접합

17.4의 고정 핵심 영역과 검수 치수는 그대로 보존한다. 외곽 전이 폭 2.4m는 모든 높이차에 안전한 상수가 아니므로 새 높이 예산에 맞게 재검토한다.

- 높이가 큰 덩어리는 코스/보호 길의 바로 바깥에 중심을 두지 않는다. 전이 공간까지 포함한 거리로 배치 가능성을 판정한다.
- 자유 지형과 고정 지형의 높이차가 크면 바깥 전이 폭을 넓히거나 해당 자유 지형을 낮춘다. 폭 상한 때문에 검사에 실패하면 그 덩어리를 생략한다. 보호 반폭을 줄이거나 지름길 단차를 깎지 않는다.
- 기본 우회·복귀·연결로뿐 아니라 새 언덕/분지에 들어갔다가 기본 길로 나오는 경사와 캡슐 여유를 검사한다. 새 바오밥 후보가 단순 경사 검사만 통과한 고립 지점에 생기지 않도록 한다. 접근을 검증하지 못한 영역은 후보에서 제외한다.
- 고정 예비 배치의 평탄화는 계속 안전 복구로 허용하되 정상 외관 완성으로 평가하지 않는다. `safeFallback/fixedPlacement`와 자유 형태 생략 여부를 화면 비교 결과에 함께 기록한다.

### 18.5 넓은 색 영역

`PlanetGround.shader`의 한 재질·로컬 triplanar와 약한 종이 질감은 유지한다. 새 높이만 바꿔 재질이 저절로 구분되기를 기대하지 않는다.

- 프로필에 흙·식생·암석의 색 또는 대표색 상대 색조를 노출한다. 현재 고정 RGB 곱셈만 쓰던 방식을 확장하되 `groundColor`의 행성별 정체성은 유지한다. 선택된 색을 준비 시 복사하고 이후 설정 변경에 흔들리지 않게 한다.
- 식생은 낮은 경사와 지역 정보, 암석은 급경사, 흙은 분지/강가를 중심으로 **넓은 연속 영역**을 만든다. 기존 마스크가 거의 같은 중간값에 몰리는지 분포를 기록하고 조절 가능한 remap을 둔다. 새로운 고주파 색 노이즈를 넣지 않는다.
- 흙/풀 중간 혼합색 하나가 전 표면을 덮지 않도록 저경사 대표 구간에서 서로 다른 우세 재질 영역이 보이게 한다. 영역 경계는 부드럽게 하고 고도별 수평 띠를 여러 겹 만들지 않는다.
- 새 자유 높이 예산에 맞춰 고도 색 범위를 프로필 고정값으로 조정한다. seed별 min/max 정규화는 금지한다. 낮은 분지 자체를 물로 표현하지 않는다.
- 형상만 보는 단색 조명, 재질만 보는 unlit 색, 실제 야간 조명 화면을 분리해 비교한다. 주간 진단 화면에서만 구분되고 실제 게임 화면에서는 단색이면 완료가 아니다. 전역 조명을 밝히거나 발광색을 넣어 덮지 않는다.
- 미세 normal 0, 종이 대비 0.05를 기본으로 유지한다. 색과 형태가 읽힌 뒤에만 미세 질감을 조절한다.

### 18.6 구현 순서·파일·버전

1. 현재 5버전의 같은 seed 화면/형상/통계와 사용자 화면의 재현 조건을 확보한다. seed가 불명확하면 현재 월드 정보를 기록하고, 알려진 비교 seed도 병행한다. 파란 삼각형은 이 단계에서 렌더러별로 분리 진단한다.
2. `TerrainAppearanceSettings`에 큰 형태 개수·높이·반경·잔여 진폭·표면색 설정을 추가한다. `ProceduralPlanetTerrain.Plan`에 확정 형태와 파생 seed·설정 복사본을 기록하고 `FreeHeight` 및 보호 합성을 갱신한다.
3. `TerrainRegions`의 연속 가중치를 재사용해 형태 후보와 재질 마스크를 연결한다. `PlanetGround.shader`, `PlanetWorldInstance`의 속성 전달, 세 설정 에셋 및 관련 빌더를 함께 수정한다. 기존 에셋의 신규 0/null 필드도 초기화한다.
4. 단색에서 형태를 검수한 뒤 색을 조절하고 최종 이동/배치 검증을 한다. `AgentScripts/runtime`과 `Assets/B612/Scripts`를 동기화한다. 모터·능력·카메라 수치로 실패를 우회하지 않는다.
5. 구현 시 생성기와 Plan 버전은 5→6, 프로필은 `terrain.stylized.v2`로 함께 갱신한다. 기존 버전 검증·빌더·테스트 기대값을 맞추고 과거 seed의 지형 동일성은 보장하지 않는다. 데이터 형식은 불필요하게 변경하지 않는다.

자유 형태 후보 탐색은 행성당 최대 64회, 완성 메시 준비는 기존 최대 5회 범위를 유지한다. 높이 보정→선택 자유 형태 생략→기존 안전 복구 순서를 준비 예산 안에 넣고, 별도 무제한 재시도 루프를 만들지 않는다. 모든 실패/생략 사유와 최종 높이를 남긴다.

### 18.7 완료 기준

| 이상 메시 | 파란 삼각형의 대상/원인을 기록. 재현되면 수정 전후 비교, 재현되지 않으면 미확인으로 명시 |
| 플레이 | 기존 필수 동선·능력 지름길·복귀와 새 자유 지형의 접근/이탈이 가능. 바오밥 후보의 도달성 유지 |

기존 여정 seed 612101/1/77에 대해 각 챕터 시작 행성 및 넓은 일반 행성을 비교한다. 고정 코스, 보호 통로, 나머지 자유 지형을 분리해 최종 방사 높이 P10/P50/P90·최소/최대와 면적 가중 경사 비율, 실제 배치된 큰 형태 수, 보완/예비 배치 사용을 기록한다. 겹치는 표본의 분류 우선순위는 고정 코스→보호 통로→자유 지형이다.

반경 12m의 공간이 충분한 대표 일반 행성에서 자유 높이 `P90-P10` 0.6~1.2m를 첫 조절 목표로 비교한다. 이는 균일 구면 면적 표본으로 계산하고, 모든 작은 행성/예약이 많은 시작 행성에 강제하는 통과 기준은 아니다. 수치에 맞추려고 검수 구간을 변경하지 않는다. 수치가 맞아도 화면에서 덩어리가 읽히지 않으면 완료가 아니다.

같은 카메라·조명에서 **5버전 기준 / 큰 형태만 변경 / 최종 색 포함**을 찍는다. 각 단계는 플레이 화면과 행성 앞/옆/뒤 전경을 남기고 단색 비교도 포함한다. 대표 seed 하나만 보기 좋게 만들고 나머지를 생략하지 않는다. 모든 seed가 안전 복구나 자유 형태 생략으로만 통과하면 외관 개선 실패로 보고한다.

결과는 `Docs/TerrainAppearanceImplementationResults.md`에 별도의 **2차 개선** 절로 추가한다. 기존 1차 측정은 보존하고 적용 설정·새 캡처·회귀·비용·미검증 항목을 구분한다. 실제 구현 완료 뒤에만 기획/README의 구현 상태를 갱신한다.
