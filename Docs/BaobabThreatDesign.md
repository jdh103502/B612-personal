# 바오밥 위험도와 게임 오버 설계안

2026-10-31. 사용자가 요청한 게임 오버 조건과 싹 총량·생존 시간 기반 게이지를 구체화한 기술 제안이다. 최초 작성은 설계와 수식 확인이었으며, 후속 구현 요청으로 아래의 첫 시제품 범위를 코드·씬·UI에 적용했다. 이후 본문의 확장 제안 전체를 구현한 것은 아니다.

## 첫 시제품 구현 (2026-10-31 후속)

- `B612_EmptyPlanet`에 `BaobabThreatMeter`와 `BaobabThreatHUD`를 연결했다. 기본 수식·개별 상한 25·고정 한계량 100을 사용한다. 살아 있는 싹만 합산하고 제거 후 해당 몫을 빼는 권장 해석을 채택했다. 이 수치는 최종 밸런스가 아니다.
- `BaobabSurge.SimulationSeconds`는 생성 시간 종료 후에도 흐르는 게임 시계다. `ElapsedSeconds`는 기존대로 120초에 멈춘다. `SpawnRecord.spawnedAt`은 실제 생성한 시각이며, 한 프레임에 여러 생성 기회를 처리해도 예정 시각 `scheduledTime`으로 나이를 소급하지 않는다.
- `BaobabTypeDefinition`은 성장 수식 설정을, `PlanetBaobabProfile`은 고정 한계량과 기본 싹 종류를 담는다. 시작 시 설정을 복사하여 실행 중 공유 에셋 변경이 현재 시도에 반영되지 않게 한다. 각 생성 기록은 종류 참조와 성장값 사본을 가진다. 다른 수식 값을 가진 종류도 합산 코드는 공유할 수 있다.
- **프로필 확장 범위:** 이번 프로필에는 위험도 설정만 구현했다. 생성 시간·기회 수·활성 상한은 기존 `BaobabSurge` 필드가 계속 소유한다. 크기별 자동 선택, 생성 묶음, 종류별 등장 가중치·상한·모델·작업량은 아래의 설계 제안 상태다. 기존 120초·40회·회당 1개·동시 6개를 유지한다.
- `Surging → Clearing → Resolved` 상태로 생성 종료 후에도 위험도 판정을 계속한다. `Resolved`는 안전 표시까지만 하며 수확 단계로 이동하지 않는다. `Surging` 또는 `Clearing`에서 100%에 도달하면 `GameOver`를 한 번만 확정한다.
- 먹는 동안도 성장한다. 양들의 `Update`가 끝난 뒤 `BaobabThreatMeter.LateUpdate`에서 제거 결과를 합산해 판정한다. 같은 프레임의 먹기 완료는 패배 판정보다 우선한다. 큰 검증 시간 간격에서 서로 다른 시각의 먹기 이벤트까지 자동 재생하는 중앙 시뮬레이터는 추가하지 않았으며, 방치 시간 검증은 0.01초 단위로 진행한다.
- 게임 오버에서 게임 시간 배율을 0으로 두고 플레이어·카메라 입력을 끈다. 생성·제거·양 먹기·소환 진입점도 종료 상태를 확인한다. UI는 정지 중에도 동작한다. 위험도 바와 숫자는 실제 비율을 직접 표시하고 패배 순간 정확히 100%가 된다. 패배 전 숫자는 내림하여 99.x%가 100%로 먼저 보이지 않게 한다.
- `TRY AGAIN` 버튼 또는 Enter로 현재 씬을 새로 불러온다. 카드·양·싹·시계·게이지를 초기화하며 기본 seed 설정은 다시 적용한다. 시제품 재시도 방식이며 전체 게임의 진행 보존·꿈 연출 규칙을 확정하지 않는다. 재시작을 위해 이 씬을 기존 Build Settings 목록에 추가했다.
- 행성 파괴, 싹의 성장 모델·말풍선 단계 표시, 작물 피해, 수확 전환은 포함하지 않는다.

구현 파일: `Assets/B612/Scripts/BaobabThreatMeter.cs`, `BaobabThreatHUD.cs`, `BaobabTypeDefinition.cs`, `PlanetBaobabProfile.cs`. 설정 에셋은 `Assets/B612/Settings/`에 있다. 기존 씬에 연결하는 도구는 `AgentScripts/BaobabThreatBuilder.cs`이며 기존 싹 생성·양 배치 설정을 덮어쓰지 않는다.

## 사용자가 정한 요구

- 행성 전체의 바오밥 게이지가 100%가 되면 게임 오버다.
- 개별 싹 하나의 방치 타이머를 전체 게이지로 사용하는 방식 대신, 모든 싹의 총량을 합산한다.
- 오래 살아남은 싹은 게이지를 더 빠르게 100%로 향하게 하는 데 기여한다.
- 행성 크기에 따라 한 번에 등장하는 싹 수가 달라지고, 이후 싹 종류를 추가할 수 있도록 확장 가능하게 설계한다.

## 권장 해석: 현재 살아 있는 뿌리의 압박도

각 싹은 생존 시간에 따라 성장하는 위험 기여도를 가진다. 전체 게이지는 현재 살아 있는 싹들의 기여도 합계다.

이 안에서 게이지는 현재 행성이 받는 압박을 뜻한다. 싹을 먹으면 해당 싹의 기여도가 사라지고, 싹이 모두 없어지면 게이지는 0이다. 제거해도 이미 쌓인 양이 남는 누적 피해 방식은 별도 대안이다.

누적 피해를 매초 더하는 방식은 한 싹만 남아도 충분히 오래 지나면 결국 100%를 만든다. 한 싹의 단독 패배를 막으려는 의도에는 현재 기여도 합산과 개별 기여도 상한의 조합이 잘 맞는다. 사용자가 제거 후 게이지 처리를 확정한 것은 아니므로 아래 감소 규칙도 제안 상태다.

## 기본 싹과 기준 행성의 수식 제안

```text
a = 해당 싹이 실제 생성된 뒤 살아 있던 게임 시간(초)
싹 기여도 = min(25, 2 + 0.15 × a + 0.005 × a²)
전체 위험량 = 살아 있는 싹의 기여도 합계
게이지(%) = clamp(전체 위험량 / 행성 한계량 × 100, 0, 100)
첫 시제품 행성 한계량 = 100
```

숫자는 초기 비교용이며 최종 밸런스가 아니다. 생존 시간은 전체 폭주 진행 시간과 구분한다. 싹 기여도는 위험량 단위인 '점'이다. 한계량 100인 기준 행성에서만 25점이 게이지 25%와 같다. 다른 행성에서도 25%로 고정하지 않는다.

| 생존 시간 | 싹 하나의 기여도 | 의미 |
| --- | ---: | --- |
| 생성 직후 | 2 | 새 싹도 작은 압박을 줌 |
| 10초 | 4 | 초반 성장 |
| 20초 | 7 | 증가량이 커짐 |
| 30초 | 11 | 우선 처리할 대상 |
| 40초 | 16 | 큰 위험원 |
| 50초 | 22 | 매우 큰 위험원 |
| 약 54.46초 이후 | 25 | 개별 상한 |

상한에 닿기 전 증가 속도는 초당 `0.15 + 0.01 × a`다. 0~10초에는 2점, 10~20초에는 3점, 20~30초에는 4점이 늘어 시간이 지날수록 가속된다. 상한에 도달하면 25점의 압박을 유지하며 추가 성장은 멈춘다.

한계량 100인 기준 행성에서 기본 싹 하나는 최대 25%를 차지하고, 세 싹은 최대 75%, 충분히 자란 네 싹은 100%를 만들 수 있다. 따라서 같은 여섯 싹이라도 나이 구성에 따라 위험도가 달라진다. 소수의 싹을 무한히 남겨도 단독으로 패배시키지 않는 성질은 상한을 선택한 결과이므로 플레이 검증에서 의도에 맞는지 확인한다.

## 수치 예시와 수식 확인

- 새 싹 여섯 개: 12%.
- 모두 30초 된 싹 여섯 개: 66%.
- 모두 40초 된 싹 여섯 개: 96%.
- 생존 시간이 40, 40, 30, 30, 20, 10초인 여섯 싹: 65%.
- 위 상황에서 40초 된 싹 하나를 제거: 49%.
- 같은 상황에서 10초 된 싹 하나를 제거: 61%.

현재의 3초 간격 생성과 동시 활성 6개 상한을 수식으로 적용하면, 아무것도 제거하지 않을 때 약 48.47초에 처음 100%에 도달한다. 생성 위치 실패 없이 0·3·6·9·12·15초에 생성된다는 가정이다. 실제 플레이나 Unity 실행을 통한 검증 결과는 아니다.

추가로 0.01초 간격의 수치 확인에서, 이동·회수 비용 없이 10초마다 가장 오래된 싹 하나를 즉시 제거하면 120초 동안 최대 약 83.11%였다. 두 개씩 제거하면 최대 약 39.21%였다. 현장에서는 양 배치·먹기·20초 수명·카드 회수 시간이 있으므로 이 결과를 플레이 난이도나 클리어 보장으로 해석하지 않는다.

양 네 마리의 이론상 처리량과 실제 이동 비용을 고려해 초기 수식을 조정해야 한다. 생성 간격, 동시 활성 수, 성장 계수를 한꺼번에 바꾸지 말고 방치 시 패배 시간과 적극 대응 시 여유를 나눠 비교한다.

## 행성 크기와 싹 종류 확장 (2026-10-31 보완)

사용자가 추가로 요청한 확장성에 대한 설계다. 행성별 수량이나 싹 종류의 구체적인 수치는 아직 제안이며, 현재 씬의 활성 상한 6개와 기본 싹 프리팹은 변경하지 않는다.

### 서로 다른 세 가지 수량

- `spawnBatchSize`: 한 번의 생성 시점에 요청하는 싹 수.
- `maxActiveSprouts`: 행성 전체에서 동시에 살아 있을 수 있는 싹 수의 상한.
- `spawnIntervalSeconds`: 생성 시점 사이의 간격.

예를 들어 '3초마다 2개, 동시에 최대 12개'를 표현할 수 있다. 여기에 폭주 지속 시간과 총 생성 수 제한이 필요하면 별도 필드로 둔다. 생성 기회 수, 성공한 생성 수, 현재 활성 수를 혼용하지 않는다.

한 번에 여러 개를 만들더라도 기존의 행성 전체 분산 배치와 최소 간격 규칙을 각각 적용한다. 실제 생성 수는 남은 활성 자리·종별 상한·유효 배치 지점에 제한된다. 배치 성공분만 활성 상태에 등록하고, 생성하지 못한 수량을 다음 시점에 무한히 몰아서 생성하지 않는다.

현재 `targetSprouts`는 단일 생성 기회의 목표 개수로 사용된다. 확장 구현에서는 생성 시점 수와 시점당 요청 수를 분명하게 이름 붙여 총 생성량이 의도치 않게 배수로 늘지 않게 한다. 기존 프로필을 옮길 때는 120초·40회·회당 1개·동시 6개를 보존한다.

### 행성 설정과 종류 설정 분리

| 설정 에셋 제안 | 보관할 정보 |
| --- | --- |
| `PlanetBaobabProfile` | 고정 한계량, 폭주 시간, 생성 간격·묶음 수, 활성 상한, 등장 가능한 종류와 가중치·종별 상한 |
| `BaobabTypeDefinition` | 안정적인 종류 ID, 표시 이름·프리팹, 시작 위험량, 선형·가속 성장 계수, 개별 위험량 상한, 배치 크기, 먹기 작업량·특성 태그 |
| 런타임 `SpawnRecord` | 개별 ID, 종류 설정 참조, 실제 생성 시각, 배치 지점, 활성·제거 상태 |

Unity에서는 행성·종류 설정을 ScriptableObject 에셋으로 둘 수 있다. 공유 에셋에는 싹 나이·먹기 진행도 같은 개별 상태를 기록하지 않는다. 행성을 시작할 때 적용할 설정을 확정하고, 플레이 도중 공유 설정 변경으로 기존 싹의 위험량이 갑자기 바뀌지 않게 한다.

종류별 계산은 동일한 인터페이스로 제공한다.

```text
기여도_i(a) = min(종류_i.상한,
                 종류_i.시작량 + 종류_i.선형계수 × a + 종류_i.가속계수 × a²)

전체 위험량 = 활성 싹 각각의 기여도_i(각각의 생존 시간) 합계
게이지 = clamp(전체 위험량 / 현재 행성의 고정 한계량 × 100, 0, 100)
```

초기에는 같은 수식에 종류별 값만 다르게 넣는다. 나중에 단계형 성장이나 특수 행동이 필요하면 기여도를 구하는 함수를 교체할 수 있게 하되, 첫 구현에서 별도 행동 프레임워크까지 만들 필요는 없다.

### 크기별 초기 프로필 예시

| 크기 | 회당 요청 수 | 동시 활성 상한 | 고정 한계량 | 예시 생성 간격 |
| --- | ---: | ---: | ---: | ---: |
| 소형·기준 | 1 | 6 | 100점 | 3초 |
| 중형 | 2 | 12 | 200점 | 3초 |
| 대형 | 3 | 18 | 300점 | 3초 |

이 표는 정규화 원리를 설명하는 수치 예시이며 확정 난이도가 아니다. 회당 수량과 활성 상한이 같은 비율로 늘어나는 경우 한계량도 같은 비율로 늘리는 것을 초기 기준으로 삼았다.

- 기본 싹 하나의 최대 25점은 소형에서 25%, 중형에서 12.5%, 대형에서 약 8.33%다.
- 기본 싹이 모두 40초 됐을 때 6·12·18개의 위험량은 각각 96·192·288점이고, 세 프로필 모두 게이지 96%다.
- 모든 배치가 성공하고 제거하지 않는 수식 확인에서는 세 프로필 모두 약 48.47초에 100%에 도달했다. 같은 시점에 같은 비율로 생성되므로 얻어지는 결과다.
- 플레이어의 양 수·먹기 속도는 자동으로 늘어나지 않는다. 대형 프로필은 더 많은 싹을 더 넓은 공간에서 처리해야 하므로 실제 대응 난이도는 같지 않다. 더 긴 생성 간격이나 다른 성장 곡선도 함께 비교한다.

행성 크기는 사용 가능한 면적을 기준으로 소형·중형·대형 등 프로필을 선택하는 초기 입력으로 사용한다. 면적만으로 수량·한계량·난이도를 모두 자동 확정하지 않는다. 구형 근사 면적, 플레이 가능한 면적, 이동 거리와 실제 배치 가능 수가 다를 수 있다. 생성 실패로 실제 싹이 적게 나왔다고 그 자리에서 한계량을 낮추지 않는다.

### 종류별 예시

| 종류 제안 | 시작량 | 선형계수 | 가속계수 | 개별 상한 | 30초 때 기여도 | 먹기 작업량 예시 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 기본형 | 2 | 0.15 | 0.005 | 25 | 11점 | 10 |
| 급성장형 | 2 | 0.30 | 0.010 | 25 | 20점 | 10 |
| 굵은 뿌리형 | 4 | 0.20 | 0.008 | 40 | 17.2점 | 15 |

모두 설명용 가상 종류이며 신규 모델·종류를 구현한 것은 아니다. 기본형 여섯 개가 모두 30초 된 상황은 66점이지만, 기본형 3개·급성장형 2개·굵은 뿌리형 1개가 모두 30초면 90.2점이다. 소형 행성에서는 각각 66%, 90.2%가 된다.

강한 종류가 나왔다고 행성 한계량을 그 종류의 상한에 맞춰 자동으로 키우지는 않는다. 같은 행성에서 종류 구성이 더 위험해지는 효과를 보존한다. 종류별 등장 가중치와 동시 활성 상한을 프로필에서 설정해 어려운 종류만 연속으로 나오는 상황을 제어할 수 있다.

먹기 작업량은 일반 양의 작업 속도가 초당 1일 때 10이면 10초가 걸린다는 의미다. 추후 특정 싹에 강한 양은 해당 태그의 작업 속도를 높이는 방식으로 연결할 수 있다. 현재 `secondsPerSprout = 10`인 구현을 이 규칙으로 이미 바꾼 것은 아니다.

### 한계량을 고정해야 하는 이유와 검증

- 분모는 행성 시작 시 정한 한계량을 유지한다. 현재 활성 싹 수나 현재 싹들의 상한 합계로 나누지 않는다. 싹을 제거했는데 분모도 줄어 게이지가 그대로이거나 오르는 현상을 방지한다.
- 한 싹의 단독 패배를 막는 기본 방침을 유지하려면, 그 행성에서 등장 가능한 모든 종류의 개별 상한이 행성 한계량보다 작아야 한다. 특수 행성에서 예외를 만들 경우 별도 규칙으로 명시한다.
- `활성 상한 × 등장 가능한 종류의 최대 상한`조차 한계량보다 작으면 패배에 도달할 수 없는 프로필이다. 이는 빠른 불가능 판정용이다.
- 반대로 위 곱이 한계량 이상이라는 사실만으로 패배 가능성이 보장되지는 않는다. 종별 활성 상한, 생성 일정, 성장 시간, 유효 배치 수까지 반영한 방치 시뮬레이션으로 확인한다. 기본형만 나오는 프로필도 별도로 검증한다.
- 예: 기본형만 18개·개별 상한 25점이면 최대 450점이다. 한계량을 500점으로 설정하면 100%에 도달하지 못한다.
- 여러 종류의 시각 크기가 달라지면 배치 간격에도 반영한다. 기존 전역 최소 간격에 종류별 점유 반경을 함께 적용한다.
- 동일한 seed·프로필·생성기 버전에서 종류 선택과 위치 배치를 재현할 수 있게 난수 흐름을 구분한다.

## 제거와 먹기 규칙 제안

- 양이 먹는 중에도 싹은 살아 있으며 기존 기여도와 성장을 유지한다.
- 실제 먹기가 완료되어 싹이 제거될 때 그 몫을 합계에서 제외한다.
- 먹기 시작만으로 기여도를 0으로 만들지는 않는다. 양 배치와 취소만으로 압박을 없애는 일을 피한다.
- 제거 시 별도의 고정 감소량을 중복 적용하지 않는다. 해당 싹의 기여도 제거가 곧 게이지 감소다.
- 100%에 도달해 게임 오버 상태가 확정되면 이후 제거로 되돌릴 수 없다.
- 먹는 동안 성장 속도를 늦추거나 일부 회복시키는 규칙은 나중에 별도로 비교할 수 있다. 첫 구현에는 넣지 않는 안을 추천한다.

## 120초 타이머와의 관계

설계 당시 `BaobabSurge`는 120초에 신규 생성을 멈추고 남은 싹을 유지했다. 완료 뒤에도 양은 남은 싹을 먹을 수 있었고, 타이머는 클리어 판정에 연결하지 않았다. 이후 첫 시제품에는 위 구현 절의 정리·안전 상태와 위험도 판정을 추가했다.

연결안으로 다음 흐름을 제안한다.

```text
Surging: 새 싹 생성 + 기존 싹 성장 + 위험도 판정
  → 생성 시간 종료
Clearing: 새 싹 생성 중단 + 남은 싹 성장 + 위험도 판정
  → 남은 싹이 0개
Resolved: 바오밥 단계 종료, 수확 단계로 이동

Surging 또는 Clearing에서 위험도 100% → GameOver
```

정리 단계는 새로운 제안이며 기존 기획에서 확정한 추가 단계가 아니다. 120초를 버티는 즉시 안전하게 만드는 생존 방식도 가능하지만, 그 경우 남은 싹의 성장 정지·제거·수확 단계 처리 규칙을 함께 결정해야 한다.

정리 단계에서 위험도에 쓰는 게임 시계는 생성 시간이 끝난 후에도 흘러야 한다. 설계 당시 `ElapsedSeconds`는 120초로 제한되고 `IsComplete` 이후 `Advance`가 중단되어 그대로 나이에 쓰면 성장이 멈추는 구조였다. 첫 시제품은 별도의 `SimulationSeconds`를 두어 이를 해결했다.

## 현재 코드에 연결하는 구조

### 싹의 정보

`BaobabSurge.SpawnRecord`에 종류 설정 참조와 실제 생성 시각 또는 생존 시간을 추가한다. 현재 `scheduledTime`은 생성 기회의 예정 시각이며, 실제 생성 시각과 같은 의미로 고정하지 않는다. 한 프레임에 생성 기회를 여러 개 처리할 때도 막 등장한 싹이 갑자기 오래된 상태로 계산되지 않게 한다.

### 위험도 관리

`BaobabThreatMeter` 같은 별도 구성에서 다음을 담당하는 안을 추천한다.

- 활성 `SpawnRecord`만 대상으로 생존 시간과 기여도를 계산.
- 원래 위험량, 0~1 표시 비율, 현재 증가 속도 제공.
- 상태와 함께 100% 도달을 한 번만 판정.
- 시작·재시작 시 나이 기준, 위험도, 종료 이벤트 초기화.

현재 최대 6개이고 예시 확장도 수십 개 수준이므로 우선 매 프레임 합산한다. 별도 스레드나 복잡한 공간 탐색부터 도입하지 않는다. 각 싹의 종류 설정에서 기여도를 구하므로 게임 오버 계산에 종류별 조건문을 추가할 필요가 없다. 기여도를 수학식으로 직접 계산하므로 프레임마다 증가량을 중복 적립하는 방식도 피할 수 있다.

실제 제거는 기존 `RemoveSprout` 경로를 활용한다. 같은 싹을 두 번 제거하거나 양이 중복 대상을 잡아도 기여도가 두 번 차감되지 않게 한다. 비활성화·파괴된 싹 역시 합계에서 제외한다.

### 종료 처리

행성 단계 상태를 한 곳에서 소유하고 게임 오버 진입을 한 번만 실행한다.

1. 종료 상태 확정.
2. 신규 생성, 성장, 양의 먹기·소환 등 게임 진행 정지.
3. 패배 연출과 결과 UI 표시.
4. 재시작 또는 꿈에서 깨어나는 후속 흐름 실행.

패배 연출·메뉴는 진행 정지 중에도 동작하도록 시간 기준을 구분한다. 모델의 변형·행성 파괴 효과는 패배 판정과 별도로 추가할 수 있다.

같은 시각에 먹기 완료와 임계 도달이 겹치는 경우에는 그 시각의 제거를 먼저 반영하고 합계를 판정하는 안을 제안한다. 서로 다른 MonoBehaviour의 임의 `Update` 순서에 결과가 달라지지 않게 한다. 큰 시간 간격을 처리하는 검증 코드에서는 생성·제거·임계 도달 시점을 나눠 처리해 중간 패배를 건너뛰지 않는다.

### HUD

- 현재 남은 시간을 나타내는 막대와 새 위험도 막대는 다른 값이다. 시간 숫자와 위험도 표시를 분리한다.
- 실제 위험량으로 패배를 판정하고, 표시용 막대의 보간값으로 판정하지 않는다.
- 실제 판정이 100%가 되면 표시도 즉시 100%로 맞춘다. 평소의 시각적 보간 때문에 95%에서 패배한 것처럼 보이지 않게 한다.
- 예: 0~49% 안정, 50~79% 주의, 80~99% 위험. 구간과 색은 조절 가능한 제안이다.
- 오래된 싹을 크기·잎·뿌리 효과 등으로 구별할 수 있게 해 위험 게이지와 현장 우선순위를 연결한다.
- 지평선 말풍선에도 성장 단계 표시를 적용할 수 있다. 먹는 중인 싹의 말풍선을 숨기는 기존 규칙과 함께 검토한다.

## 조절 항목과 최소 검증

설정값: 행성 프로필의 고정 한계량·생성 규모·종류 구성, 종류별 시작 기여도·선형 성장 계수·가속 성장 계수·개별 상한·먹기 작업량.

행성 크기를 반영할 때 생성 수와 한계량을 함께 검토한다. 현재 활성 상한 6개·개별 상한 25에서 한계량만 150 초과로 올리면 게임 오버에 도달할 수 없다. 논리 구역 수는 위험도 계산에 직접 쓰지 않는다.

- 활성 싹 0개면 0%, 과거 제거한 싹은 합산하지 않음.
- 싹 하나는 상한을 넘지 않음. 나이 증가가 상한 전 성장 속도를 높임.
- 위 예시의 65%와 제거 후 49%가 일치.
- 100% 임계 판정과 종료 이벤트가 정확히 한 번 발생.
- 양이 먹는 10초 동안 성장하고, 완료 순간 해당 기여도만 제거.
- 생성 종료 후의 성장·정리 동작이 선택한 규칙과 일치.
- 일시정지·재시작·동일 시각 이벤트·낮은 프레임 속도에서 중복 성장이나 판정 누락이 없음.
- 소형·중형·대형 및 혼합 종류 프로필에서 고정 한계량 정규화, 묶음 생성 상한, 종별 상한과 배치 실패 처리가 일치.
- 새 종류를 설정 에셋으로 추가해도 합산·제거·게임 오버 판정의 코드를 바꾸지 않음.

최초 설계 단계에서는 수식 예시만 계산으로 확인했다. 이후의 게임 오버·HUD·Unity 검증 결과와 미구현 범위는 문서 위의 첫 시제품 구현 절을 기준으로 한다.
