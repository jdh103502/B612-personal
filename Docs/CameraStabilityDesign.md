# 구형 행성 카메라 안정화 설계안

2026-10-30. 각진 지면에서 이동하거나 점프할 때 화면이 과도하게 움직인다는 사용자 피드백에 대한 기술 검토다. 현재 코드와 첨부 화면을 확인한 제안이며, 런타임 재현이나 프레임 기록으로 주원인을 확정하지는 않았다. 게임 코드와 씬 설정은 이 검토에서 변경하지 않았다.

## 관찰과 코드 근거

사용자가 제공한 화면에는 캐릭터 주변 지면과 착지 지점이 화면 아래에 적게 보이고 하늘이 크게 보인다. 한 장의 화면만으로 발생 직전의 회전 방향이나 충돌 보정 원인을 알 수는 없다.

현재 `Assets/B612/Scripts/OrbitCamera.cs`와 `AgentScripts/runtime/OrbitCamera.cs`는 다음 자동 동작을 포함한다. `B612_EmptyPlanet.unity`에도 아래 초기 설정이 저장되어 있다.

| 동작 | 현재 구현 | 확인할 영향 |
| --- | --- | --- |
| 카메라 위쪽 기준 | 접지 시 `target.Up`을 `anchorUp`으로 사용하고 `camUp`으로 완화 | 지면 법선 변화가 화면 회전으로 전달됨 |
| 접지·공중 전환 | `GravityWalker.Up`은 접지 시 바닥 법선, 공중에서는 중력 반대 방향을 따라감 | 카메라 기준은 공중에서 유지되지만, 시선 목표와 몸통 가림 검사에는 계속 변하는 `target.Up`이 사용됨 |
| 가림 회피 | `Place`에서 각도를 10도 간격으로 검사하고 최대 50도 추가 상승 | 작은 능선에서도 큰 각도 보정 목표가 선택될 수 있음. 모든 후보가 막히면 기본값인 최대 보정량이 남음 |
| 거리 보정 | 공중 시간이 0.3초를 넘으면 목표 거리에 1m 추가 | 보통 점프에도 줌 변화가 겹침 |
| 자동 좌우 회전 | 이동 속도로 자동 회전, 최대 초당 50도. 공중에서도 실행 | 모서리 이동·점프에 방향 보정이 겹칠 수 있음 |
| 높이 추적 | 공중 상승은 느리게, 하강은 빠르게 추적 | 일반 점프를 완전히 무시하는 구조는 아니며, 지형·충돌 보정과 함께 확인 필요 |

이미 `upSmoothTime = 0.45`, 높이 추적 완화, 공중에서의 `anchorUp` 유지, 장애물 해제 후 복귀 지연이 있다. 완화 시간만 늘리는 접근보다 카메라가 반응할 기준과 조건을 정리하는 편을 우선한다.

## 제안 1: 이동용 자세와 촬영용 기준 분리

캐릭터의 바닥 접촉과 몸의 자세는 기존 `GravityWalker`가 담당한다. 카메라는 별도의 안정적인 기준을 갖는다.

- 같은 행성에서는 지면 기준점과 행성 중심으로 구한 반지름 방향을 촬영 기준의 기본값으로 사용한다.
- 실제 지형의 개별 면 법선이 카메라 기준을 매번 바꾸지 않게 한다.
- 현재 행성은 위쪽이 평탄하게 눌린 형태이므로, 넓은 평지에서 순수 반지름 방향이 구도에 맞는지 함께 확인한다. 필요하면 구역의 안정적인 기준이나 넓게 평균한 지면 방향을 제한적으로 혼합한다.
- 일반 점프의 이륙·착지에서도 같은 기준을 이어간다. 월드 Y축 고정은 사용하지 않고 행성 곡률에 따른 방향 변화는 유지한다.
- 기준이 바뀔 때 기존 시선 방향을 함께 회전시켜 유지한다. 현재의 반복적인 평면 투영으로 인한 불필요한 방향 변화를 줄인다.
- 실제 행성 전환은 별도의 상태로 명시하고, 전환 중에만 새로운 기준을 부드럽게 받아들인다. 경계에서 잠깐 다른 중력원이 선택되었다고 즉시 전환하지 않는다.

## 제안 2: 보통 점프를 화면 안의 움직임으로 수용

- 지면을 따라 이동하는 추적 기준점과 캐릭터의 점프 높이를 분리한다.
- 화면에 수직 여유 영역을 두고, 일반 점프는 그 안에서 캐릭터가 움직이게 한다.
- 여유 영역을 벗어나거나 큰 낙하가 발생하면 높이 추적을 재개한다. 높은 위치에 착지했을 때도 새 지면 높이를 받아들인다.
- 같은 행성에서 하는 보통 점프에는 자동 거리 증가와 FOV 변화를 기본적으로 적용하지 않는다.
- 자동 좌우 회전과 이동 예측에는 지면을 따라가는 이동을 사용한다. 공중 속도가 기울어진 카메라 평면에 투영되어 자동 회전 입력처럼 작용하지 않는지 확인한다.

화면의 여유 영역은 아래쪽 카드 UI가 가리는 공간을 고려해 정한다. 캐릭터와 착지 지점이 함께 보이는 것이 목표다.

## 제안 3: 물리 충돌과 잠깐의 시야 가림을 분리

카메라 자체가 지면이나 벽에 들어가는 일은 즉시 막는다. 캐릭터 일부가 작은 능선에 잠깐 가리는 일은 별도의 가림 판정으로 처리한다.

- 먼저 현재 시선 각도를 유지하면서 안전한 거리까지 접근하는 방식을 검토한다.
- 거리 조절로 해결되지 않는 지속적인 가림에 한해 작은 각도 보정을 추가한다. 큰 행성 곡률 때문에 필요한 보정은 허용하되, 작은 지형 요철마다 큰 각도를 선택하지 않게 한다.
- 일반 이동의 자동 각도 보정 상한은 우선 10~15도 정도로 낮춰 비교한다. 이는 검증용 제안이며 확정 수치가 아니다.
- 가림이 약 0.15~0.25초 지속된 뒤 구도 보정을 시작하는 방안을 비교한다. 실제 카메라 충돌 회피에는 이 지연을 적용하지 않는다.
- 가림 해소 후에는 여유 시간을 둔 다음 서서히 원래 거리·각도로 복귀한다. 기존 복귀 지연을 활용하되 반복 전환을 확인한다.
- 작은 싹·수집물·상호작용 영역은 카메라 충돌 대상으로 삼아야 하는지 레이어 단위로 구분한다.
- 실제 충돌을 피하는 최종 위치 검사와 시야 품질 보정은 분리한다. 단순히 `maxLift`를 낮추는 것만으로 충돌 안전성이 확보되지는 않는다.

## 적용 우선순위 제안

1. 현재 장면에서 지형 모서리를 왕복하고 제자리·전진 점프를 하며 회전·거리·가림 보정 값을 기록한다.
2. 자동 상승의 큰 변화와 일반 점프의 거리 증가를 각각 분리해 비교한다. 충돌 방지는 유지한다.
3. 촬영 기준을 `target.Up`에서 분리하고 평지·측면·밑면을 확인한다.
4. 점프 높이 여유 영역과 공중 자동 회전 제한을 조정한다.
5. 행성 전환·발사 별·수동 회전·줌을 확인하고 기본값을 확정한다.

로그에는 접지 여부, 행성 식별자, 지면 법선과 촬영 기준 사이의 각도, `lift`, 목표·실제 거리, 자동 좌우 회전량을 포함한다. 카메라의 월드 회전량만으로 흔들림을 판단하지 않고 행성 기준에 대한 상대 회전도 확인한다.

완료 기준은 제자리 점프에서 원치 않는 자동 회전·줌이 생기지 않고, 모서리를 왕복해도 구도가 반복해서 크게 바뀌지 않으며, 지면을 관통하지 않고 캐릭터와 착지 지점을 읽을 수 있는 것이다. 지형 충돌이나 플레이어 이동이 실제로 튀는 경우에는 해당 원인도 별도로 조사한다.

## 공식 문서에서 참고한 설계 개념

아래 개념은 현재 커스텀 카메라에도 적용할 수 있다. 이 제안이 Cinemachine 패키지 전환을 전제로 하는 것은 아니다.

- [Cinemachine Position Composer](https://docs.unity3d.com/Packages/com.unity.cinemachine@3.1/manual/CinemachinePositionComposer.html): 화면 내 여유 영역과 축별 추적 완화. 이동 예측이 노이즈를 증폭할 수 있다는 설명.
- [Cinemachine Deoccluder](https://docs.unity3d.com/Packages/com.unity.cinemachine@3.1/manual/CinemachineDeoccluder.html): 가림 지속 시간, 장애물 대응 방식, 보정 및 복귀 완화의 분리.
