# 절차적 지형 2단계 구현·검증

> 아래는 2단계 당시 기록이다. 2026-11-11에 지역·얕은 강·3챕터 해금을 추가하고 생성기 4로 갱신했다. 현재 범위는 [3~4단계 기록](ProceduralTerrainStages34Results.md)을 따른다.

2026-11-10. `ProceduralTerrainTraversalDesign.md` 15절의 **2단계까지** 구현했다. 저주파 평지·언덕과 검수한 골짜기/높은 턱을 공통 행성 생성에 연결했다. 1단계 고정 실험실은 유지한다.

## 실행

- `Assets/B612/Scenes/B612_EmptyPlanet.unity`: 기존 크기 범위와 기본 반경 5.3m를 유지하며 새 저주파 지면을 생성한다. 작은 행성에는 고정 크기의 주요 요소를 억지로 넣지 않는다.
- `Assets/B612/Scenes/B612_ProceduralTerrainTest.unity`: 기준 반경 12m의 생성 실험실이다. 기존 바오밥·양·지도·F12 디버그를 그대로 사용할 수 있다. 고정 여정 seed는 `StarSystemFlow.runSeed=612101`이다.
- 다른 결과는 Edit 모드에서 `StarSystemFlow.runSeed`를 바꾸고 Play하거나 `randomizeRunSeed`를 켜 확인한다. 플레이 중 지형을 새로 추첨하는 입력은 추가하지 않았다.
- F12의 기존 체크박스로 기본/대쉬/추가 점프/전체 능력을 비교한다. 바오밥을 정리하고 이동 지형만 보려면 기존 스킵 버튼을 사용한다. 이후 닫고 M으로 다음 행성을 선택한다.
- Play 중 `ActivePlanetWorld`의 `ProceduralPlanetTerrain` Inspector는 seed·반경·요소 수·배치/메시 시도·검증 시간·제외 사유를 읽기 전용으로 표시한다. Scene Gizmos의 민트 선은 보호 통로/우회로, 금색 선은 지름길이다. 지형을 수정하거나 점유를 다시 만들지 않는다.

공통 설정은 `Assets/B612/Settings/PlanetTravel/EmptyPlanetGeneration.asset`, 실험실 설정은 `ProceduralTerrainTestGeneration.asset`이다. `proceduralTerrain`, `terrainFeatureBudget`(0~2), 기준 반경을 다음 여정부터 적용한다. 설정의 원본 groundTemplate 메시·재질을 직접 변형하지 않는다.

## 생성 순서와 고정 규칙

1. 행성 `spec.seed`, `terrain.radius`, 스폰 방향으로 별도 지형 난수 흐름을 만든다. 기존 크기·지면색 난수 흐름은 변경하지 않는다.
2. 3D 방향에서 연속 value noise를 저주파 두 층으로 표본화한다. 진폭은 `min(0.55m, 0.08×반경)`이다. 별도의 고주파 충돌 노이즈는 추가하지 않았다.
3. 스폰 안전 원과 스폰→반대편의 시험 목적지를 잇는 반구 통로를 예약한다. 통로 중심에서 1.25m 이내의 노이즈를 억제하고, 그 밖의 1.5m 구간에서 부드럽게 복원한다. 실제 NPC/퀘스트 목적지를 추가한 것은 아니다.
4. 1단계의 고정 폭/높이를 사용한 **골짜기+우회로**, **2m 턱+옆 경사로**를 1~2개 선택한다. 중심 위치와 접선 방향은 seed로 바뀐다. 각 요소에는 별도 평탄한 진입/도착 공간과 우회 경사를 유지한다. 활공 전용 계곡은 이번 무작위 풀에 넣지 않았다.
5. 요소별 최대 64개 후보만 시도한다. 스폰·기본 통로·다른 요소의 예약 영역과 겹치면 건너뛴다. 반경 8m 미만에는 주요 요소를 넣지 않고, 8~11m 미만은 최대 1개, 11m 이상은 최대 2개로 제한한다. 타일 개수에 비례해 수량을 늘리지 않는다. 작은 크기에서 요소를 축소하지 않는다.
6. 공유 정수 cube-sphere 정점으로 최종 방사형 지면을 만든다. 면 경계의 정점을 실제로 공유하며 단일 방향에는 기본 지면 하나만 둔다. 동일한 생성 메시를 MeshFilter와 MeshCollider에 연결한다. 지면 Transform은 위치/회전 0·배율 1로 두어 월드 높이를 다시 확대하지 않는다.
7. 최종 Collider를 독립 3D PhysicsScene에 연결해 현재 플레이어의 캡슐·보행/점프/능력 수치를 복사한 실제 모터로 검사한다. 기본 통로와 요소별 우회 왕복·골짜기 탈출을 보행만으로 확인한다. 또한 기본 점프 직진은 실패하고 대응 능력 직진은 성공해야 요소를 유지한다.
8. 요소 검사 실패는 해당 요소를 제거한다. 기본 통로 실패는 요소·노이즈를 없앤 안전 구면으로 대체한다. 최초를 포함한 메시 준비는 최대 4회이며, 안전 상태도 검증하지 못하면 목적지 준비를 실패시켜 기존 이동의 되돌리기 경로로 보낸다. seed·색·크기·방문 경로를 다시 추첨하지 않는다.
9. Collider와 변환을 확정한 뒤에만 `PlanetSurfaceGrid.Prepare`로 후보를 만든다. 지면 경사 30도 초과, 스폰 주변, 보호 통로, 요소의 예약 범위를 제외한다. 후보는 최종 지면의 실제 점·법선을 보관한다.
10. 준비 성공 뒤 기존 Flow가 플레이어 도착과 120초 바오밥 시계를 시작한다. 다음 행성에서는 새 런타임 메시·재질을 소유하고, 이전 행성 폐기/실패 때 소유 인스턴스를 해제한다.

생성기 버전은 **3**, 데이터 형식은 **1**, 지형 프로필은 **`terrain.lowFrequency.v1`**이다. 버전 2 입력은 새 생성 경로에서 거부한다. 저장 마이그레이션이나 지형 높이 저장 기능은 추가하지 않았다. 논리 격자 밀도 공식과 1배 80 / 1.5배 180 / 2배 320 구역은 유지한다.

검증용 이동 입력은 `PlayerTraversalAbilities.QueueSimulationInput`이라는 internal 경로로 독립 물리 씬에만 전달한다. 실제 플레이어의 공개 점프·대쉬 요청은 기존 시간 정지/모달 차단을 그대로 따른다. 따라서 지도/디버그 정지 상태에서도 다음 월드를 검수할 수 있고, 기존 pause 소유권을 해제하거나 실제 플레이 시계를 진행시키지 않는다. 이동 속도·점프·대쉬·활공의 수치와 자원 회복 규칙은 변경하지 않았다.

## 실행한 검증

Unity CLI `1.0.0-beta.17`, Unity `6000.3.23f1`의 열린 Editor에서 수행했다. Computer Use는 사용하지 않았다.

`AgentScripts/ProceduralTerrainStage2Validation.cs`로 기준 반경 12m에 0.7/1/1.5/2배, 여정 seed 612101/1/77의 **12개 조합**을 검사했다. 표의 시간은 이 환경에서 월드 준비 호출을 한 번씩 측정한 값이며 테스트 전체 실행 시간이나 프레임 성능 보장은 아니다.

| 배율 / 반경 | 유지한 요소 | 안전한 후보 수 | 준비 시간 범위 |
| --- | ---: | ---: | ---: |
| 0.7 / 8.4m | 골짜기 1개 | 2,059~2,134 | 약 452~460ms |
| 1 / 12m | 골짜기+턱 2개 | 1,964~1,981 | 약 974~1,143ms |
| 1.5 / 18m | 2개 | 5,152~5,161 | 약 1,869~1,904ms |
| 2 / 24m | 2개 | 9,627~9,671 | 약 3,150~3,367ms |

확인한 항목:

- 같은 seed의 메시 정점·삼각형 SHA256과 후보 수 재현. 다른 seed의 위치/방향·형상 해시는 달랐다.
- 각 크기의 공유 정점/삼각형 수 공식과 양수 반경·정상 법선. 1배의 모든 메시 변에 삼각형이 정확히 2개씩 연결됐고 Euler 값이 2였다. 면 이음선에 열린 변이 없었다.
- 표시/충돌 메시 참조 일치와 지면 배율 1. 모든 후보의 예약 영역 제외와 실제 Collider 재투영을 확인했다. 위치 차이는 0.005m 이내, 인접 면 경계의 법선 차이는 2도 이내를 사용했다.
- 최대 128회 배치 시도, 최대 4회 메시 준비 상한. 정상 12개 조합은 최초 메시 준비로 통과했다.
- 기본 이동만으로 보호 통로·우회 왕복·탈출을 통과하고, 기본 점프/대응 능력의 구분이 유지된 요소만 채택했다. 복귀 경사를 포함한 최대 관측 기울기는 약 39.3도로 기존 60도 모터 한계 이내였다. 보행 검사에서는 이륙/추가 점프를 요청하지 않는다.
- 다른 월드를 준비해도 활성 월드의 메시·슬롯 점유와 공유 원본 메시·재질 색은 유지됐다.
- 준비된 `PlanetWorldInstance.Prepare`를 다시 호출하면 새 지면을 만들기 전에 거부하며, 기존 데이터/메시와 Terrain 컴포넌트 하나가 유지되는 것을 확인했다.

실제 게임의 기준 반경 5.3m도 별도로 검사했다. 0.7배(3.71m)와 1배(5.3m)는 주요 요소 0개로 안전한 저주파 지형을 만들었고, 2배(10.6m)는 요소 1개를 유지했다. 후보는 각각 2,161 / 2,303 / 8,599개였다.

별도 검증용 캐릭터에서 대쉬/추가 점프의 속도를 0으로 둬 요소 검사가 실패하도록 만들었다. 2개 요소를 제거해 **3회의 메시 준비** 안에서 안전한 보행 지형과 후보 2,560개를 만들었다. 실제 플레이어 설정은 바꾸지 않았다. 평지 대체 후에도 실패하는 최종 거부 경로를 실제 Player 빌드에서 주입 검사한 것은 아니다.

`AgentScripts/ProceduralTerrainStage2SceneValidation.cs`는 실제 Play 프레임에서 다음을 확인했다.

- F12 능력 체크 변경·선택/Gizmos·읽기 전용 Inspector와 바오밥 스킵 중 메시/셀/슬롯 참조 유지.
- 잘못된 목적지 규격의 준비 실패 후 현재 행성·메시와 지도 상태 복구.
- **시간이 정지된 지도에서 실제 다음 행성 준비와 이동 성공**, 이전 런타임 메시 해제, 고정된 목적지 데이터 적용.
- 기존 양 카드/claims 정리, 새 행성의 스킵 표식 초기화·120초/동시 6개 유지, 실제 바오밥의 안전 후보 사용, 최종 지면 착지와 EventSystem 한 개.

원시 결과는 `Temp/TerrainStage2/Scale0.json`~`Scale3.json`, `MainSized.json`, `Repairs.json`, `Live.txt`다. 생성된 골짜기의 Game view는 CLI로 확인했고 `GeneratedValley.png`에 캡처했다.

새 Player 빌드·전체 이전 회귀·다양한 기기 성능 검사는 수행하지 않았다. 현 단계는 준비 시 동기 메시 생성과 실제 물리 검수를 사용하므로 큰 행성에서는 위 표처럼 전환 대기 비용이 있다. 3단계의 지역 가중치/확장·물길 연결, 4단계의 챕터와 정식 해금은 구현하지 않았다. 강/물·동굴·오버행·다층 다리도 추가하지 않았다.

## 변경 파일

- `ProceduralPlanetTerrain`: seed 계획·연속 높이·요소 배치/예약·메시 소유와 유한 보완.
- `TerrainTraversalVerifier`: 최종 Collider의 실제 기본/능력 모터 검사.
- `PlanetWorldInstance` / `PlanetGenerationSettings`: 공통 월드 준비 순서와 프로필 연결.
- `PlanetSurfaceGrid.CandidateFilter`: 최종 지면 위의 안전 후보 필터. Gizmos의 준비 상태와 분리했다.
- `ProceduralPlanetTerrainEditor`: 생성 결과의 읽기 전용 Inspector.
- `AgentScripts/ProceduralTerrainStage2Builder.cs`: 공통 설정 활성화와 별도 생성 실험실 구성. 전체 씬 빌더는 사용하지 않았다.

변경한 런타임 C# 소스는 `AgentScripts/runtime` 사본에 동기화한다. 1단계 `B612_TraversalTest`의 고정 메시·조작·측정 경로는 변경하지 않았다.
