# 개발자 디버그: 바오밥 페이즈 스킵 구현 명세

2026-11-09. 최초에는 다른 구현 chat에 전달하기 위한 문서로 작성했으며, 이후 사용자 요청으로 아래 기본안을 구현했다. 기본 디버그는 `DeveloperDebugModeSpec.md`, 지도·이동은 `StarSystemMapTravelImplementationSpec.md`, 행성 상태는 `PlanetDataModel.md`를 따른다. 본문의 원래 제안·수용 조건과 아래 실제 검증 결과를 구분한다.

## 구현 결과 (2026-11-09)

- 기존 F12 uGUI 패널에 1회 실행 버튼과 독립 결과 문구를 추가했다. 기존 세 Toggle·닫기와 Canvas/EventSystem을 유지하고, 패널 높이·행 간격만 조정했다. 기존 정적 TMP 아틀라스에 필요한 한글을 추가했다.
- `DeveloperDebugController` → `StarSystemFlowController.RequestDebugSkipBaobab`은 요청자·항성계 ID·행성 ID·활성 월드 참조를 고정해 한 번만 큐에 넣는다. 닫기/비활성화/대상 변경 시 취소한다. 실제 적용은 Threat의 `LateUpdate(50)` 이후 Flow의 `LateUpdate(300)`에서 재검증하고, 게임오버가 우선한다. Editor/Development 가용성은 요청·내부 완료 경로 양쪽에서 검사한다.
- `BaobabSurge.CompleteForDebug`는 시간을 진행시키지 않고 완료 시간만 설정한다. 모든 단계의 레코드를 released로 만들고 슬롯과 인스턴스를 정리하되 실제 생성 기록·통계를 보존한다. 완료 후에도 활성 실행 조회와 위협 평가가 가능하며 재생성하지 않는다.
- 양 일괄 회수는 이동과 공통 경로를 사용한다. 스킵에서는 선택 카드와 현재 지면의 숨긴 프리뷰를 유지한다. `LambAgent.RetireForRecall`로 타깃·먹기 진행·범위 표시를 즉시 해제하고 Collected로 확정해 파괴 콜백의 중복 반환을 막는다.
- 위험도를 실제 잔여량으로 재평가해 Resolved로 갱신하고, 같은 프레임의 스냅샷에 `SurgeProgress.skippedByDebug`를 남긴다. 기존 해금 알림·도착 노드 완료 경로를 재사용한다. 자동 지도 열기/이동이나 pause 해제는 없다. 타이머 HUD에는 `00:00`, `ACTIVE 0`, 실제 TOTAL과 `SKIPPED (DEBUG)`를 표시한다.
- 다음 `Begin`에서 표식은 false로 초기화된다. 이전 행성의 출발 기록에는 true를 유지한다. 격자 준비·행성 교체·플레이어 이동 자원 변경은 스킵 경로에 없다. 변경 런타임 소스는 `AgentScripts/runtime`에 동기화했다.

### 최소 검증 결과

사용자 요청에 따라 새 기능에 필요한 Editor 컴파일과 짧은 실제 Play 검사만 실행했다. Unity CLI `1.0.0-beta.17`, Unity `6000.3.23f1`에서 `AgentScripts/DeveloperBaobabSkipValidation.cs`를 실행했고 `Temp/DeveloperBaobabSkipValidation.txt`의 `passed=True`를 확인했다.

- 닫힌 패널의 요청 거부, 중복 요청 거부, 처리 전 닫기의 취소와 0.6배 실행 속도 복원.
- 세 성장 단계와 먹는 양·회수 아이템 양이 있는 상태에서 시간 0으로 실행: 바오밥/점유/claims/위험도/증가율 정리, 같은 카드·선택 유지, 지연 파괴 후 중복 회수 없음.
- 시뮬레이션 시계·네 가지 생성 통계·격자 셀/슬롯 참조·플레이어 위치/속도·카메라 위치·이동 자원 유지. 완료 스냅샷·타이머·결과 문구와 비활성 버튼의 선택 해제 확인.
- 닫기/재열기 후 표식 유지와 기존 지도 이동 경로 연결. 다음 행성은 120초·표식 false로 시작하고 이전 출발 기록은 유지.
- 자연 생성 종료 후 잔여만 정리해도 해금 알림 중복 없음.
- 실제 같은 프레임의 위협 100%와 스킵 요청에서는 게임오버가 우선. 패배 뒤 버튼과 요청 거부, 디버그 닫기 후 GameOver 정지 유지.
- 기존 EventSystem 한 개와 추가 문구의 정적 폰트 글리프 포함 확인.
- 기존 Game view에서 버튼과 게임오버 비활성 설명을 한 번 렌더링해 겹침·잘림 없이 표시되는 것을 확인했다. 캡처는 `Temp/DeveloperBaobabSkipUI.png`이며 여러 화면 비율의 별도 순회는 하지 않았다.

전체 이동/생성 회귀, 실제 Development/Release Player 빌드, 모든 수용 조건의 별도 순회는 실행하지 않았다. 초기 Unity 내부 빌드 백엔드 오류는 스크립트 컴파일 캐시 재생성으로 복구했고 최종 컴파일은 오류 없이 완료됐다.

## 1. 요구와 제안 기본안

사용자가 정한 요구는 **기존 F12 디버그 모드에 바오밥 페이즈를 스킵하는 기능을 추가**하는 것이다. 아래는 최초 인계 시 제안한 기본안이며 후속 구현에서 적용했다.

아래 동작은 바로 구현할 수 있도록 구체화한 **제안 기본안**이다.

- 기존 디버그 패널에 **[바오밥 페이즈 스킵] 버튼** 하나를 추가한다. 지속 설정이 아닌 1회 실행 명령이므로 체크박스를 사용하지 않는다.
- 현재 행성의 신규 바오밥 생성을 종료하고, 이미 생성된 바오밥을 성장 단계와 종류에 관계없이 모두 정리한다.
- 배치한 양은 같은 카드로 회수하고, 위험도는 남은 바오밥이 없는 상태에서 다시 계산해 0으로 만든다.
- 현재 행성의 생성 종료 조건을 충족시켜 기존 지도 해금 경로로 연결한다.
- 스킵 후에도 디버그 패널과 일시정지는 유지한다. 사용자가 F12/닫기로 돌아간 뒤 M으로 지도를 연다.
- 게임 오버가 확정된 상태에서는 실행할 수 없다.
- 다른 행성에 자동 적용하지 않는다. 다음 행성에서는 원래 바오밥 페이즈가 시작된다.

여기서 스킵은 **생성 중단 + 잔여 위협 정리**를 뜻한다. 생성 시간만 종료하고 잔여 바오밥을 남기는 별도 버튼은 이번 범위에 넣지 않는다. 다음 행성으로 자동 이동하거나 수확·퀘스트·양털 조건을 완료하는 기능도 아니다.

## 2. 현재 구현에서 확인한 연결 지점

| 코드 | 현재 동작 | 스킵에서 필요한 처리 |
| --- | --- | --- |
| `DeveloperDebugController` | Editor/Development에서 F12, 디버그 모달·pause 소유 | 기존 사용 가능 범위·정지 상태 안에서 명령 요청 |
| `DeveloperDebugHUD` | uGUI Toggle 3개, 닫기, 상태 문구 | 독립 Button과 실행 결과 문구 추가 |
| `GameplayModalInput` | 디버그/지도 중 하나만 열고 게임 입력 차단 | 스킵 중에도 디버그 소유권 유지 |
| `BaobabSurge.Advance` | 시뮬레이션 시간 증가, 생성 기회 처리, 성장 갱신 | 남은 시간을 한 번에 진행시키는 방식으로 스킵하지 않음 |
| `BaobabSurge.StopAndClear` | `ready=false`, 개체 기록·생성 루트 정리 | 이 호출만으로 종료 처리하지 않음 |
| `BaobabSurge.IsComplete` | 생성 종료 여부 | 스킵 성공 때 true로 확정 |
| `BaobabThreatMeter` | `LateUpdate` 순서 50에서 패배 판정, 실행 중인 Surge만 평가 | 기존 패배 확정을 우선하고 정리 뒤 위험도 재계산 |
| `StarSystemFlowController` | `LateUpdate` 순서 300에서 상태 기록·지도 해금 | 스킵 요청을 패배 판정 뒤, 상태 기록·해금 전에 처리 |
| `LambCardHand.RecallForTravel` | 카드 회수·claims 정리·프리뷰 제거, 선택 인덱스 초기화 | 같은 카드 반환 경로를 재사용하되 스킵에 맞는 선택/프리뷰 처리 |
| `SurgeTimerHUD` | 남은 시간·ACTIVE·TOTAL과 위협 상태 표시 | 스킵 직후 00:00, ACTIVE 0, 스킵 여부 표시 |

이 표는 수정 전 연결 지점을 설명한다. 후속 구현에서 추가한 API와 필드는 위 구현 결과를 따른다.

## 3. 최소 화면과 버튼 상태

기존 uGUI 패널에 기능 행만 추가한다. 새 Canvas·EventSystem을 만들거나 기존 세 체크박스를 재구성하지 않는다.

```text
개발자 디버그                              일시정지 중

[✓] 대쉬 사용
[✓] 더블점프 사용
[✓] 활공 사용

바오밥 페이즈
[바오밥 페이즈 스킵]
현재 행성의 바오밥을 정리하고 지도 진행을 해금합니다.

F12로 닫기
[닫기 · 계속하기]
```

성공 후:

```text
[스킵 완료]                              비활성 버튼
바오밥 페이즈를 스킵했습니다. 닫은 뒤 M으로 지도를 여세요.
```

- 같은 행성에서 패널을 다시 열어도 실행 결과를 표시한다. 다음 행성에서는 새 페이즈 상태에 맞춰 버튼을 갱신한다.
- 기존 `statusLabel`의 기술 구성 누락/일시정지 상태와 실행 결과가 덮어쓰기 경쟁을 하지 않도록 바오밥 전용 설명·결과 텍스트를 둔다.
- 기존 TMP 폰트는 디버그용 글자만 구운 정적 아틀라스다. 추가 한글·문장부호를 포함하고, 실제 빌드에서도 누락이 없는지 확인한다.
- 버튼 비활성화 시 포커스가 잘못 남아 Enter/패드 제출이 반복 실행되지 않도록 선택 상태를 정리한다. 닫기와 기존 Toggle은 계속 사용할 수 있다.
- 첫 구현에는 별도 단축키·확인 팝업을 추가하지 않는다. F12로 연 개발자 화면 안에서 실행한다.

| 현재 상태 | 스킵 버튼 | 설명 |
| --- | --- | --- |
| 생성 중 `Surging` | 활성 | 생성 중단과 잔여 정리 가능 |
| 생성 종료·잔여 있음 `Clearing` | 활성 | 남은 위협을 정리할 수 있음 |
| 자연 종료·잔여 없음 `Resolved` | 비활성 | 이미 종료된 페이즈 |
| 이 행성을 디버그로 스킵함 | 비활성 | 스킵 완료 |
| 요청 처리 대기 | 비활성 | 처리 중 |
| 게임 오버 | 비활성 | 게임 오버 상태에서는 사용할 수 없음 |
| 월드 준비 중·이동 중 | 비활성 | 현재 행성 준비 또는 이동 중 |
| 필수 참조 없음 | 비활성 | 현재 씬에서는 사용할 수 없음 |

다음 조건은 UI와 실제 명령 처리 양쪽에서 검사한다.

```text
CanRequestSkip = Editor 또는 Development Build
                 && 디버그 화면이 열려 있음
                 && 현재 행성이 준비됨
                 && Surge가 실행 중임
                 && 게임 오버가 아님
                 && 이동/지도 표시 중이 아님
                 && 스킵 요청 대기가 없음
                 && 이 실행에서 디버그 스킵을 적용하지 않았음
                 && (!IsComplete || ActiveSproutCount > 0)
```

이동 기술 컴포넌트 유무와 바오밥 명령의 가용성은 각각 판단한다. 기술 Toggle이 비활성이라는 이유만으로 모든 디버그 기능을 끄지 않는다. 다만 현재 행성·Surge·Threat·손패 등 정리에 필요한 참조가 빠졌다면 스킵은 시작하지 않는다.

## 4. 성공 후의 상태 계약

| 항목 | 스킵 성공 후 |
| --- | --- |
| `surge.IsComplete` | true |
| `surge.ElapsedSeconds` | 기존 `durationSeconds`와 같음 |
| 남은 생성 시간 | 0, HUD는 00:00 |
| 활성 바오밥 | 0, 모든 단계·종류 포함 |
| 앞으로의 생성 기회 | 취소. 닫은 뒤에도 재개되지 않음 |
| `surge.SimulationSeconds` | 스킵 직전 값 유지 |
| 기존 생성/시도/누락/상한 집계 | 실제 기록 유지 |
| 위험도·증가율 | 실제 잔여량 재계산 결과 0 |
| `BaobabThreatMeter.State` | `Resolved` |
| 배치 양·회수 대기 양 | 같은 카드로 반환, 타깃 점유 해제 |
| `state.surge.result` | `Resolved`와 디버그 스킵 표식 |
| 플레이어·카메라·행성·방문 경로 | 현재 상태 유지 |
| 디버그·게임 시간 | 화면 유지, 기존 정지 소유권 유지 |

`ElapsedSeconds`는 생성 카운트다운의 완료 위치를 표시한다. 실제 플레이한 시간이 duration만큼 지난 것으로 기록하지 않는다. `SimulationSeconds`를 증가시키거나 양 수명·먹기 진행·기술 쿨다운을 진행시키지 않는다.

현재 행성의 `PlanetPhase`와 위협의 `Phase`는 서로 다른 enum이다. 지도 시제품은 생성 종료 후 행성 상태를 `Clearing`으로 기록하고 `surge.result`로 잔여 정리 여부를 구분하므로, 이 규칙을 우선 유지한다. 스킵만을 위해 `Harvest`·`Quest`·`ReadyToLeave`로 강제 이동하지 않는다. 향후 정식 페이즈 관리자를 추가하면 그 관리자의 완료 경로에 스킵 사유를 전달한다.

### 실제 생성 기록을 보존한다

- `Attempts`, `SpawnedCount`, `SkippedSpawns`, `CapacityBlockedSpawns`를 목표 수량으로 채우거나 0으로 지우지 않는다.
- 아직 실행하지 않은 기회는 디버그 취소이며, 위치 부족이나 동시 상한으로 실패한 기회가 아니다.
- 기존 `Spawned` 기록은 남기고 정리한 레코드는 released/비활성으로 처리하는 안을 권장한다. 그러면 TOTAL은 스킵 전까지 실제 생성한 수를 유지할 수 있다.
- 향후 별도 진단 수치가 필요하면 취소한 생성 기회를 따로 기록한다. 이번 버튼을 위해 모든 통계 구조를 확장할 필요는 없다.

## 5. 요청 처리 순서와 게임 오버 우선순위

버튼의 `onClick`에서 월드를 즉시 지우지 않는다. UI는 요청만 기록하고 **기존 패배 판정이 끝난 뒤** 처리한다.

권장 흐름:

```text
UI onClick
  사용 가능 조건 검사
  현재 systemId / planetId / 활성 월드 인스턴스를 묶어 요청 기록
  버튼을 처리 중 상태로 표시

같은 프레임의 ThreatMeter.LateUpdate (현재 순서 50)
  기존 양 제거·성장 결과로 게임 오버 최종 판정

FlowController.LateUpdate (현재 순서 300)
  월드 준비 상태 확인
  게임 오버이면 스킵 요청 폐기, 기존 패배 처리
  아니면 요청 대상·디버그 열림·참조를 다시 검증
  스킵을 한 번 적용
  SnapshotCurrent
  기존 생성 종료 알림 / 항성계 완료 표시 처리
```

- UI 활성화 뒤 조건이 달라질 수 있으므로 실행 직전에 다시 검사한다.
- 대기 요청의 행성 ID와 활성 월드가 현재 것과 다르면 취소한다. 오래된 요청이 다음 행성을 지우면 안 된다.
- 더블클릭·연속 Submit은 하나의 요청으로 합치고, 적용 후 재실행은 아무 상태도 바꾸지 않는다.
- 요청 대기 중 F12/닫기·컨트롤러 비활성화·씬 재시작이 발생하면 미적용 요청을 취소한다. 이미 적용한 스킵은 창을 닫는다고 되돌리지 않는다.
- 스킵 요청과 100% 패배가 겹치면 **게임 오버가 우선**이다. 위험도를 낮추거나 GameOver pause를 해제해 부활시키지 않는다.
- 디버그의 `timeScale=0`에서도 Update/LateUpdate와 UI 명령 처리로 완료할 수 있게 한다. 완료를 기다리며 `WaitForSeconds`·다음 물리 틱·게임 시간 진행에 의존하지 않는다.

현재 Flow는 `SnapshotCurrent(false)`를 먼저 호출한다. 구현 시 스킵 적용 뒤 같은 프레임의 스냅샷·해금이 갱신되도록 순서를 정리한다. 기존 패배 판정을 앞당기거나 정상 플레이 프레임 순서를 바꾸지 않는다.

## 6. 실제 정리 동작의 권장 절차

명령 진입점 예: `StarSystemFlowController.RequestDebugSkipBaobab(...)`. Surge 내부 적용 예: `BaobabSurge.CompleteForDebug()`. 이름은 제안이며, UI가 시간·게이지·씬을 직접 수정하지 않도록 책임을 나누는 것이 핵심이다.

1. 필수 참조·현재 요청 대상·패배 여부를 검증한다. 검증이 끝나기 전에 개체를 제거하지 않는다.
2. 신규 생성이 더 실행되지 않도록 완료 상태를 먼저 확정하고 카운트다운을 종료 위치로 둔다.
3. 배치·회수 대기 양을 같은 카드로 반환한다. 먹기 대상 claim과 `FeedingLamb` 연결을 해제한다.
4. 모든 활성 바오밥 레코드의 slot 점유를 반환하고 released로 표시한다. 루트 인스턴스를 즉시 비활성화한 뒤 정리한다. 성장 단계별 Visual만 삭제해 논리 개체가 남지 않게 한다.
5. 프리뷰·먹기 범위·지평선 말풍선 등 정리된 대상의 표시를 갱신한다. 기존 레코드 참조가 해제된 대상을 다시 잡지 않게 한다.
6. `WasSkippedByDebug = true`를 기록한다. 시뮬레이션 시계·생성 집계·원본 설정·격자 해상도는 유지한다.
7. 위협을 재계산한다. 이 명시적인 월드 변경 뒤 `Evaluate()`를 한 번 호출해 RawThreat/증가율/State를 갱신할 수 있다. 정상 플레이의 패배 판정은 앞에서 이미 끝났고, 패배 확정 상태는 여기로 진입하지 않는다.
8. 행성 스냅샷·HUD·디버그 버튼 상태를 갱신하고 요청을 해제한다. 외부 갱신 이벤트는 가능한 한 정리가 끝난 일관된 상태에서 전달한다.

### 기존 메서드를 그대로 조합할 때의 주의점

- **`Advance(남은 시간)` 금지:** 남은 생성 이벤트를 몰아서 실행하고 바오밥 나이·위험도·성장 단계까지 뛰어넘을 수 있다.
- **`durationSeconds`를 작게 바꾸는 방식 금지:** 원본 규칙을 바꾸고 다음 실행까지 영향을 줄 수 있다.
- **`StopAndClear()`만 호출하는 방식 금지:** `IsComplete`가 완료되지 않고 `IsRunning`이 false가 되어 Threat 평가도 멈출 수 있다. 지도와 HUD가 이전 상태에 남는다.
- **`ResetForRun()/Begin()` 재호출 금지:** 실행을 새로 시작하거나 첫 싹을 다시 생성하고 집계를 지울 수 있다.
- **위험도 숫자만 0으로 변경 금지:** 살아 있는 바오밥에서 다음 평가 시 다시 위험도가 생긴다.
- **격자 `Prepare/BuildCells` 재호출 금지:** 같은 행성의 슬롯·점유·ID를 새로 만들 필요가 없다.

전용 완료 경로는 기존 `ready` 계약을 고려한다. 현재 Threat는 `IsRunning`이 false면 평가하지 않으므로, 생성은 끝났어도 완료된 활성 행성의 상태를 조회·평가할 수 있게 한다. 단순히 컴포넌트를 비활성화해 완료를 표현하지 않는다.

### 양 회수의 범위

기존 `RecallForTravel()`의 소유권 검사·타깃 해제 로직을 공통 회수 경로로 추출하는 안이 적합하다.

- 새 카드를 지급하거나 `startingCards`로 손패를 초기화하지 않는다. 기존 카드 인덱스/향후 양 ID를 유지한다.
- `LambAgent.OnDestroy()`도 `RecoverCard()`를 호출하므로 중복 반환이 없어야 한다. 회수 대기 개체와 이미 회수한 개체도 포함해 점검한다.
- 스킵 정리를 '양이 먹기 완료'한 것으로 처리해 `SproutsEaten`·재화·업적을 증가시키지 않는다.
- 이번에는 행성을 떠나는 것이 아니므로 가능한 한 기존 선택 카드 인덱스를 유지한다. 프리뷰를 제거했다면 현 행성 기준으로 다시 준비하되 모달 중에는 표시하지 않는다.
- 미래의 양 특성·강화·작물 휴식 상태를 스킵 때문에 지우지 않는다.

## 7. 지도 해금·정지·결과 기록

### 지도와 정지

- 기존 Flow가 `IsComplete`로 지도 해금과 1회 알림을 처리하도록 연결한다. 별도 `debugMapUnlocked` 플래그를 만들어 지도 규칙을 우회하지 않는다.
- 이미 자연 생성 종료로 알림을 보인 행성에서 잔여만 스킵해도 해금 알림 수를 다시 늘리지 않는다.
- 디버그가 열린 동안은 기존 `CanOpenMap`이 false인 것이 정상이다. **완료 조건 충족**과 **지금 지도를 열 수 있음**을 구분한다.
- 성공 문구는 디버그 패널 안에 유지해 기존 HUD의 unscaled 알림이 먼저 사라져도 닫은 뒤 M을 사용할 수 있음을 알린다.
- 스킵은 `OpenMap/RequestMap/BeginTransition`을 자동 호출하지 않는다. 마지막 도착 노드에서는 기존 테스트 항성계 완료 표시만 반영한다.
- 디버그의 pause 소유권·커서·입력 차단은 유지한다. 스킵 때문에 `ReleasePause`, `ResetForSceneReload`, `Time.timeScale=1`을 호출하지 않는다.
- 닫을 때 기존 실행 속도·다른 pause 소유권·게임 오버 정지를 그대로 따른다. 클릭/키 입력이 게임 동작으로 이어지지 않게 기존 모달 경계를 유지한다.
- 플레이어 위치·속도·대쉬 시간·점프 횟수·활공 예산·허용 Toggle은 스킵으로 변경하지 않는다. Teleport/리스폰도 호출하지 않는다.

### 최소 결과 표식 제안

```text
BaobabSurge
  WasSkippedByDebug : bool, 실행 중 읽기 전용 조회

SurgeProgress (PlanetData.state.surge)
  skippedByDebug : bool, 기본 false
```

- 신규 행성 `Begin()`에서는 false, 스킵 성공 시 true다. 다음 `SnapshotCurrent`와 출발 기록에서도 같은 값을 유지한다.
- 자연 시간 종료·자연 제거는 false다. `SurgeResult.Resolved`와 함께 조회하면 자연 해결과 디버그 정리를 구분할 수 있다.
- `SnapshotCurrent`가 매 프레임 result를 다시 계산하므로 `result`에만 임시 문자열을 넣거나 UI에만 성공 여부를 저장하지 않는다.
- R 리스폰·지도 재열기·디버그 재열기에서 현재 행성의 스킵 표식과 완료 상태를 유지한다.
- 다음 행성은 자체 false 상태로 시작한다. 이전 행성 표식과 여정의 경로 기록은 남긴다. 새 Play/패배 재시도는 기존대로 새 테스트 여정이다.
- 현재 게임에는 스킵 보상을 추가하지 않는다. 향후 자연 클리어 보상·업적을 연결하면 이 표식을 확인해 디버그 정리가 보상을 만들어내지 않게 한다. 정상 수확·퀘스트 상태를 소급 완료하지 않는다.
- 후속 구현에서 DTO에 이 필드를 추가했다. 기존 JSON 예시는 생략 필드의 기본값 false로 읽으며 저장/불러오기 기능을 새로 구현한 것은 아니다.

## 9. 수용 조건과 검증

| 검증 상황 | 기대 결과 |
| --- | --- |
| 시작 직후 F12 → 스킵 | 잔여 00:00, 활성 0, 위험도/증가율 0, 완료 표식 true |
| 생성 중 여러 바오밥과 먹는 양이 있는 상태 | 모든 단계 정리, 같은 카드 반환, 먹기 점유·표시 제거 |
| 생성 종료 후 잔여 바오밥만 있는 상태 | 잔여 정리, 기존 해금 알림 중복 없음 |
| 자연 종료·잔여 없음 | 버튼 비활성, 디버그 스킵으로 잘못 기록하지 않음 |
| 성공 뒤 닫기·기다리기 | 생성·위협 재발 없음, M으로 다음 행성 선택 가능 |
| 같은 행성에서 R·지도·디버그 재열기 | 스킵 상태 유지, 다시 바오밥 페이즈를 시작하지 않음 |
| 다음 행성 이동 | 기존 120초 페이즈 시작, 표식 false, 행성당 명령만 적용 |
| 도착 노드에서 스킵 | 테스트 항성계 완료 표시, 없는 다음 행성 생성 안 함 |
| 더블클릭·Enter/패드 반복 | 한 번 적용, 카드·알림·이벤트 중복 없음 |
| 요청 뒤 창 닫기·월드 변경·씬 재시작 | 미적용 요청 취소, 다른 행성에 적용되지 않음 |
| 게임 오버 후 디버그 열기 | 스킵 비활성, 닫아도 패배·정지 유지 |
| 같은 프레임 위험도 100%와 스킵 요청 | 기존 최종 판정 뒤 게임 오버가 우선, 스킵 없음 |
| 필요한 Surge/Threat/Flow/손패 참조 없음 | 설명과 비활성 버튼, 부분 정리·예외 없음 |
| 디버그 화면 반복 활성/비활성 | 콜백·구독 누적 없음, 닫기와 기존 세 Toggle 정상 |
| 0.6배 속도에서 디버그 실행 | 스킵 중 시간 0, 닫으면 다른 정지 없을 때 0.6으로 복원 |
| 공중 대쉬/활공 중 스킵 | 이동 상태·속도·자원 보존, 새 점프/대쉬 입력 재생 없음 |

추가로 확인할 항목:

- 스킵 전후 `SimulationSeconds`, 실제 생성·시도·누락·상한 집계가 같고 미실행 이벤트를 실제 생성으로 계산하지 않는다.
- 카드 총수·선택·양 특성 유지, `OnDestroy` 이후에도 중복 회수나 늦은 타깃 갱신이 없다.
- 스킵 후 다음 프레임·디버그 닫기·지도 열기에서도 상태 표식이 `SnapshotCurrent`로 지워지지 않는다.
- 서로 다른 크기/격자의 행성에서 슬롯 점유가 정상 반환되고 `Prepare`를 다시 호출하지 않는다.
- 일반 자연 종료·양 먹기·위험도 100%·지도 해금·패배 재시도의 기존 동작이 유지된다.
- 한글과 버튼이 기준 해상도/다른 화면 비율에서 정상 표시되고 EventSystem은 기존 하나다.
- Development와 일반 Release의 접근 범위를 검사한다. 실제 Player 빌드 검증을 하지 않았다면 Editor 검증과 구분해 기록한다.

위 표는 전체 수용 조건이다. 이번에 실제 실행한 최소 검증과 실행하지 않은 범위는 상단의 검증 결과를 따른다.

## 다른 구현 chat에 전달할 요청문

> `Docs/GameDesign.md`, `Docs/DeveloperDebugModeSpec.md`, `Docs/DeveloperBaobabSkipImplementationSpec.md`를 읽고 기존 F12 디버그 패널에 [바오밥 페이즈 스킵] 버튼을 추가해줘. 현재 행성의 생성과 잔여 바오밥을 시간 진행 없이 종료하고 양을 같은 카드로 회수해 위험도 0·기존 지도 해금 경로로 연결해줘. 디버그 창과 pause는 유지하고 자동 지도 열기/이동은 하지 마. 게임 오버가 우선이며 같은 명령은 한 번만 적용돼야 해. 실제 생성 기록과 이동 자원을 보존하고 디버그 스킵 표식이 상태 기록에서 유지되게 해줘. 기존 모달 입력·양 파괴 콜백·Surge의 실행 상태와 SnapshotCurrent를 확인하고, 런타임 사본·기존 UI·폰트 연결과 문서의 수용 조건까지 검증해줘.
