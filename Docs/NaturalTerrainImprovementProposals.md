# 자연 지형 후속 개선 제안

2026-11-21 작성. **제안이며 승인된 설계가 아니다.** 현재 구현은 생성기 버전 9(`terrain.natural.v1`, 등각 지면 메시)다. 결과는 [자연 지형 구현 결과](NaturalPlanetTerrainImplementationResults.md)를 따른다. 아래 A~C는 화면의 지형 형태를 바꾸므로 사용자 승인 뒤 구현하고 생성기 버전을 올린다. D~E는 결과를 바꾸지 않는 성능 작업이다.

## 현재 상태 요약

- 높이: 3D value noise 두 층(넓은 층 12m/1.4m, 중간 층 5m/0.3m, 반경 12m 미만은 `R/12` 비율로 축소)
- 강: 높은 지점 768개 중 수원 후보를 골라 16방향 중 가장 낮은 쪽으로 따라 내려가는 물길 하나. 양 끝은 지면 아래로 사라진다.
- 준비 비용(2배): 전체 약 0.61초 = 메시 생성 약 0.14초 + PhysX 쿠킹 약 0.18초 + 연결 분석 약 0.19초 + 후보 약 0.1초

## A. 기반 노이즈를 gradient noise로 교체

- **문제:** `ProceduralPlanetTerrain.Noise`는 격자값을 smoothstep으로 보간하는 value noise다. 격자점에서 기울기가 0이 되어 둥근 혹이 반복되고, 3D 격자의 축 방향 무늬가 구면에 드러날 수 있다.
- **제안:** 같은 크기·진폭 설정에서 3D simplex(또는 Perlin) gradient noise로 바꾼다. seed는 지금처럼 층마다 오프셋으로 분리한다. octave·ridge·warp는 추가하지 않는다(18.3절 원칙 유지).
- **주의:** 출력 분포가 달라진다(value noise는 0~1, gradient noise는 대략 −1~1이며 중앙에 몰린다). 높이 범위가 유지되도록 진폭 보정 계수를 정한다.
- **검증:** 기존 표본 기준(`(P90−P10)/q` 1.13~1.46m, 20개 구역 모두 `0.35×q` 이상), 연결 면적, `NaturalTerrainMeshValidation.Walk`, 같은 구도 화면 비교

## B. 지역별 거칠기 마스크

- **문제:** 중간 층(5m)이 행성 전체에 같은 진폭으로 깔려 있어서 어디를 가도 비슷하게 울퉁불퉁하다.
- **제안:** 매우 낮은 주파수(예: 크기 15~20m)의 마스크 노이즈로 중간 층 진폭을 0.35~1.0배로 조절한다. 평평한 초원과 거친 구역이 나뉜다. 넓은 층과 높이 예산 `min(2m, 0.17R)`는 바꾸지 않는다.
- **검증:** A와 같다. 추가로 마스크 하위·상위 영역의 경사 분포를 따로 보고한다.

## C. 흐름 누적 기반 강과 끝 연못

- **문제:** 현재 추적기는 국소 웅덩이에서 멈추기 쉽다(짧은 추적으로 기록된다). 수원과 끝이 경사 중간의 땅속으로 사라져 물의 시작과 끝이 읽히지 않는다.
- **제안:**
  1. 약 1m 간격의 구면 셀 그래프(배치 분석과 같은 `PlanetSurfaceGrid.CreateTopology`)에 높이장을 표본화한다.
  2. 웅덩이 채우기(priority-flood)로 각 셀의 흐름 방향과 누적 유량을 구한다.
  3. 누적 유량이 큰 경로 중 길이 8~18m(`q` 적용)를 만족하는 하나를 고른다.
  4. 끝이 웅덩이(sink)면 넘침 높이까지 채운 작은 연못을 둔다. 연못의 수심과 반경 상한을 둔다.
  5. 강바닥 깎기·강둑 전이·물 감속 규칙은 지금 것을 재사용한다. 실패하면 지금의 추적기로 돌아간다.
- **비용 추정:** 셀 수천~2만 개, `O(n log n)`이라 수 ms 수준이다.
- **결정 필요:** 연못이 걸어 들어갈 수 있는 얕은 물인지, 우회해야 하는 장애물인지. 연못 주변을 상호작용 지점·바오밥 후보에서 제외할 폭.
- **검증:** 강 생성률(지금 21/21과 24/24), 강 양방향 횡단과 연못 가장자리 보행, 연결 면적, 화면 비교

## D. 비동기 준비 (성능, 결과 동일)

- 현재 `StarSystemFlowController`는 행성 준비를 한 프레임에 동기로 실행한다. 2배 행성에서는 약 0.6초 동안 화면이 멈춘다.
- 메시 생성(이미 병렬)과 `Physics.BakeMesh`는 작업 스레드에서 돌릴 수 있다. 준비를 코루틴이나 비동기 작업으로 나누고 지도 이동 연출 중에 끝내면 멈춤을 숨길 수 있다.
- 배치 분석의 물리 조회는 메인 스레드에 남는다. `RaycastCommand` 일괄 처리로 Raycast 부분(약 절반)을 병렬화할 수 있다. 캡슐 침투 검사(`ComputePenetration`)는 일괄 API가 없어서 순차로 남는다.
- 실패 시 출발 행성·진행 상태를 유지하는 현재의 확정 규칙은 그대로 지킨다.

## E. 조각 단위 지면 메시 (성능)

- 지면을 cube 면당 여러 조각으로 나누고, 강이 지나는 조각만 0.18m로, 나머지는 0.35~0.4m로 만든다. 지형의 가장 작은 무늬가 5m라서 정점 수를 몇 분의 1로 줄일 수 있다.
- 조각 경계에서 해상도가 다르면 이음새를 처리해야 한다. 거친 쪽 정점에 맞추거나 스커트를 둔다.
- 조각마다 Renderer·Collider를 따로 두면 지평선 뒤 조각을 그리지 않을 수 있고, 쿠킹도 조각 단위로 병렬화된다.
- 렌더와 충돌이 같은 메시를 쓰는 현재 원칙은 유지한다.
