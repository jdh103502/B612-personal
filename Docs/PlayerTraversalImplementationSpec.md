# 플레이어 더블점프·대쉬·활공 구현 명세

2026-11-08. 최초 작성은 다른 chat으로 전달하기 위한 구현 명세였다. 이후 사용자의 구현 요청으로 아래 첫 구현을 연결하고 Unity 검증을 진행했다. 본문의 기본안 수치는 최종 밸런스를 뜻하지 않는다.

## 구현 결과 (2026-11-08)

후속 경사 결함 수정: `PlayerTraversalSlopeDiagnosis.md`의 분석에 따라 실제 지면 법선·지지체 상대 속도로 접지를 판단하고, 물리 이동 평면 `MovementUp`과 자세 보간 `Up`을 분리했다. 투영한 입력의 크기를 보존하고, 명시적인 점프 상승에만 짧은 점프 추가 중력을 적용한다. 점프 상승 및 이륙 직후에는 근처 바닥으로 재접지하지 않는다. 기존 지지에서만 작은 능선 반발(기본 0.5m/s)을 허용하며 가까운 실제 지지가 매 틱 필요하다. Animator/HUD의 접지 값을 따로 위장하지 않았다. 15·30·45도 9개 이동 조건·경사 기술 조합·이동 발판·능선·실제 변형 메시·실제 씬 8초 이동 검사에서 접지 오판/공중 애니메이션 전환 없이 통과했다. 상세 수치와 한계는 원인 분석 문서의 후속 수정 절에 기록했다.

### 연결과 실제 동작

- Unity CLI `1.0.0-beta.17`에서 열린 Unity `6000.3.23f1` 에디터의 `ready` 상태와 실제 `eval` 응답을 먼저 확인했다. `B612_EmptyPlanet`의 Player에만 `PlayerTraversalAbilities`를 추가했고 전체 씬 빌더는 실행하지 않았다.
- `PlayerController`는 Space/양쪽 Shift/패드 South·Right Shoulder를 수집한다. Space 요청을 먼저 처리한 뒤 대쉬를 승인한다. 연속 유지와 새 누름을 구분하고 여러 장치의 점프 유지는 OR로 합친다. 입력 중단 후에는 유지 중이던 버튼을 한 번 해제해야 새 동작을 시작한다.
- 기술 상태·예산은 `PlayerTraversalAbilities`가 소유하고, 실제 물리 틱에서는 `GravityWalker`가 호출한다. 새 컴포넌트에는 자체 `FixedUpdate`가 없으며 최종 Rigidbody 속도 작성자는 기존 모터 하나다.
- 추가 점프는 중력 기준 수직 속도를 3m/s로 교체한다. 지면/코요테 점프의 `Jumped`와 추가 점프의 `AirJumped`를 분리했다. 착지 후 버퍼 점프는 착지 이벤트 뒤 점프 이벤트 순으로 처리해 기존 점프 표현을 유지한다.
- 대쉬는 정면 접선 방향을 고정해 시작하고 곡면의 Up 변화만 방향에 운반한다. 8m/s에서 마지막 0.06초간 3m/s까지 감속하는 0.18초 동작이다. 종료 다음 틱과 점프 취소 시 잔여 접선 속도를 3m/s 이하로 제한한다. 공중의 상승·낙하 성분은 별도로 유지하며 일반 중력을 계산한다.
- 캡슐 축·중심·회전·비균일 크기를 반영한 sweep와 시작 겹침 검사를 적용했다. 바닥에 닿은 캡슐이 0거리 겹침의 가짜 법선을 반환하는 문제를 확인해, skin만큼 작은 sweep와 법선 방향 보상으로 처리했다. 하나의 MeshCollider에 바닥과 벽이 함께 있어도 벽을 검사한다. Rigidbody의 ContinuousDynamic 및 PhysX 접촉은 유지한다.
- 활공은 0.20초 유지 후 하강 중에만 승인하며 총 2.5초를 실제 물리 사용 시간만큼 차감한다. 하강을 0.75m/s로 점진적으로 조절하고 최소 0.15m/s의 음수 하강 성분을 유지한다. 일반 중력과 활공 수직 처리를 중복 계산하지 않는다.
- 0.04초 연속 지지와 이륙 후 0.10초 차단을 사용한다. 대쉬 중 접촉은 착지 회복을 승인하지 않는다. 실제 착지는 점프·대쉬·활공 예산을 회복하지만 대쉬 쿨다운을 지우지 않는다. 지면 대쉬는 종료·쿨다운·안정적 지지 조건으로 다시 충전한다.
- 일시정지·입력 비활성화·포커스 상실·발사 별은 오래된 요청과 진행 중 동작을 취소하면서 이미 소모한 공중 자원을 보존한다. 게임 시간이 정지하면 타이머도 진행하지 않는다. 명시적인 `Teleport`/R 리스폰은 속도·입력·모드·쿨다운과 자원을 초기화한다.
- 실제 연계에서 높이 올라간 캐릭터가 상단 HUD에 가려지는 구도를 확인해, 확장 기술 중 카메라의 높이 여유를 0.2m·수직 추적률을 10으로 조절했다. 기존 일반 점프 설정과 별도이며 자동 거리 증가·FOV 효과·공중 자동 회전은 추가하지 않았다.

첫 조절값은 아래 11절 표와 같다. 플레이어의 일반 하강에만 중력 배율 1.6을 사용하며 여우의 기존 경로에는 적용하지 않는다. 생성·성장·카드 시스템의 규칙은 이 작업에서 변경하지 않았다.

`AgentScripts/PlayerTraversalValidation.cs`의 `Validate`는 실제 3D PhysicsScene·Rigidbody·Collider에 모터를 연결해 17개 검증 묶음을 통과했다.

- 유지 입력의 자동 더블점프 방지·하강 활공, 추가 점프 1회 제한, 코요테 안/밖, 짧은 점프와 긴 점프, 착지 버퍼의 한 번 소비.

- 벽 sweep, 시작 겹침, Trigger 통과, 천장의 가짜 착지 방지와 실제 착지의 한 번 회복·쿨다운 보존.
- 반경 3m 구의 위·옆·밑면 대쉬에서 초기 이격 0.02m를 포함한 최대 이격은 약 0.0277m였다.
- 물리 간격 0.01/0.02/약 0.0333초에서 대쉬 동작 시간은 0.18초였다. 종료를 관찰한 물리 틱까지의 실제 변위는 각각 약 1.285/1.281/1.333m였다. 마지막 틱에 대쉬 종료 후 이동이 포함될 수 있다.
- 가상 Dynamic 입력의 Update 스케줄을 30/60/120fps로 모의하고 0.02초 PhysX 틱과 연결했다. 각 조건에서 지면 점프 1회·추가 점프 1회·대쉬 요청 1회가 일치했다. 한 번의 입력 뒤 여러 물리 틱, 키보드 해제+패드 유지, 패드 Right Shoulder 대쉬, 포커스·일시정지·입력 비활성화도 확인했다.

`ValidateGeometryAndLegacy`는 바닥과 벽이 같은 MeshCollider인 경우 약 0.629m, 회전·비균일 크기 캡슐은 정면 변위 약 0.603m에서 벽을 통과하지 않고 멈추는 것을 확인했다. 보고한 캡슐 bounds는 실제 Collider bounds와 일치했다. 기술 컴포넌트가 없는 기존 모터의 점프·대쉬 요청 경로도 검사했다.

`AgentScripts/PlayerTraversalSceneValidation.cs`는 현재 씬에서 실제 프레임을 진행하며 가상 키보드로 기술을 연계했다. 일반 점프 1회·추가 점프 1회·대쉬·활공·착지 회복, 공중 소환 거부·지상 Q 소환, R 리스폰, Space+Shift의 실제 LaunchStar 우선 탑승과 도착 초기화, 100% 게임오버의 입력 취소·시간 정지를 확인했다. 이 검사에서는 생성·위험도 진행을 임시 제어하고 끝날 때 정상 플레이로 복원한다.

최종 구도 보정 뒤 이 연계 검사에서 머리 기준점의 최대 뷰포트 Y는 약 0.723으로 상단 HUD 아래였다. FOV는 42도로 유지됐고 자동 목표 거리 변화는 0이었다. Unity 컴파일 오류·경고는 0개였으며, CLI의 이전 Pipeline 명령 이름 호환 안내는 별도다.

검증 도구는 테스트가 끝나면 임시 물리 씬·입력 장치·설정을 정리한다. 런타임 사본은 `AgentScripts/runtime/`에 동기화한다. 원시 씬 검사 결과는 `Temp/PlayerTraversalSceneValidation.txt`, 활공 캡처는 `Assets/Captures/B612_TraversalGlide.png`다. 실제 화면을 각각 30/60/120fps로 제한한 성능 측정이나 새 레벨 전체의 난이도 검증을 수행했다는 뜻은 아니다.

아래는 요구 사항과 최초 설계 근거다. 첫 구현의 연결·측정 결과는 위 절을 기준으로 한다.

## 1. 요구 사항과 구현 기본안

사용자가 정한 요구:

- 체공 중 Space를 다시 누르면 한 번 더 점프할 수 있다.
- Shift를 누르면 바라보는 방향으로 짧게 대쉬한다. 지상과 공중에서 모두 가능하다.
- 더블점프 후 대쉬할 수 있다.
- 대쉬로 더블점프 횟수가 초기화되어 무한 체공하는 일을 막는다.
- 공중에서 Space를 길게 누르면 활공한다.
- 이번 구현은 이동 기능만 다룬다. 새 애니메이션·이펙트·사운드는 추가하지 않는다.
- 마리오 같은 플랫포머를 참고해 반응성과 기술 연계가 자연스럽게 느껴지도록 한다.

아래의 공중 대쉬 1회 제한, 활공 시간 제한, 입력 우선순위, 세부 수치는 구현 가능한 첫 기본안으로 제안한 사항이다. 사용자가 최종 밸런스로 확정한 수치는 아니다. 구현 chat은 이 기본안으로 기능을 연결하고 검증 후 조절한 값을 보고한다.

| 동작 | 입력 | 첫 구현 기본안 |
| --- | --- | --- |
| 지면 점프 | Space 누른 순간 | 기존 코요테 타임·입력 버퍼·가변 점프 높이 유지 |
| 공중 추가 점프 | 공중에서 Space를 새로 누름 | 착지 전 1회, 낙하 속도를 정해진 상승 속도로 교체 |
| 대쉬 | Left/Right Shift 누른 순간 | 캐릭터 정면의 접선 방향, 약 0.18초 |
| 공중 대쉬 | 공중에서 Shift | 착지 전 최대 1회. 추가 점프 횟수와 독립 |
| 활공 | 공중에서 Space를 0.20초 이상 유지하고 하강 | 완만하게 하강, 공중 구간당 총 2.5초 |

핵심 계약: 대쉬 시작·종료, 활공 시작·종료, 점프 버튼 해제, 단순 중력원 변경은 공중 자원을 회복시키지 않는다.

## 2. 현재 프로젝트에서 확인한 기반

- Unity `6000.3.23f1`, Input System `1.20.0`을 사용한다.
- `Assets/B612/Scripts/GravityWalker.cs`: Rigidbody 기반 구형 중력 이동 모터다. `FixedUpdate`에서 접지·중력·접선 속도·수직 속도를 계산하고 마지막에 `rb.linearVelocity`를 쓴다.
- 현재 기본값은 이동 속도 2m/s, 지상 가속도 12m/s², 공중 가속도 5m/s², 점프 속도 3.1m/s, 코요테 타임 0.12초, 점프 버퍼 0.15초다. 대표 행성 중력은 3.4m/s²다.
- `PlayerController.cs`: `Update`에서 키보드·게임패드 입력을 읽는다. Space와 게임패드 South가 점프이며, 실제 입력 방향은 `OrbitCamera.PlanarDirection`으로 변환한다.
- `GravityWalker`는 여우도 사용한다. 새 기능이 여우에게 자동 적용되지 않도록 플레이어 전용 구성을 사용한다.
- `LaunchStar`는 `Suspend(true)` 중 스크립트 비행을 하고 종료 시 `Suspend(false)`와 `Teleport`를 호출한다.
- `BaobabThreatMeter`는 게임 오버 시 `PlayerController`와 카메라 입력을 비활성화하고 `Time.timeScale = 0`으로 정지한다.
- 안정화된 `OrbitCamera`는 일반 점프의 자동 줌·공중 자동 회전을 제거한 상태다. 새 기술 때문에 이 보정을 다시 추가하지 않는다.
- `Assets/B612/Scripts/`와 `AgentScripts/runtime/`에 이동 코드가 중복 보관되어 있다. 명세 작성 시 `GravityWalker.cs`, `PlayerController.cs` 두 사본의 SHA256이 각각 일치했다. 구현 시 양쪽을 함께 갱신하고 동일성을 확인한다.
- 기존 `AgentScripts/JumpProbe.cs`는 상태 문자열을 반환하는 간단한 진단 코드이며, 아래 수용 조건을 검증하는 테스트를 대신하지 않는다.

먼저 구현할 대상은 현재 시제품 `Assets/B612/Scenes/B612_EmptyPlanet.unity`의 `Player`다. 기존 변경 사항을 보존하고, 씬 전체를 다시 만드는 `B612Builder.Build`를 실행해 덮어쓰지 않는다.

## 3. 조작감의 목표와 레퍼런스

역할을 분명하게 나눈다: 추가 점프는 높이와 낙하 복구, 대쉬는 짧은 거리와 순간 속도, 활공은 착지 위치를 고르는 시간을 준다.

Nintendo의 SUPER MARIO 3D LAND 개발자 인터뷰에서는 정지·달리기 점프의 감각을 조정하고 Roll과 Long Jump가 서로 다른 용도로 쓰이도록 구성했다고 설명한다. 이를 참고해 단독 동작의 반응성과 조합의 쓰임새를 함께 검증한다. New Super Mario Bros. U Deluxe의 공식 소개에서도 활공과 공중 동작의 조합을 볼 수 있다.

본 명세의 Space 더블점프·Shift 대쉬 조합, 코요테 타임, 활공 예산과 모든 수치는 B612용 제안이다. 마리오의 정확한 물리값이나 동일한 입력 체계를 재현한다는 의미는 아니다.

## 4. 입력: Space의 점프와 활공을 구분하는 규칙

### 기본 처리

1. Space의 새 누름은 즉시 점프 요청을 만든다. 길게 누르는지 기다린 뒤 점프를 실행하지 않는다.
2. 유효한 지면/코요테 점프가 가능하면 지면 점프한다.
3. 지면 점프가 불가능하고 공중 추가 점프가 남았으면 즉시 추가 점프한다.
4. 점프를 실행할 수 없으면 요청을 최대 0.15초만 유지한다. 그 안에 착지하면 지면 점프로 소비할 수 있다.
5. Space를 계속 누른 시간이 0.20초 이상이고 하강·활공 가능 조건을 만족하면 활공한다.
6. 누르고 있는 것 자체는 새로운 점프 요청을 만들지 않는다. 새 점프는 해제 후 다시 눌러야 한다.

이 규칙의 결과:

- 지면에서 Space를 누른 채 유지: 일반 점프 → 정점을 지난 뒤 활공. 자동 더블점프는 없음.
- 공중에서 추가 점프가 남은 상태로 Space를 새로 길게 누름: 즉시 추가 점프 → 이후 하강 시 활공.
- 공중 추가 점프가 이미 소모된 상태에서 Space를 길게 누름: 추가 상승 없이 하강 중 활공.
- 추가 점프를 보존한 채 일반 점프에서 이어진 활공 중 Space를 해제 후 다시 누름: 남은 추가 점프 사용 가능.
- 낭떠러지에서 걸어 나간 뒤 누름: 코요테 시간 안이면 일반 점프, 그 이후면 공중 추가 점프 1회 사용.

따라서 '추가 점프가 남아 있을 때 공중에서 새로 누르는 길게 누르기'는 점프를 먼저 사용한다. 짧게/길게를 판별하느라 추가 점프 반응이 늦어지지 않게 하기 위한 선택이다.

### 입력 수집과 소비

- `Update`에서 눌림·해제·유지 상태를 기록하고 `FixedUpdate`에서 실제 기술을 승인한다.
- 누름 요청은 한 번 승인되면 바로 소비한다. `Update` 한 번 뒤 물리 틱이 여러 번 돌아도 같은 입력으로 두 번 점프하지 않는다.
- 여러 장치의 유지 상태는 OR로 합친다. 키보드 Space를 해제해도 게임패드 점프를 유지 중이면 전체 해제로 취급하지 않는다.
- Shift 유지로 자동 연속 대쉬하지 않는다. 새 누름과 최대 0.10초의 짧은 대쉬 버퍼만 사용한다.
- 게임패드는 기존 South 점프/유지를 유지하고, 대쉬는 Right Shoulder를 첫 매핑으로 제안한다. 현재 입력 체계를 통째로 교체하지 않는다.
- 일시정지·입력 비활성화·창 포커스 상실 시 남은 누름 요청과 유지 시간을 지운다. 복귀 시 오래된 입력을 실행하지 않는다.

## 5. 공중 자원과 유효 착지

### 관리할 상태

```text
Mode = Locomotion | Dash | Glide | Suspended
airJumpsRemaining = 0 또는 1
dashChargeAvailable = true/false
glideSecondsRemaining = 0~2.5
dashCooldownRemaining
jumpHeldSeconds
pendingJump / pendingDash / requestId
flightActive / supportStableSeconds / timeSinceTakeoff
```

상승·하강은 수직 속도에서 판정한다. 모든 조합을 별도 enum으로 늘리지 않는다. `IsDashing`, `IsGliding`, 남은 자원은 디버그와 후속 연출을 위해 읽기 전용으로 노출한다.

### 회복 조건

- 초기 배치·명시적인 리스폰: 공중 점프 1회, 대쉬 가능, 활공 2.5초, 진행 중 동작·입력·속도·쿨다운 초기화.
- 실제 비행 후 유효 착지: 공중 점프 1회, 대쉬 자원, 활공 예산 회복. 대쉬 쿨다운은 남아 있으면 계속 적용한다.
- 공중 추가 점프 승인: 추가 점프만 1회 차감.
- 어떤 대쉬든 승인: 대쉬 자원 소모, 쿨다운 시작. 점프/활공 자원은 보존.
- 활공: 실제 활성 상태의 물리 시간만 예산에서 차감. 다시 시작하거나 대쉬를 끼워도 회복되지 않는다.

지상 대쉬 후에도 지상에 남아 있다면 대쉬 종료·쿨다운 완료·안정적인 지지 조건을 만족할 때 지상 대쉬를 다시 쓸 수 있다. 지상 대쉬로 절벽을 벗어나면 그 공중 구간의 대쉬 자원은 이미 소모된 상태다. 착지 전 두 번째 대쉬를 허용하지 않는다.

### 착지의 정의

`Grounded`의 단일 프레임 변화만 보고 자원을 초기화하지 않는다.

2026-11-08 경사 회귀 보완: 걷는 동안의 물리 접지와 공중 기술을 회복하는 착지 확정을 분리한다. 경사 오르기는 중력 반대 방향 속도가 양수여도 정상적인 접지 이동이다. 그 성분에 작은 문턱을 걸어 곧바로 공중으로 판정하지 않는다. 지면 이탈 속도는 실제 지지 법선과 지지체 대비 상대 속도를 기준으로 판단하고, 점프 직후의 잔여 접촉은 명시적인 이륙 차단으로 제외한다. 아래 연속 지지·회복 차단 시간은 자원 회복 조건이며 일반 걷기를 공중으로 만드는 근거가 아니다. 현재 구현에서 발견한 원인과 검증 보완은 `PlayerTraversalSlopeDiagnosis.md`를 따른다.

- 발밑의 유효 지면이고 자기 몸·Trigger·벽·천장이 아니다.
- 법선은 현재 행성 중력의 반대 방향에 대해 허용 경사 안에 있다. 월드 위쪽을 기준으로 삼지 않는다.
- 지면 쪽으로 접근하거나 서 있는 상태다. 상승 중 발밑이 탐색 거리에 남아 있는 것을 착지로 보지 않는다.
- 첫 기본값으로 지지가 0.04초 연속 확인되어야 한다. 이륙 직후 약 0.10초에는 잔여 발밑 접촉으로 재충전하지 않는다.
- 진행 중 대쉬의 순간 접촉은 착지 회복으로 처리하지 않는다. 대쉬 종료 후 지지와 접근 조건을 확인한다.
- 착지 회복은 한 번만 발생시키고, 버퍼된 지면 점프가 있으면 회복 후 해당 요청을 소비한다.
- 착지 확인 시간을 기다리는 동안 0.15초 입력 버퍼를 유지한다. 모서리와 낮은 천장에서 불필요한 지연이 생기는지는 플레이 검증으로 조정한다.

원래 지상에서 계속 서 있는 동안에는 점프 사용 여부를 반복해서 초기화하지 않는다. 특히 점프를 실행한 물리 틱에서 지면 탐색 결과가 true였다는 이유로 즉시 추가 점프가 충전되어서는 안 된다.

## 6. 더블점프 물리

공중 점프를 승인할 때, 해당 중력 반대 방향을 기준으로 현재 속도를 분해한다.

```text
up = 공중 이동에 사용하는 정규화된 중력 반대 방향
vertical = dot(velocity, up)
tangentVelocity = velocity - up * vertical

vertical = doubleJumpSpeed   // 첫 값 3.0m/s
velocity = tangentVelocity + up * vertical
airJumpsRemaining -= 1
```

- 기존 낙하 속도를 지우고 정해진 상승 속도로 바꾼다. 낙하 중에도 효과가 일정하다.
- 현재 상승 속도에 점프 속도를 계속 더하지 않는다.
- 접선 운동량은 보존한다. 대쉬 취소 직후라면 아래의 대쉬 종료 속도 제한을 적용한다.
- 일반 점프와 추가 점프 모두 버튼을 빨리 놓으면 짧게 뜨는 기존 가변 높이 규칙을 적용한다.
- 추가 점프는 코요테 타임이나 지면 점프 권리를 새로 만들지 않는다.
- 추가 점프 때 활공/진행 중 대쉬는 종료하지만, 남은 활공 시간과 소모한 대쉬 자원은 유지한다.
- 기존 `Jumped` 이벤트는 지면/코요테 점프의 기존 의미를 유지하고 추가 점프에는 별도 `AirJumped`를 제공하는 안을 사용한다. 여우가 공중 점프를 새로운 지면 점프로 오해하지 않게 한다.

## 7. 대쉬 물리와 곡면·충돌 처리

### 방향과 속도

- 시작 시 캐릭터 루트의 실제 정면을 이동 접선 평면에 투영하고 정규화한다. 카메라 정면이나 마우스 피치로 방향을 정하지 않는다.
- 투영이 거의 0이면 최근 유효 접선 정면을 사용한다.
- 시작 이후 WASD나 카메라 회전으로 대쉬 방향을 다시 지정하지 않는다.
- 작은 구형 행성을 따라 `up`이 바뀌면 이전 `up`에서 새 `up`으로의 회전을 대쉬 방향에도 적용한다. 고정된 월드 직선으로 지면 속을 파고들게 하지 않는다.
- 접선 속도를 정해진 대쉬 속도로 교체한다. 기존 속도에 매 틱 대쉬 힘을 더하지 않는다.
- 첫 값은 최고 8m/s, 총 0.18초다. 처음 0.12초는 빠르게 이동하고 마지막 0.06초는 약 3m/s까지 감속한다. 평탄한 무장애 지면의 예상 이동량은 약 1.29m다.
- 종료 후 일반 이동 가속도에 제어를 반환한다. 최고 속도가 오래 남아 실제 대쉬 거리가 무제한 늘어나지 않게 한다.
- 점프로 조기 취소할 경우 접선 속도는 최대 3m/s로 정리한 뒤 점프한다. 속도를 완전히 0으로 만들지는 않는다.

### 수직 운동

- 공중 대쉬는 상승 속도를 추가하지 않고 정상 중력을 계속 적용한다.
- 대쉬 시작 때 낙하 속도를 0으로 만들지 않는다. 대쉬 종료 때도 점프·활공 시간을 회복하지 않는다.
- 지상에서 지면을 따라가는 보정은 기존 경사/접지 처리와 연결한다. 절벽 밖을 지면으로 당겨 붙이거나 착지로 위장하지 않는다.
- 구면에서는 빠른 접선 이동 자체가 지면으로부터 멀어지게 할 수 있다. 방향 보정·지면 추적이 의도치 않은 상승을 만들지 않는지 측면·밑면에서도 확인한다.
- **비탈 꼭대기에서 튀어 오르지 않는다 (2026-11-23 수정):** 지상 대쉬는 디딘 비탈면을 따라 8m/s로 움직인다. 그래서 강둑·비탈·벼랑을 오르는 대쉬는 행성 바깥 방향 속도를 크게 얻었다. 비탈 꼭대기에서 땅을 벗어나면 그 속도로 날아올라, 실제 지형에서 최대 5.3m(일반 점프 약 1.5m)까지 떴다.
  - 대쉬를 시작한 뒤 다시 안정적으로 착지할 때까지, 공중에서의 바깥 방향 속도를 제한한다(`dashMaxRiseSpeed` 0.8m/s, `PlayerTraversalAbilities.LimitDashRise`).
  - 땅에서 공중으로 나갈 때는 최대 0.8m/s다. 그 뒤로는 중력으로 줄어들기만 한다. 공중에서 가파른 면에 닿아도 상승이 늘지 않는다.
  - 점프는 이 제한을 풀고 자기 속도를 그대로 쓴다. 같은 틱의 Space+Shift와 점프 뒤 공중 대쉬도 점프 상승을 그대로 유지한다.
  - 지상에서 비탈을 따라 오르는 대쉬 자체와 대쉬 거리는 바뀌지 않는다.
  - 검증(`NaturalTerrainMeshValidation.Dash`, 생성기 20 행성 4곳, 강둑 오르기·강 쪽으로·비탈 오르기·벼랑 내려가기·평지 약 600회): 이륙 지점보다 높이 뜬 최대값은 5.3m → 0.23m다. 가파른 비탈을 앞으로 계속 걸어 오르는 경우는 0.74m까지 오르지만, 지면에서 0.43m 안을 지나므로 비탈을 따라 오르는 것이다.
  - `PlayerTraversalValidation`의 `Validate`·`ValidateSlopes`·`ValidateGeometryAndLegacy`는 모두 통과했다. 대쉬 거리는 1.29/1.29/1.35m로 같다. `TraversalTestCourseValidation`은 수정 전과 모든 시도의 결과·높이·착지 위치가 같다. 이 검사는 수정 전부터 `passed=false`였다(구간 0 "Dash launch -0.1" 등).

### 충돌

- Transform 순간 이동이나 `Suspend`를 이용한 비행으로 구현하지 않는다. 현재 Rigidbody 이동과 접촉을 유지한다.
- 한 물리 틱의 예상 변위에 캐릭터 캡슐 크기로 sweep/cast하고, 벽을 만나면 안전 거리까지로 제한하고 대쉬를 종료한다. 벽을 타고 상승하는 힘으로 바꾸지 않는다.
- 캡슐 중심·반경·끝점은 현재 CapsuleCollider와 회전·스케일을 반영한다. 자기 Collider와 Trigger는 제외한다.
- 정상적인 지면의 얕은 접촉과 진행 방향을 가로막는 벽을 구별한다. 바닥의 거의 0거리 접촉 때문에 모든 지상 대쉬가 취소되지 않도록 한다.
- cast 시작 시 이미 겹친 Collider는 cast만으로 검출되지 않을 수 있으므로 기존 접촉/겹침 해소도 유지한다. 충돌을 피하려고 전체 지면 레이어를 제외하지 않는다.
- 기존 ContinuousDynamic을 유지하되 CCD만으로 관통 방지를 완료했다고 판단하지 않는다.

## 8. 활공 물리

### 진입과 종료

진입 조건은 전부 만족해야 한다.

- 실제 공중 상태이고 유효 중력장이 있다.
- 대쉬/발사 별 비행/게임 오버가 아니다.
- Space를 연속 0.20초 이상 유지하고 있다.
- 상승이 끝나 하강 중이다. 첫 판정 기준은 수직 속도 -0.05m/s 이하로 둔다.
- 남은 활공 시간이 0보다 크다.

Space 해제, 착지, 활공 예산 소진, 대쉬·추가 점프 승인, 중력장 상실, 입력 중지/비행 전환 중 하나가 발생하면 종료한다.

### 하강과 조향

- 목표 하강 속도는 0.75m/s, 최소 하강 속도는 0.15m/s를 첫 값으로 사용한다. 기준은 현재 중력 방향이다.
- 활공 중에는 수직 속도를 음수로 유지하면서 목표 하강 속도로 초당 4m/s² 범위에서 접근시킨다.
- 빠르게 떨어지는 중에 활공했다고 낙하 속도를 한 프레임에 0으로 지우지 않는다. 예를 들어 -5m/s에서 -0.75m/s로 점진적으로 감속한다.
- 공중 접선 목표 속도는 최대 2.6m/s, 조향 가속도는 3m/s²를 첫 값으로 둔다. 작은 입력 보정이 가능하고 즉시 반대로 꺾이지 않게 한다.
- 활공 해제 시 현재 속도를 이어받아 일반 중력으로 돌아간다. 인위적인 위쪽 impulse나 별도 낙하 속도를 주지 않는다.
- 활공 수직 처리는 해당 틱의 일반 중력/점프 짧게 누르기 처리와 중복 적용하지 않는다.
- 작은 행성에서는 중력만 낮추면 접선 속도로 궤도처럼 머무를 수 있다. 하강 성분 유지와 공중당 총 2.5초 예산을 함께 적용한다.
- 토글해도 예산은 회복되지 않는다. 예산 소진 뒤 Space를 계속 눌러도 다시 켜지지 않는다.

## 9. 조합·동시 입력 처리표

| 상황 | 처리 |
| --- | --- |
| 일반 점프 → 추가 점프 → 대쉬 | 모두 가능. 이후 추가 점프/대쉬 재사용 불가 |
| 일반 점프 → 대쉬 → 추가 점프 | 남아 있던 추가 점프 1회 사용 가능. 대쉬가 진행 중이면 취소 후 점프 |
| 추가 점프를 쓴 뒤 대쉬 종료 | 추가 점프는 0회로 유지 |
| 활공 중 대쉬 | 활공 종료 후 대쉬. 활공 잔량은 유지 |
| 대쉬 종료 후 계속 Space 유지 | 하강·유지 시간·잔량 조건을 만족하면 활공 재개 |
| 활공 중 새 Space 누름 | 추가 점프가 남아 있으면 활공 종료 후 점프 |
| 같은 틱의 Space + Shift | 가능한 점프를 먼저 적용하고 대쉬를 시작. 수직 점프와 접선 대쉬를 함께 사용 |
| 점프 불가능한 상태의 Space + Shift | 점프는 짧게 버퍼, 가능한 대쉬 실행. 대쉬가 점프 권리를 만들지 않음 |
| 발사 별 위에서 Space + Shift | 기존 발사 별 탑승 우선. 두 일반 기술 요청을 지우고 Suspended 진입 |
| Shift 연타/유지 | 공중 자원·쿨다운·새 누름 조건을 모두 통과한 1회만 승인 |
| 벽·천장에 닿음 | 자원 회복 없음 |
| 중력원만 변경됨 | 자원 회복 없음 |
| 실제 착지 | 공중 자원 회복. 대쉬 쿨다운은 별도 유지 |

점프 요청은 승인이 실패했다고 무기한 남기지 않는다. 요청 만료 시점과 소비 여부를 관리하고, 해제/유지 상태와 별개로 취급한다.

## 10. 코드 책임 분리와 계산 순서

### 권장 파일 구성

| 파일 | 구현 책임 |
| --- | --- |
| 기존 `PlayerController.cs` | Space/Shift/패드 입력 수집, 발사 별 우선순위, 비활성화 시 입력 해제 |
| 기존 `GravityWalker.cs` | 접지·중력·속도 계산과 충돌을 통합하는 단일 모터 |
| 새 `PlayerTraversalAbilities.cs` | 플레이어 전용 기술 상태·횟수·쿨다운·활공 잔량·튜닝 필드 |
| `AgentScripts/PlayerTraversalBuilder.cs` 제안 | 현재 씬의 Player에 구성 연결. 씬 전체 재생성 없이 수행 |
| `AgentScripts/PlayerTraversalValidation.cs` 제안 | 조합·착지·벽 접촉·입력 경계·행성 좌표 검증 |

첫 구현은 플레이어 전용 컴포넌트의 직렬화 필드로 조절해도 충분하다. 여러 캐릭터 프리셋이 필요해질 때 설정 에셋으로 분리한다.

`PlayerTraversalAbilities`는 별도 `FixedUpdate`에서 Rigidbody 속도를 덮어쓰지 않는다. 모터의 한 물리 틱 안에서만 호출되어 현재 속도와 명령을 조정한다. 최종 `rb.linearVelocity` 작성자는 `GravityWalker` 하나로 유지한다.

### 최소 연결 계약

- 기존 `GravityWalker.Jump()`는 요청 등록 경로로 유지한다. 플레이어 기술 구성이 있으면 공중 추가 점프 판정까지 위임하고, 없으면 기존 점프만 수행한다.
- 대쉬 요청 메서드 `RequestDash()`를 추가한다. 플레이어 기술 구성이 없으면 실행하지 않는다.
- `jumpHeld`와 입력 버퍼는 `Update`→`FixedUpdate` 경계를 보존한다.
- `PlayerController.OnDisable` 등에서 입력과 진행 중 플레이어 기술을 취소한다. 이 취소가 공중 자원을 충전해서는 안 된다.
- 기존 `Grounded`, `Up`, `Source`, `TangentSpeed`, `VerticalSpeed`, `Suspended`의 의미와 읽기 경로를 유지한다.
- 첫 씬 연결은 Player에만 기술 컴포넌트를 추가한다. 여우에는 추가하지 않는다.
- 추가한 런타임 파일과 수정 파일은 `AgentScripts/runtime/`의 대응 사본도 준비한다.

### 모터 한 틱의 권장 순서

1. 정지/스크립트 비행 확인. 진행 중이면 기술·입력 처리 중단.
2. 중력장, 물리 접촉, 유효 지지와 착지 확정 갱신.
3. 착지 자원 회복 및 지상 대쉬 재충전 조건 갱신.
4. 현재 월드 속도를 이번 이동 기준의 접선/수직 성분으로 분해.
5. 유효 점프 요청 처리. 기존 대쉬/활공 중이면 성공 시 취소.
6. 새 대쉬 요청 처리. 자원·쿨다운 승인 후 접선 속도 결정.
7. 대쉬가 아니면 활공 진입/종료, 아니면 일반 공중·지상 이동 처리.
8. 해당 모드의 수직 운동을 한 번 계산. 점프 승인 틱에는 새 상승 속도를 의도대로 유지하고 다른 모드가 덮어쓰지 않게 함.
9. 대쉬 sweep 등 충돌 제한, 최종 속도·회전 적용.
10. 사용한 요청 소비, 활성 기술 시간·잔량·진단값 갱신.

지상에서는 기존 지면 방향을, 공중에서는 중력 반대 방향을 이동 기준으로 사용한다. 같은 틱의 점프·대쉬·활공이 서로 다른 기준으로 속도를 덮어쓰지 않게 한다. 월드 속도 자체를 매번 회전시켜 불필요한 에너지를 만들지 않는다. 곡면을 따라 회전시킬 대상은 대쉬의 진행 기준 방향이다.

## 11. 초기 조절값

| 항목 | 첫 값 | 비고 |
| --- | ---: | --- |
| 기존 일반 이동/점프 속도 | 2 / 3.1m/s | 첫 검증에서 유지 |
| 추가 점프 상승 속도 | 3.0m/s | 현재 수직 속도 교체 |
| 코요테 타임/점프 버퍼 | 0.12 / 0.15초 | 기존 값 유지 |
| 일반 공중 가속도 | 5m/s² | 먼저 유지, 제어 부족 시 7까지 비교 |
| 하강 중 중력 배율 | 1.6 | 플레이어 기술 구성에서만 적용할 첫 제안 |
| 상승 중 버튼 해제 추가 중력 | 기존 2.2 | 기존 `shortHopGravity` 의미 유지 |
| 대쉬 최고 속도/시간 | 8m/s / 0.18초 | 첫 0.12초 유지, 마지막 0.06초 감속 |
| 대쉬 종료 접선 속도 | 최대 3m/s | 과도한 잔여 이동 방지 |
| 대쉬 쿨다운 | 시작 후 0.65초 | 착지로 생략하지 않음 |
| 대쉬 입력 버퍼 | 0.10초 | 유지 입력 자동 반복 없음 |
| 활공 유지 임계 | 0.20초 | 가장 최근 누름 기준 |
| 공중당 활공 예산 | 2.5초 | 실제 활공 시간 누적 |
| 활공 목표/최소 하강 속도 | 0.75 / 0.15m/s | 중력 방향 기준 |
| 활공 수직 감속·가속 한계 | 4m/s² | 급강하를 즉시 취소하지 않음 |
| 활공 접선 목표 속도/조향 가속도 | 2.6m/s / 3m/s² | 입력 방향으로 완만하게 조향 |
| 지지 확인/이륙 직후 회복 차단 | 0.04 / 0.10초 | 모서리·낮은 천장에서 조절 검증 |

일반 중력 3.4m/s²와 점프 속도 3.1m/s의 단순 평면 계산에서는 정점까지 약 0.91초, 높이 약 1.41m다. 이 값과 약 1.29m 대쉬 거리는 설계용 계산이며 구형 행성의 실제 플레이 측정값이 아니다.

상승 중에는 기존 일반 중력과 짧게 누르기 규칙을, 일반 하강 중에는 1.6배 중력을, 활공 중에는 활공 수직 규칙을 사용한다. 세 규칙을 동시에 더하지 않는다. 하강 배율은 여우의 기존 동작에는 적용하지 않는다.

## 12. 기존 시스템과의 회귀 조건

- 발사 별 탑승 시 진행 중 기술과 입력 버퍼를 취소한다. `Suspend(true/false)` 자체로 자원을 충전하지 않는다. 도착의 명시적인 `Teleport`는 착지/리스폰 초기화 경로로 정리한다.
- `Teleport`와 R 리스폰은 대쉬 방향·모드·입력·타이머도 초기화한다. 이전 방향으로 다음 틱에 튀어나오지 않는다.
- 게임 오버/일시정지는 기술 시간·잔량·쿨다운을 게임 시간과 함께 정지시킨다. 비활성 입력을 계속 수집하지 않는다.
- 중력장이 없으면 마지막 유효 기준을 유지하되 활공은 종료한다. 현재 `TimeWithoutGravity` 기반 리스폰 규칙과 충돌하지 않게 한다.
- 기존 Animator 연결과 절차적 표현은 보존한다. 새 클립, Animator 파라미터, 전용 포즈, 파티클, 소리, 대쉬 FOV/카메라 흔들림을 추가하지 않는다.
- 카메라의 안정적인 기준과 지면 추적을 보존한다. 대쉬 속도에서 대상과 착지 지면을 따라갈 수 있는지는 검증하되, 문제를 해결하기 위해 자동 줌·공중 자동 회전을 다시 도입하지 않는다.
- 양 소환은 기존처럼 실제 접지 중에만 가능해야 한다. 대쉬/활공을 쓰려고 `Grounded`를 임의로 true로 바꾸지 않는다.
- 게임패드의 기존 이동·점프와 키보드 WASD·화살표·R 입력을 유지한다.

## 13. 수용 조건과 검증 계획

자동 검증에서는 가상 입력 또는 모터 요청으로 아래 조건을 검사하고, 실제 씬에서 조작감을 확인한다. 테스트용 변경은 종료 시 원상 복구하거나 격리된 검증 씬에서 수행한다.

| 항목 | 기대 결과 |
| --- | --- |
| 한 번 Space 누르고 유지 | 일반 점프 1회. 자동 추가 점프 없음. 하강 시 활공 |
| 공중에서 Space 재누름 | 추가 점프 정확히 1회. 세 번째 누름으로 상승하지 않음 |
| 빠른 누름과 유지 | 짧은 점프와 긴 점프의 높이 차이가 일관됨 |
| 코요테 안/밖 | 안에서는 일반 점프, 밖에서는 남은 공중 추가 점프 사용 |
| 착지 직전 누름 | 공중 점프가 없으면 버퍼 후 착지 점프. 요청 하나로 중복 점프 없음 |
| 추가 점프 후 대쉬 | 두 동작 성공. 대쉬 후 추가 점프는 여전히 0 |
| 대쉬 후 추가 점프 | 남아 있던 1회만 성공. 이후 재대쉬/재점프 불가 |
| 같은 틱 Space+Shift | 점프 상승과 접선 대쉬 동시 적용. 둘 중 하나가 덮어써지지 않음 |
| Shift 유지/연타 | 공중에서 대쉬 1회. 쿨다운 경과만으로 공중 재충전 없음 |
| 지상 대쉬로 절벽 이탈 | 공중 대쉬는 소모 상태. 추가 점프는 기존 잔량 유지 |
| 활공 재시작 반복 | 합계 활성 시간이 2.5초를 넘지 않음 |
| 빠른 낙하에서 활공 | 상향 점프나 순간 정지 없이 점진 감속 |
| 기술 반복·중력원 변경 | 착지 없이 자원 증가 없음. 작은 행성 궤도 체공으로 활공 예산 회복 없음 |
| 벽·천장·지형 모서리 | 관통·벽 상승·가짜 착지 재충전 없음 |
| 실제 착지 후 다시 점프 | 추가 점프·대쉬·활공이 정상 회복 |
| 발사 별·리스폰·게임 오버 | 상태 잔류, 멋대로 발동, 시간 진행 없음 |
| 여우와 기존 데모 | 플레이어 전용 기술이 여우에게 적용되지 않음 |

검증 위치: 위쪽 평지, 행성 측면, 밑면, 완만한 곡면, 각진 능선, 벽, 낮은 천장, 절벽 끝. 30/60/120fps와 같은 물리 간격에서 입력 누락·횟수 차이를 비교한다. 물리 간격을 바꾼 경우에도 대쉬 시간·거리와 버퍼가 심하게 달라지지 않는지 추가 확인한다.

경사 검증은 중력과 지면 법선이 실제로 다른 15·30·45도 바닥에서 오르기·내리기·횡이동을 포함한다. 정렬된 구나 전체 장면을 함께 회전하는 검증으로 대체하지 않는다. 실제 접지가 유지되는 걷기에서 `Grounded`가 반복 전환되어 Animator의 `Locomotion/Air`가 끊기는지도 확인한다.

개발용 진단에는 모드, 지지 상태, 공중 점프 잔량, 대쉬 자원/쿨다운, 활공 잔량, 현재 수직·접선 속도와 요청 소비 ID를 노출한다. 제품 UI 추가는 이번 범위가 아니다.

## 14. 구현 순서와 보고할 내용

1. 기존 변경 상태와 현재 입력/중력 코드를 재확인한다.
2. 플레이어 전용 기술 구성과 입력 소비·착지 회복을 연결한다.
3. 추가 점프와 자원 불변 조건을 검증한다.
4. 대쉬 방향·충돌·곡면 이동과 조합을 검증한다.
5. Space 유지 판정과 활공·예산을 연결한다.
6. 게임 오버·발사 별·리스폰·여우·카메라 회귀를 확인한다.
7. 실제 플레이에서 기본 수치를 조절하고 수용 조건 결과를 기록한다.
8. `AgentScripts/runtime/` 사본을 맞추고, `Docs/GameDesign.md`에 실제 구현 범위를 기록한다.

완료 보고에는 수정 파일, 최종 조절값, 수행한 자동/플레이 검증과 결과, 남은 문제를 포함한다. 테스트를 실행하지 않았다면 통과했다고 기록하지 않는다.

## 15. 다른 chat에 전달할 작업 문구
