## 1. 요청 범위와 첫 구현의 선택

후속 타일 밀도 변경 요구는 `PlanetTileDensityImplementationSpec.md`를 참고한다. 행성 크기에 따라 논리 구역 수를 늘리는 별도 구현 명세이며, 기존 지도·전환 구현과 달리 이 후속 변경은 아직 문서 단계다.

### 사용자가 정한 요구

- 공통 행성 씬을 사용하고, 각 행성의 데이터를 적용해 새 행성을 만든다.
- 새 행성은 우선 **지면 색과 크기만** 무작위로 달라진다.
- 크기는 **기존 `B612_EmptyPlanet` 행성의 0.7배~2배**로 제한한다.
- 지도에서 마우스로 다음 행성을 고른다. 마우스를 올리면 행성의 대·중·소 정보를 표시한다.
- 이후 NPC·작물 정보도 툴팁에 추가할 수 있어야 한다. 이번에는 크기만 표시한다.
- 바오밥 **생성 페이즈 종료**를 알리고 지도를 해금한다. `M`으로 지도를 열고 다음 행성을 선택해 이동한다.

## 2. 공통 씬과 행성 인스턴스를 구분한다

**씬과 행성의 원본은 재사용하고, 행성별 데이터는 독립적으로 유지한다.** A에서 B로 이동할 때 A의 `PlanetData`를 B의 값으로 덮어쓰지 않는다.

```text
공통 게임플레이 씬
  GameSession / StarSystemFlowController  : 항성계·현재 위치·진행 제어
  Player / Camera                       : 행성 교체 후 재배치·참조 재설정
  HUD / Map UI / Debug UI / EventSystem  : 공통 화면
  GamePauseCoordinator                  : 일시정지 소유권
  BaobabSurge / BaobabThreatMeter        : 현재 행성에 다시 연결할 서비스
  LambCardHand                          : 여정 동안 유지하는 손패
  PlanetWorldHost                       : scale = (1,1,1)
    ActivePlanetWorld                   : scale = (1,1,1)
      GroundSurface                     : 원본 지면 scale × sizeScale
      SurfaceGrid / Gravity / Spawn     : 지면에 맞춰 설정
      RuntimeActors                     : scale = (1,1,1), 싹·양 등
```

- 기존 씬을 공통 플레이 공간으로 활용한다. 첫 구현에서 매번 `LoadScene`할 필요는 없다.
- 기존 `Asteroid B-612`의 메시·Collider·원본 재질을 행성 템플릿으로 추출한다. 씬의 마지막 변경 상태를 다음 원본으로 삼지 않는다.
- 플레이어·카메라·UI·양·바오밥 모델까지 포함한 `B612 World` 전체를 확대하지 않는다. **크기 배율은 지면에 적용**하고, 지면 좌표를 사용하는 요소는 재배치한다.
- `RuntimeActors`는 확대된 `GroundSurface`의 자식으로 두지 않는다. 현재 싹 생성 루트는 `surface.transform` 아래에 생기므로 `PlanetSurfaceGrid`도 배율 1인 기준 Transform에 두고 `ground`로 지면 Collider를 참조한다.
- 기존 빌더를 다시 실행해 데모 전체를 재생성하는 방식으로 적용하지 않는다. `AgentScripts/B612Builder.cs`는 생성물·씬을 넓게 바꾸는 경로다.

새 컴포넌트 이름과 계층은 제안이다. 핵심은 **지면의 배율과 플레이 개체의 배율을 분리하는 것**이다.

## 3. 크기·색 데이터 계약

`PlanetDataModel.md`의 `spec.terrain`에 `sizeScale`을 추가한다.

```json
{
  "planetId": "system_01_planet_B",
  "seed": 612101,
  "generatorVersion": 1,
  "role": "Normal",
  "sizeClass": "Small",
  "terrain": {
    "profileId": "terrain.emptyPlanet.v1",
    "sizeScale": 0.85,
    "radius": 4.505,
    "gravityStrength": 3.4,
    "groundColor": "#A6B88C"
  }
}
```

이 예시는 `PlanetSpec` 일부다. 기존 `baobab` 등은 전체 데이터 모델대로 유지한다. `terrain.emptyPlanet.v1`은 새로 연결할 템플릿 ID의 제안이며 현재 존재하는 에셋 ID가 아니다.

### 크기 적용

```text
sizeScale = 0.7 ~ 2.0
ground.localScale = templateBaselineScale * sizeScale
nominalRadius = templateBaselineNominalRadius * sizeScale
sizeClass = Classify(sizeScale)
```

- 0.7~2배는 **선형 크기 배율**이다. 같은 형태의 면적은 약 0.49~4배가 된다. 부피나 Transform의 절댓값을 뜻하지 않는다.
- `localScale *= sizeScale`로 누적 적용하지 않는다. 항상 고정된 원본 scale에서 계산한다. 2배 행성 다음 0.7배 행성은 원본의 0.7배여야 한다.
- 현재 빌더의 `AstRadius`는 `5.3`이다. 이 원본을 사용할 때 명목 반경은 `3.71~10.6`이다. 지형이 찌그러지고 요철이 있으므로 모든 표면점이 이 반경에 놓이지는 않는다.
- `terrain.radius`는 이 템플릿에서 위 식으로 계산해 확정한 명목 반경이다. `sizeScale`과 독립적으로 다시 추출하지 않는다. 프로필이 다른 원본 반경을 사용하면 해당 프로필 기준으로 계산한다.
- 크기 분류도 배율에서 한 번 계산해 저장하고, 데이터 검증 시 일치 여부를 확인한다. UI는 저장된 동일한 분류를 사용한다.
- 기존 크기 1.0은 이 기본안에서 '중'이다. 분류 경계는 설정 한 곳에서 관리한다.

### 중력·스폰·카메라에 함께 적용할 것

- `GravitySource.strength`는 기존값을 유지한다. 플레이어 속도·점프 높이·대쉬 거리·Collider 크기도 유지한다.
- `GravitySource.surfaceRadius`는 실제 지면 반경이 아니라 중력원 선택용 값이다. 원본의 해당 값을 배율에 맞게 조정하되 `terrain.radius`와 같은 수치로 취급하지 않는다.
- `influenceRadius`는 숫자 필드라 Transform 확대만으로 커지지 않는다. 새 Collider의 중심 기준 최대 범위를 감싸고, 최대 점프·더블점프 높이와 낙하 감지 여유가 있는지 검증한다. 원본 영향 반경을 배율만큼 키운 값과 필요한 외곽 여유 중 큰 쪽을 사용한다.
- 출발 위치는 원본 스폰 방향을 보관하고 새 Collider에 투영한 지면점 + 캡슐 바닥 여유로 계산한다. 이전 월드의 스폰 좌표를 재사용하거나 캐릭터 높이까지 배율로 곱하지 않는다.
- 지면 scale과 Collider를 적용한 뒤 `Physics.SyncTransforms()`를 수행하고 `PlanetSurfaceGrid.Prepare`로 슬롯을 다시 만든다. 기존 `TryProject`는 실제 `ground.bounds`와 Collider를 사용하므로 이를 활용한다.
- 카메라 기본 추적 거리·FOV를 행성 배율로 곱하지 않는다. 플레이어 기준 조작감을 유지하고, 전환 때 이전 지면·중력원·보간 기록을 초기화한다. 큰 행성에서도 지면이 시야를 과도하게 가리지 않는지 확인한다.
- 작은 행성에서 유효 슬롯이 적으면 기존 간격·급경사 제한을 유지한 채 생성 요청을 건너뛰고 진단 수치를 남긴다. 슬롯을 무한 재추첨하거나 플레이어 발밑에 강제 생성하지 않는다.

### 색 적용

첫 팔레트 예: 모래 `#EADFC6`, 연두 `#A6B88C`, 연보라 `#B8A6D8`, 분홍 `#D9A6AC`, 하늘 `#9EBCCB`. 이 목록은 조절 가능한 제안이며 인접 행성이 같은 색일 수도 있다.

- 각 노드의 `groundColor`를 한 번 확정해 지도 아이콘과 실제 지면이 같은 데이터를 읽는다.
- 기존 8색 재질의 상대적인 밝기 차이를 원본에서 추출해 대표색에 적용한다. 종이 텍스처·노멀·표면 설정을 유지한다.
- 공유 원본 Material을 직접 수정하지 않는다. 행성 소유 재질 인스턴스를 만들고 행성 폐기 때 해제한다. 다른 행성·양·UI가 같이 변색되면 안 된다.
- 재적용할 때 현재 색에 다시 곱하지 않는다. 원본 팔레트와 대표색에서 계산한다.
- 실제 화면의 조명 때문에 지도 아이콘과 화면상의 색이 완전히 같을 필요는 없다. 색에 바오밥 속도·시간대 등의 의미를 붙이지 않는다.

## 4. 항성계는 먼저 확정하고, 월드는 방문할 때 만든다

첫 검증용으로 고정 6개 노드를 권장한다. 중앙 태양·궤도는 장식이며 이동 경로는 `links`가 결정한다.

```text
           B ───→ D
         ↗   ↘       ↘
Start          E ───→ Destination
         ↘   ↗
           C

links: Start→B, Start→C, B→D, B→E, C→E,
       D→Destination, E→Destination
```

1. 시작 시 ID·역할·depth·지도 좌표·links를 만든다. 위 그림의 실제 계약은 명시된 `links`다.
2. 항성계 seed에서 노드별 seed를 만들고 각 노드의 크기·분류·색을 확정한다.
3. `currentPlanetId = startPlanetId`, 방문 경로에 시작 노드를 한 번 기록한다.
4. 시작 행성 월드만 만든다. 다른 노드는 데이터와 지도 아이콘만 존재한다.
5. 지도를 다시 열거나 마우스를 올리거나 클릭할 때 외형을 다시 추출하지 않는다.

`System.Random` 등 생성기 버전을 고정한 난수 경로를 사용하고, 노드 순서·seed 파생 규칙도 고정한다. 문자열의 런타임 `GetHashCode()`에 재현성을 기대하지 않는다. 외형·배치·향후 NPC의 난수 흐름을 나눠 한 기능의 추출 추가가 다른 기능을 바꾸지 않게 한다.

현재 `BaobabSurge.Begin()`은 `randomizeSeed = true`면 새 GUID 기반 seed를 뽑는다. 데이터 주도 경로에서는 **false와 확정된 배치 seed를 먼저 주입**한다. 크기·색은 seed만 남기지 않고 실제 선택값도 `PlanetSpec`에 보관한다.

노드 ID 중복, 없는 ID를 가리키는 link, 역방향·순환, 시작에서 도달 불가, 도착까지 연결되지 않은 노드를 시작 전에 검사한다. 새 지도를 열었다고 방문 경로나 행성 상태를 초기화하지 않는다.

## 5. 생성 종료와 지도 해금

현재 구현은 다음을 구분한다.

| 상태 | 현재 코드 의미 | 이번 지도 |
| --- | --- | --- |
| `Surging` | 생성 시간이 남음 | 잠김 |
| `Clearing` | 생성 종료, 살아 있는 싹이 남음 | 해금 |
| `Resolved` | 생성 종료, 남은 싹도 없음 | 해금 |
| `GameOver` | 위험도 100% | 지도 열기·출발 금지 |

**사용자가 요청한 '바오밥 생성 페이즈 종료'는 `BaobabSurge.IsComplete`에 대응한다.** `ActiveSproutCount == 0`만으로 해금하지 않는다. 생성 중 잠깐 싹이 없어도 지도가 열리면 안 된다.

```text
CanOpenMap = worldReady
             && surge.IsComplete
             && !threat.IsGameOver
             && !isTravelling
             && !debugIsOpen

CanTravel(target) = CanOpenMap
                    && currentNode가 terminal이 아님
                    && links에 current → target이 존재
                    && target.state.phase == Unvisited
```

`isMapUnlocked`를 진행 상태와 별개의 저장 정답으로 두지 않는다. 위 조건과 현재 행성 ID에서 계산한다. 해금 알림을 한 번 보여주었는지만 해당 활성 행성의 UI 상태로 관리한다.

- 해금 시 1회: **'행성 지도 활성화 · M 키로 다음 행성 선택'** 알림.
- 이후 HUD: **'[M] 행성 지도'** 표시. 남은 바오밥·위험도는 계속 표시한다.
- 잠긴 동안 M: **'바오밥 생성이 끝나면 지도를 열 수 있습니다.'**를 짧게 표시한다.
- 생성 종료 뒤 지도를 열기 전까지 남은 바오밥은 계속 성장하고 양은 먹기를 계속한다.
- 지도 안에서는 시간이 정지한다. 닫으면 동일한 나이·먹기 진행·이동 상태에서 재개한다.
- 미제거 상태로 떠난 경우 `surge.result`를 `Resolved`로 꾸미지 않는다. 첫 모델에 `LeftWithRemaining`을 추가해 남은 싹이 있는 출발을 구분한다. 현재 위험도 컴포넌트의 `Phase` enum에 같은 값을 추가할 필요는 없다.
- `PlanetState.phase`는 지도 해금만으로 `ReadyToLeave`로 바꾸지 않는다. 현재 `Clearing`/향후 콘텐츠 단계를 보존하고 출발 시 `Departed`로 기록한다. 전체 게임의 출발 정책을 추가할 때 이 시제품의 해금·출발 정책을 교체한다.

### 같은 프레임의 게임 오버 우선순위

현재 `BaobabThreatMeter`는 `LateUpdate`에서 양의 제거까지 반영해 패배를 판정한다. M 입력을 먼저 처리해 일시정지하면 그 프레임의 양 먹기·위험도 판정 순서가 달라질 수 있다.

따라서 M 입력은 요청만 기록하고, **기존 위험도 최종 판정 뒤** 지도 열기를 처리한다. 예: `StarSystemFlowController`의 `LateUpdate`를 ThreatMeter의 실행 순서 50보다 뒤에 둔다. 그 프레임에 100%가 확정되면 M 요청·이동 요청을 폐기한다. 기존 위험도 판정을 `Update`로 옮기거나 두 번 판정하는 방식은 피한다.

## 6. 지도 UI와 툴팁

기존 런타임 UI와 맞춰 uGUI Canvas + 기존 Input System의 UI 이벤트 경로를 사용한다. EventSystem과 입력 모듈을 중복 생성하지 않는다.

지도·알림의 한글 문자가 모두 표시되는 TMP 폰트를 연결한다. 기존 디버그 폰트는 해당 화면에 필요한 글자만 구운 정적 아틀라스이므로 지도 문구까지 포함한다고 가정하지 않는다. 지도용 글리프를 추가하거나 적절한 폴백을 지정하고 실제 빌드에서도 확인한다.

### 노드 표시와 선택

- 현재 노드: '지금 여기' 마커.
- 지나온 노드·연결: 실제 방문 경로로 강조.
- 현재 노드의 outgoing 목적지: 밝은 테두리와 마우스 선택 가능 표시.
- 나머지 노드: 흐리게 표시하고 클릭을 받아도 이동하지 않는다.
- 지면 대표색을 아이콘에 적용한다. 상태 표시는 테두리·마커로 구분해 대표색을 덮어쓰지 않는다.
- 소·중·대는 필요하면 아이콘 크기에도 완만하게 반영하되 클릭 영역은 충분히 유지한다. 월드 배율 0.7~2를 UI 크기에 그대로 곱할 필요는 없다.
- UI 노드는 `planetId`만 전달한다. 최종 이동 허가는 중앙 흐름 컨트롤러가 다시 검사한다.

### 이번 툴팁

```text
행성 크기: 소
```

현재 크기 한 줄만 표시한다. 정확한 배율·반경, NPC·작물의 임시 문구는 노출하지 않는다. 모든 노드는 크기 확인을 위한 hover가 가능하고, 이동 가능 여부와 hover 가능 여부를 분리한다. 비활성 Button이 포인터 이벤트까지 막으면 별도 hover 대상 Graphic/컴포넌트를 둔다.

- `PointerEnter`에서 해당 `PlanetData`를 읽어 표시하고 `PointerExit`·지도 닫기·전환 시작 때 숨긴다.
- 포인터 근처에 작은 패널을 표시하고 Canvas 안으로 위치를 제한한다. Screen Space Camera에서는 올바른 UI 카메라로 좌표를 변환한다.
- 툴팁 배경과 텍스트는 raycast를 막지 않게 해 진입·이탈 깜빡임을 방지한다.
- 지도 재열기 때 툴팁은 숨김에서 시작한다. 노드가 바뀌었는데 이전 크기가 남지 않아야 한다.
- 향후 `PlanetMapPreview`에 크기·NPC 표시명·작물 목록을 읽는 선택 필드를 추가한다. UI는 표시 데이터만 받고 NPC·작물 생성 규칙을 소유하지 않는다. 실제 데이터가 생겼을 때만 추가 줄을 표시한다.

### 입력과 일시정지

- M은 열기/닫기, Esc는 지도 닫기, 좌클릭은 선택이다. 잠겨 있거나 이동 중이면 열리지 않는다.
- 지도 안에서 게임 입력(WASD·Space·Shift·Q·숫자·휠·R)과 카메라 입력을 막는다. UI·M·Esc는 `timeScale == 0`에서도 동작한다.
- `GamePauseReason`에 `MapOverlay`, `PlanetTransition`을 추가하고 **각 소유자의 AcquirePause/ReleasePause**를 사용한다. 닫을 때 `Time.timeScale = 1`로 직접 덮어쓰지 않는다.
- `PlayerController`의 현재 `Time.timeScale <= 0` 경로는 `ClearControls()`를 호출한다. 지도에 그대로 사용하면 활공·대쉬 중 상태가 취소될 수 있다. 기존 디버그용 Begin/Observe/End pause 경로를 공통 모달 입력 처리로 추출해 재사용하고, 지도 열기만으로 이동 자원·타이머를 바꾸지 않는다.
- 기존 `DeveloperDebugController.BlocksGameplayInput/BlocksMouseInput`에만 의존하는 소비자를 공통 모달 차단에 연결한다. 플레이어·카메라·양 소환·배치 미리보기가 모두 적용 대상이다. `OnDisable`로 플레이어 이동 컴포넌트를 끄는 방식도 피한다.
- 닫힌 프레임의 클릭·키 입력을 게임으로 전달하지 않는다. Space·Shift 등은 기존 디버그의 계속 누름/놓기 처리 원칙을 유지한다. 지도 안에서 새로 누른 입력을 닫은 직후 점프·대쉬로 사용하지 않는다.
- 커서는 지도에서 표시·잠금 해제하고, 닫을 때 저장한 상태로 복원한다. 게임 오버가 있으면 게임 오버의 커서 상태가 우선한다.
- 첫 구현은 지도와 F12 디버그 창을 동시에 열지 않는다. 지도 중 F12는 무시하고 먼저 M/Esc로 지도를 닫게 한다. 디버그 중 M도 무시한다. 게임 오버 중 기존 F12 디버그 동작은 유지한다.
- 지도/전환 소유권 해제는 자신의 토큰만 제거한다. 게임 오버·디버그가 소유한 pause를 지우면 안 된다.
- UI 비활성화·컨트롤러 파괴·전환 취소 시에도 자신이 가진 pause와 이벤트 구독을 정리한다. 지도를 닫을 때 이전에 비활성 상태였던 카메라·입력 컴포넌트를 임의로 켜지 않는다.

## 7. 클릭에서 다음 행성 도착까지

`RunProgressData.mode`는 지도 열기에서 `SelectingRoute`, 이동 준비에서 `Travelling`, 정상 도착에서 `PlayingPlanet`으로 바꾼다. 매프레임 다른 노드로 갱신하지 않는다.

### A. 요청 검증과 준비

1. 클릭한 ID가 현재 노드와 다른지, 실제 outgoing인지, 미방문인지, 지도 해금·게임 오버 조건을 다시 검사한다.
2. 이동 잠금을 걸고 `pendingDestinationId`를 설정한다. 이 순간부터 추가 클릭·M·Esc·F12로 전환을 바꾸지 못한다.
3. `PlanetTransition` pause를 먼저 얻고 지도 pause를 해제한다. pause가 없는 프레임이 끼어들지 않게 한다. 가림 화면은 unscaled 시간으로 표시한다.
4. 목적지의 **이미 확정된** 설정으로 새 지면을 준비하고 재질·Collider·투영 스폰·배치 가능 여부·참조 에셋을 검증한다. 이전 월드는 아직 파괴하지 않는다.
5. 준비 단계에서 새 `GravitySource`·Surge·Threat·양 AI가 자동 실행되지 않게 한다. Collider 검증에 새 월드 활성화가 필요하면 이전 지면 Collider를 잠시 비활성화하고 되돌릴 목록을 남긴다. 기존 행성의 개체·시계·양 상태는 그대로 동결한다.

### B. 성공한 목적지로 한 번만 확정

6. 검증 성공 후 현재 행성의 생성 경과·결과를 기록한다. 남은 바오밥이 있으면 `LeftWithRemaining`, 없으면 `Resolved`다.
7. 기존 행성의 양을 일괄 회수한다. **현재 손패의 동일한 카드 인덱스/향후 양 ID**를 반환하고 먹기 대상 점유·배치 미리보기를 정리한다. `startingCards`만큼 새로 지급하지 않는다.
8. 기존 Surge를 정지·정리하고 옛 지면·중력원을 비활성화한다. 공통 서비스의 `surface`, `spawnPoint`, 지면/중력 참조를 새 월드에 연결한다.
9. 플레이어를 새 표면 스폰으로 `Teleport/Respawn` 경로를 통해 배치하고 속도·접지 참조·입력 대기·이동 자원을 신규 도착 상태로 초기화한다. 카메라의 옛 참조와 보간 기록도 새 행성 기준으로 설정한다.
10. 이전 `phase = Departed`, 현재 ID 변경, 경로에 목적지 1회 추가, 목적지 `worldInitialized = true`, `phase = Surge`를 하나의 전환 확정 구간에서 적용한다. 목적지 시계·생성 진행은 0부터 시작한다.
11. 새 Surge를 **한 번만** 시작한다. `pendingDestinationId`를 비우고 지도·툴팁·해금 알림 상태를 닫힌 초기값으로 둔다. 옛 월드·소유 재질을 폐기한다.
12. 가림 화면을 걷고 전환 소유권을 해제한다. 다른 pause가 없을 때 게임이 재개된다. 새 행성에서는 다시 생성 시간 종료까지 M이 잠긴다.

현재 `LambAgent.OnDestroy()`도 `RecoverCard`를 호출한다. 일괄 회수와 파괴 콜백이 중복 지급하지 않도록 기존 `RecoverCard(index, agent)`의 소유자 검사를 유지하고, 회수 과정에서 모든 claims·deployed 목록이 비워지는 전용 경로를 둔다. 회수 알림은 개체별로 여러 번 띄울 필요가 없다.

이번 전환의 양 회수는 현재 시제품 손패의 유실 방지를 위한 규칙이다. 목표 기획의 '작물을 먹은 양은 다음 행성에서 쉼'은 작물 시스템과 함께 구현하고, 휴식 상태를 전환 때 임의로 지우지 않는다. F12의 기능 허용 체크 상태도 같은 여정의 행성 이동으로 초기화하지 않는다.

### C. 준비 실패

- 검증까지는 현재 ID·방문 경로·출발 상태·손패·자원을 바꾸지 않는다.
- 새 준비 월드만 정리하고 이전 Collider/중력원 등 일시 변경을 복원한다. `Physics.SyncTransforms()` 후 지도 참조를 확인한다.
- 지도 pause를 다시 얻은 뒤 전환 pause를 해제하고 `SelectingRoute`로 돌아간다. 툴팁을 숨기고 '행성을 준비하지 못했습니다. 다시 선택해 주세요.'를 표시한다.
- 같은 목적지를 다시 눌러도 크기·색을 재추출하지 않는다.
- 예상 가능한 실패는 재질·프리팹·지면·스폰 검증 단계에서 처리한다. 첫 구현에 옛 월드 파괴 뒤 전체 플레이 상태를 역생성하는 복구 시스템까지 만들지는 않는다.

## 8. 초기화·재시도와 종료 경계

- `BaobabSurge.Start()`는 현재 자동으로 `Begin()`을 호출한다. 데이터 주입 전 시작되거나 전환에서 두 번 시작되지 않도록 자동 시작을 분리하고, 흐름 컨트롤러가 시작을 소유하게 한다. 관리되는 경로와 기존 단독 데모의 자동 시작은 명시적으로 구분한다.
- 필요하면 준비/시작 API를 나눈다. 새 SurfaceGrid를 검증할 때 첫 싹·위험도·시계까지 돌리면 안 된다. Threat의 `LateUpdate`도 준비 중에는 평가하지 않도록 실행 상태를 명시한다.
- 바오밥 수량·시간·위험도는 이번에는 기존 시제품값(120초·40회·회당 1·동시 6·간격 1.4·한계량 100)을 유지한다. 크기별 수량 증가는 별도 `BaobabPlan` 정책으로 확장한다. 면적 4배가 곧 생성 수 4배인 것으로 구현하지 않는다.
- 일반 R 리스폰은 같은 행성의 플레이어만 재배치한다. 지도 해금·크기·색·생성 시계·손패·방문 경로를 새로 만들지 않는다.
- 게임 오버는 기존처럼 전체 시제품 씬 재시작을 사용한다. 현재 구현은 `SceneManager.LoadScene`하므로 첫 지도 시제품의 Enter/재시도는 **새 테스트 여정으로 초기화**하는 기본안이다. 같은 목적지 재도전·영구 저장을 구현했다고 표현하지 않는다.
- 씬 재시작에서는 이전 pause 소유자·대기 이동·커서·툴팁을 남기지 않는다. 기존 디버그 기능의 '씬 재시작 시 기본 허용값 복원' 정책을 유지한다.
- 도착 노드는 outgoing이 없다. 생성 시간이 끝나면 '테스트 항성계 완료' 상태를 표시하고 M으로 경로를 볼 수 있게 하되 이동 버튼은 없다. 이번 시제품의 완료 표시는 바오밥 완전 제거/양털 출구 통과와 별개이며, 남은 싹의 기존 성장·패배 판정은 유지한다.

## 10. 구현 순서와 완료 조건

1. 데이터와 고정 그래프를 먼저 만든다. 같은 seed의 외형 결과·ID·분기 재현성을 확인한다.
2. 지도 없이 지정한 `PlanetSpec`으로 기존 지면의 0.7/1.0/2.0 배율과 색을 적용하고 스폰·중력·카메라를 확인한다.
3. 생성 종료 해금 알림과 M 지도 열기/닫기, 공통 모달 입력 차단을 연결한다.
4. 고정 노드·links·현재 위치·선택 가능 표시·크기 hover를 연결한다.
5. 다음 행성 전환과 양 회수·서비스 초기화를 연결한다.
6. 마지막 노드·실패 복구·게임 오버/재시작까지 확인한다.

### 데이터·순서 검증

- 배율 경계 0.7/1.0/1.5/2.0의 크기 분류가 명세와 같고 범위 밖 데이터가 거부된다.
- 같은 데이터로 반복 생성해도 원본 기준 배율·팔레트가 같다. A→B→C에서 scale이 누적되지 않는다.
- 지도 재열기·hover·선택 재시도로 미래 행성 정보가 바뀌지 않는다. 지도 '소'가 실제 대형 행성으로 생성되지 않는다.
- outgoing이 아닌 ID 요청, 같은 노드, 재클릭·더블클릭은 이동을 만들지 않는다. 정상 전환 한 번에 경로가 정확히 1회 늘어난다.
- 의도적으로 템플릿/스폰 검증을 실패시켜 이전 행성·손패·경로·pause가 유지되는지 확인한다.

### 플레이 모드 확인

- 생성 중 M은 잠겨 있다. 생성 중 활성 싹 0개여도 해금되지 않는다.
- 생성 종료 후 남은 싹이 있어도 알림이 한 번 나오고 M으로 열 수 있다. 닫고 기다리면 위험도가 계속 증가한다.
- 생성 종료와 위험도 100%가 같은 프레임이면 게임 오버가 우선하고 지도·전환이 시작되지 않는다. 양 제거와 패배의 기존 프레임 순서도 유지한다.
- 지도에서 시간·위험도·먹기·더블점프/대쉬/활공 자원이 변하지 않는다. 닫은 클릭이나 Space/Shift가 게임 입력으로 새지 않는다.
- 지도와 F12를 반복해도 pause가 풀리거나 영구 정지하지 않는다. 해상도·UI 스케일을 바꿔도 툴팁이 화면 밖으로 나가거나 깜빡이지 않는다.
- 양을 전부 배치하거나 회수 가능한 상태로 둔 뒤 이동해도 원래 카드 수가 유지된다. 옛 양·먹기 점유·프리뷰·바오밥이 남지 않는다.
- 새 행성은 타이머·위험도·활성 수·슬롯 점유가 초기화되고 첫 싹이 한 번만 생성된다. 그 뒤 기존 동시 6개 제한이 유지된다.
- 0.7/2.0 행성의 여러 방향에서 걷기·경사 이동·점프·더블점프·공중 대쉬·활공이 동작하고 중력이 끊기지 않는다. 이전의 경사 접지/걷기 애니메이션 문제를 다시 만들지 않는다.
- 이동 도착 시 공중 자원은 정상 초기화되지만 디버그 허용 체크는 유지된다. 카메라가 옛 행성으로 보간하거나 크게 튀지 않는다.
- R은 월드를 다시 만들지 않고, 게임 오버 재시작은 테스트 여정·pause·UI를 정상 초기화한다. 마지막 노드에서 없는 다음 행성을 생성하지 않는다.

단순 DTO 필드 복사 검사를 늘리기보다 등급 경계·출발 허가·한 번만 확정되는 이동 같은 로직을 자동 검사하고, 지면·카메라·입력·양 회수는 실제 씬에서 검증한다. 긴 대기만 줄이려면 테스트용 설정에서 생성 시간을 일시적으로 줄이고 배포할 기본 설정은 복원한다.

## 구현 chat에 전달할 요청문

> `Docs/GameDesign.md`, `Docs/PlanetDataModel.md`, 이 명세를 먼저 읽고, 기존 `B612_EmptyPlanet`을 공통 씬으로 사용해 행성별 데이터 기반 지면 크기·색 변경과 항성계 지도·이동을 구현해줘. 크기는 원본 대비 선형 배율 0.7~2.0, 지도 hover는 소·중·대만 표시한다. 바오밥 생성 시간 종료 후 M 지도를 해금하고, 연결된 다음 노드 클릭으로 전환한다. 남은 싹이 있어도 이번 시제품에서는 출발할 수 있지만 게임 오버가 우선이다. 기존 pause 소유권·디버그·이동 기능·카메라·양 카드의 회귀를 막고, 런타임 코드 사본과 씬 연결까지 완료해줘. 세부 기본값은 문서의 제안안을 적용하되 실제 코드와 충돌하는 부분은 구현 전에 확인해줘.
