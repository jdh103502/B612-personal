## 1. 사용자 요구와 문서 우선순위

### 확정된 방향

- 행성 전체에 자연스러운 언덕·골짜기·분지와 강이 먼저 만들어진다.
- 사전에 계획하는 보행로, 보호 통로, 고정 우회로와 대쉬용 골짜기·더블점프용 턱·활공용 착지 코스 구분을 없앤다.
- 지형 때문에 이동이 지나치게 어렵다면 플레이테스트를 통해 생성 수치를 조금씩 완화한다.
- 대쉬·더블점프·활공과 챕터 해금은 유지한다. 자연 지형을 이동하는 방법으로 사용하며, 특정 능력을 반드시 쓰게 하는 지형 규격을 강제하지 않는다.

이 문서는 현재 플레이용 절차적 생성에 관한 과거 명세보다 우선한다. 특히 `ProceduralTerrainTraversalDesign.md`의 보호 보행로, 능력별 필수 코스, 고정 배치 복구, 해금 전후 지름길 통과를 강제하는 검증 조건은 새 생성 경로에 적용하지 않는다. 과거 실험 씬과 결과 문서는 비교 기록으로 보존한다.

### 이번 구현의 기본안

아래 알고리즘·수치·테스트 기준은 워커가 구현할 기본안이다. 사용자가 최종 재미나 난이도를 검증한 값은 아니다. 초기 구현은 **생성 후 개발자가 직접 플레이하며 설정을 조절하는 방식**이다. 런타임에서 막히는 곳을 자동으로 깎거나 전체 지형을 반복적으로 평탄화하는 기능은 이번 범위에서 제외한다.

## 2. 플레이 경험과 범위

플레이어는 특정 통로를 따라가는 대신 눈앞의 지형을 보고 이동 방향을 정한다. 능선 옆을 돌아가거나, 완만한 사면을 오르거나, 얕은 강을 건너는 선택이 자연스럽게 생겨야 한다. 능력 해금은 같은 지형을 더 빠르거나 편하게 이동하는 데 기여한다. 능력 해금 전후에 행성을 다시 생성하지 않는다.

이번 구현에 포함한다:

- 전역 연속 높이장, 지형을 따르는 강바닥·강둑·물 표면.
- 지형 생성 뒤 시작 위치와 기존 상호작용 지점·바오밥 후보 배치.
- 오브젝트 배치용의 보수적인 이동 가능 영역 추정. 이 분석으로 지면에 길을 만들지 않는다.
- 같은 seed로 비교할 수 있는 설정·생성 기록과 기존 실제 플레이 경로 연결.

새 작물 경제·NPC 퀘스트·수영·익사·동굴·오버행·교량·침식 시뮬레이션·자동 지형 보정·새 디버그 UI는 추가하지 않는다. 기존 얕은 물의 보행 감속과 이동 조작 수치는 유지한다.

## 3. 전체 생성 순서

```text
행성 데이터와 생성 설정의 스냅샷
  → 구면 전체의 연속 높이장
  → 높이를 따라 강 경로 선택
  → 강바닥·강둑 합성 및 물 표면 계획
  → 최종 지면 메시·MeshCollider 생성
  → 표면의 경사·여유 공간·이동 연결성 분석
  → 안전한 시작 위치 선택
  → 연결된 영역에서 해금 지점·기존 조사/만남 지점 선택
  → 같은 영역으로 바오밥 생성 후보 제한
  → 월드 준비 성공 후 기존 여정 전환 확정
```

분석에서 생기는 연결 그래프는 오브젝트 배치를 위한 내부 자료다. 그래프 간선을 평평한 띠, 경사로, 보호 구역이나 화면의 길 안내선으로 변환하지 않는다.

## 4. 전역 지형 생성

### 4.1 구면 전체에서 하나의 높이 함수를 사용

행성 로컬 좌표에서 단위 방향을 `d`, 기준 반경을 `R`이라 하면 다음 구조로 만든다. `N1`, `N2`는 독립된 seed의 연속 3D 노이즈이고, 출력 범위는 대략 -1~1로 맞춘다.

```text
p = d × R
h(d) = broadAmplitude × N1(p / broadScale + offset1)
     + mediumAmplitude × N2(p / mediumScale + offset2)
최종 위치 = d × (R + h(d))
```

- 타일마다 독립적인 높이를 추첨하지 않는다. 같은 위치는 타일·메시 경계와 관계없이 같은 높이를 반환한다.
- 큰 굴곡이 지형을 만들고 중간 굴곡은 약하게 변주한다. 초기에는 두 층으로 제한한다. warp·ridge·고주파 자글거림은 비활성으로 시작한다.
- 기존 `TerrainLandforms`의 언덕 2개·분지 1개를 새 지형 위에 다시 얹지 않는다. 분지와 능선은 연속 높이장의 낮고 높은 영역에서 형성된다.
- 보행로·스폰 방향·능력 코스와의 거리로 높이를 0에 가깝게 만드는 처리를 제거한다.
- 필요하면 지역 가중치를 넓고 부드럽게 섞을 수 있지만, 최초 구현은 두 노이즈의 합으로 완료한다. 지역마다 독립된 둔덕을 생성하는 우회 구현은 하지 않는다.

### 4.2 최초 설정값

반경 12m를 기준으로 다음 값을 출발점으로 사용한다. Scale은 노이즈 좌표의 공간 크기이며 언덕 사이의 정확한 거리나 개수를 보장하는 값은 아니다.

| 설정 | 시작값 | 튜닝 시 의미 |
| --- | ---: | --- |
| `broadScaleMeters` | 12m | 넓은 기복의 공간 크기 |
| `broadAmplitudeMeters` | 1.4m | 넓은 기복의 진폭 |
| `mediumScaleMeters` | 5m | 중간 굴곡의 공간 크기 |
| `mediumAmplitudeMeters` | 0.3m | 중간 굴곡의 진폭 |
| `warpStrength` / `ridgeStrength` | 0 | 초기에는 추가하지 않음 |

작은 행성은 `q=min(1, R/12)`를 위의 두 Scale과 두 Amplitude에 함께 곱한다. 이는 작은 공통 행성에서도 비슷한 상대 경사를 유지하기 위한 초기 기본안이다. R이 12m 이상이면 물리적인 굴곡 크기를 고정해 큰 행성에 더 많은 굴곡이 등장하게 한다. 플레이어·양·싹·텍스처 반복 길이와 논리 타일 크기는 이 q로 확대·축소하지 않는다.

진폭 합은 높이 예산 `min(2m, 0.17×R)` 안에 둔다. 설정이 예산을 넘으면 두 진폭을 같은 비율로 줄여 사용하고 기록한다. 정점별 높이를 잘라 평평한 꼭대기·바닥을 만드는 방식은 사용하지 않는다. 작은 진폭은 별도 스냅샷에 기록해 같은 seed에서 재현한다.

### 4.3 크기·분포·표면 표현

- 기존 0.7~2배 범위, 행성 데이터의 반경, 크기에 따른 논리 타일 수 증가를 유지한다.
- 시작·일반·도착 행성 모두 새 자연 지형 경로를 사용한다. 시작 행성이라는 이유로 능력 코스를 남기거나 자동으로 평평하게 만들지 않는다.
- 배치 seed와 지형 seed를 분리한다. 오브젝트 후보 수가 변해도 지형이나 강 모양이 달라지지 않게 한다.
- 선택된 실제 프로필·보정된 수치·파생 seed를 Plan에 스냅샷으로 남긴다. R 리스폰과 동일 행성 재생성은 같은 결과를 사용한다.
- 현재 잔디·흙 Base Color/Normal, 행성 대표색, 고도·경사·강가의 재질 혼합을 유지한다. 기존 정점 색 채널의 역할을 확인하고 새 지형에서 필요한 값을 갱신한다.
- 렌더 메시와 충돌 메시, 강바닥 조회와 실제 물 표면이 동일한 확정 Plan을 사용한다. 메시를 만든 뒤 Plan만 바꿔서는 안 된다.

## 5. 강 생성

### 5.1 기본 방식

기존 `TerrainWater.Plan`은 예약 보행로를 가로지르는 위치와 고정 여울을 기준으로 계획한다. 이를 **기존 지형의 낮은 방향을 따르는 물길**로 교체한다. 물 표면·강바닥 샘플링과 얕은 물 감속 처리는 가능한 범위에서 재사용한다.

1. 초기 높이장의 표면을 분석하고 비교적 높은 후보 중에서 수원을 고른다. 습윤도는 후보 우선순위에만 사용해도 된다.
2. 주변의 더 낮은 표면으로 이동하며 중심선을 만든다. 여기서 높이는 행성 중심으로부터의 방사 고도이며 월드 Y가 아니다.
3. 낮은 분지에 도착하거나 목표 길이에 도달하면 끝낸다. 닫힌 구면에는 지도 바깥 출구가 없으므로 무조건 바다까지 이어지게 만들지 않는다.
4. 중심선을 완만하게 다듬은 뒤, 낮은 방향과 강둑 조건을 다시 확인한다. 평활화 때문에 언덕을 가로질러 흐르면 해당 후보를 버린다.
5. 중심선 주변을 파서 강바닥과 넓은 강둑 전이를 만들고, 그 안에 물 표면을 배치한다. 강 양쪽 지면과 매끄럽게 접합한다.

### 5.2 최초 설정과 제한

| 설정 | 반경 12m 기준 시작값 |
| --- | ---: |
| 물길 목표 개수 | 1개 |
| 중심선 목표 길이 | 8~18m |
| 물 표면 폭 | 0.9m |
| 물 표면에서 강바닥까지 깊이 | 0.12~0.20m |
| 물 가장자리에서 주변 지형으로 이어지는 강둑 전이 폭 | 한쪽 1.2m |
| 수원 후보 시도 상한 | 64회 |
| 중심선 추적 상한 | 256단계, 방문 지점 재방문 금지 |

길이·폭·깊이·전이 폭에는 4.2절의 q를 적용한다. 상한 도달 시 무한 탐색하지 않고 해당 후보를 종료한다. 최초 범위에서는 분기·합류·호수 시스템까지 만들지 않는다. 강 끝은 주변의 낮은 지형에 자연스럽게 접합하고, 별도의 호수 시스템 없이 처리할 수 있다.

- 수면 고도는 하류로 갈수록 증가하지 않아야 한다. 순환 경로, 공중에 뜬 물, 강둑보다 높은 물, 지면을 뚫고 튀어나온 물 조각이 있으면 실패 후보다.
- 교차 지점을 정해 강을 강제로 얕게 만드는 `fordIndex`와 보호 여울을 제거한다. 기본적인 얕은 폭·깊이와 자연 강둑으로 횡단할 수 있도록 테스트한다.
- 자연 지형에 적합한 강을 만들지 못하면 강을 억지로 예약 통로에 놓거나 전체 행성을 평탄화하지 않는다. 실패 이유를 기록하고 그 표본은 강 검증 미완료로 보고한다. 납품 검증 표본에서 강이 모두 빠진 상태는 완료가 아니다.
- 한 물길로 먼저 완료한다. 여러 물길은 이후 개수·간격·합류 처리를 확장할 수 있도록 자료를 분리하되 이번 작업에서 필수로 늘리지 않는다.

## 6. 시작 위치·상호작용·바오밥 배치

### 6.1 오브젝트 배치용 연결성 분석

모든 산 정상이나 지형 정점을 기본 이동으로 방문하게 만드는 것은 이번 목표가 아니다. 게임 진행과 바오밥 대응에 필요한 오브젝트가 놓이는 위치를 우선한다. 기본 배치 판정에는 대쉬·더블점프·활공을 요구하지 않는다.

최종 Collider 위에 표면 샘플을 만들고, 발판·경사·캡슐 여유 공간과 이웃 간 이동 가능성을 검사해 보수적인 도보 연결 영역을 구한다.

- 기존 논리 타일은 분포와 후보 관리에 사용한다. 타일 중심의 높이 차만으로 도달성을 판정하지 않는다.
- 분석용 샘플 간격은 약 0.6m에서 시작하고, 최대 노드 수는 30,000개를 출발 상한으로 둔다. 플레이어 캡슐, 강 폭과 비용을 확인해 조절한다. 렌더 메시의 모든 정점에서 모터를 시뮬레이션하지 않는다.
- 경사는 월드 위쪽 대신 방사 방향과 기하 노멀로 계산한다. 초기 배치 경사 상한은 `min(35도, 실제 모터 maxGroundAngle−5도)`를 사용한다.
- 이웃 사이도 중간 지면·단차·급경사·캡슐 통과 공간을 확인한다. 바위 반대편이나 골짜기 건너편을 직선 거리만으로 연결하지 않는다.
- 왕복이 가능한 간선으로 연결 영역을 구한다. 내려갈 수만 있고 되돌아올 수 없는 영역을 안전한 배치 영역으로 합치지 않는다.
- 얕은 물의 강바닥은 기존 감속 규칙으로 보행할 수 있으면 연결성 분석에 포함할 수 있다. 오브젝트 자체는 물 안에 배치하지 않는다.

이 분석은 **도보 연결성의 보수적인 추정**이다. 실제 입력·마찰·단차와 모든 점프를 증명하는 장치는 아니다. 최초 구현에서 점프·대쉬·활공을 조합하는 자동 경로 탐색까지 추가하지 않으며, 최종 접근·복귀는 플레이테스트로 확인한다. 그래프 결과만으로 실제 이동 검증을 통과했다고 기록하지 않는다.

### 6.2 배치 순서

1. 충분한 공간을 가진 연결 영역을 고른다. 같은 조건이면 안정적인 ID 순서로 결정한다.
2. 해당 영역에서 기존 선호 스폰 방향에 가까운 안전한 지점을 선택한다. 평탄한 통로나 스폰용 지형을 먼저 만들지 않는다.
3. 플레이어 캡슐의 실제 크기·회전·여유 높이로 겹침과 착지를 확인한다. 선택한 방향·위치·노멀을 Plan에 남긴다.
4. 같은 연결 영역에서 기존 해금 기둥과 조사/만남 지점을 선택한다. 기존의 고정 대원 경로 비율 좌표는 사용하지 않는다. 지점 간 간격은 2m에서 시작하고 작은 행성에서도 캡슐과 모델이 겹치지 않게 한다.
5. 확정된 해금 지점에는 현재 데이터의 해금 능력을 그대로 연결한다. 챕터 1의 해금 전 상태에서도 도달할 수 있어야 한다.
6. `PlanetSurfaceGrid`의 최종 생성 후보에도 같은 연결 영역과 기존 경사·수면·점유 조건을 적용한다. 접근할 수 없는 섬이나 급경사에 바오밥을 배치하지 않는다.

선택된 연결 영역은 전체 지표의 약 60% 이상을 차지하는 것을 초기 배치 기준으로 둔다. 면적은 샘플 개수만 세기보다 구면 표본의 면적 가중치로 추정한다. 이 값은 `minConnectedAreaRatio`와 같은 설정으로 노출하는 검증 전 기본안이다. 미달하거나 기존 최대 동시 바오밥 수량과 상호작용 지점을 수용하지 못하면 준비 실패로 보고한다. 작은 고립 구역에만 오브젝트를 몰아 넣어서 문제를 숨기지 않도록, 연결 영역 면적 비율과 후보 분포도 결과에 기록한다. 분석 해상도 때문에 과도하게 영역이 끊겼다면 실제 지면과 분석 간선을 먼저 확인하고, 분석 오류를 지형 난이도 문제로 단정하지 않는다.

배치 후보 탐색에는 상한을 두고 실패 이유를 남긴다. 기본 상한은 지점당 64후보다. 실패 시 높이를 실시간으로 낮추거나 seed를 몰래 바꿔 재추첨하지 않는다. 새 월드 준비 실패에서는 기존 여정과 월드를 보존하는 전환 계약을 유지한다.

## 7. 플레이테스트와 수치 조절

### 7.1 같은 조건으로 문제를 재현

테스트 기록에는 여정 seed·행성 seed/ID·크기·반경·생성기/프로필 버전·스폰 방향·이동 능력 상태·설정값을 남긴다. 실패 위치는 월드 위치뿐 아니라 행성 로컬 단위 방향으로도 남긴다. 그래야 행성 위치가 바뀌어도 같은 곳을 찾을 수 있다.

처음에는 기본 보행과 일반 점프로 탐색하고, 이어 같은 지형에서 대쉬·더블점프·활공을 사용해 조작감을 비교한다. 해금 능력의 사용을 강제하는 통과 조건이나 해금 후 시간 이득의 합격 기준은 만들지 않는다. 접근뿐 아니라 내려온 곳에서 다시 나갈 수 있는지도 확인한다.

### 7.2 원인별로 한 항목씩 조절

| 실제 문제 | 먼저 조절할 값 | 확인할 부작용 |
| --- | --- | --- |
| 넓은 언덕을 오를 수 없음 | broad 진폭 5~10% 감소 또는 broad Scale 5~10% 증가 | 전체 실루엣과 기복 밀도 감소 |
| 작은 요철에 걸리거나 이동이 튐 | medium 진폭 감소 | 지형 전체를 평평하게 만들 필요가 없는지 |
| 분지에서 빠져나올 수 없음 | 전체 진폭 감소, 필요 시 낮은 고도 구간을 완만하게 하는 연속 곡선 | 바닥만 평평하게 잘리거나 모든 분지가 사라지지 않는지 |

5~10%는 조절 폭의 출발 제안이다. 매번 한 계열만 바꾸고 같은 seed·같은 크기·같은 능력 상태로 재생성해 비교한다. R이 단순 리스폰만 한다면 설정이 다시 적용되는 월드 재생성/Play 재시작 경로를 사용한다. 현재 월드의 확정 Plan을 실행 중에 일부만 수정하지 않는다.

수치를 변경한 뒤에는 원래 실패 seed 외에 다른 seed와 작은/큰 행성도 확인한다. 전체 진폭을 계속 낮추어 구형에 가까워지는 결과가 나오면 그 시점을 기록하고, 강둑·중간 굴곡 등 실제 원인부터 다시 분리한다. 국소 보정이나 실행 중 자동 완화는 후속 확장 항목이며 이번 구현의 필수 사항으로 추가하지 않는다.

### 8.1 설정과 자료

`NaturalTerrainSettings`와 같은 직렬화 설정을 `PlanetGenerationSettings`에 두고 지형·강 조절값을 모으는 구성을 권장한다. 기존 외관 설정의 팔레트·텍스처 값은 유지한다. 필드 이름을 바꾸더라도 Inspector에서 조절한 값이 실제 생성에 사용되고, 유효성 검사와 Plan 스냅샷에도 같은 값이 들어가야 한다.

자연 지형 Plan에는 최소한 다음을 기록한다:

- seed, generatorVersion, profileId, 반경, 확정된 두 노이즈의 수치와 파생 seed.
- 강 중심선·수면/바닥 고도·폭·깊이·전이 폭과 후보 실패 이유.
- 선택된 스폰, 오브젝트 후보/선택 위치, 배치용 연결 영역 정보.
- 분석 시간·노드 수·후보 수·면적 비율·안전 판정 실패 사유.

기존 생성기 버전이 7인 상태에서 구현하면 다음 버전으로 증가시키고 자연 지형을 구분하는 프로필 ID를 사용한다. 다른 작업으로 이미 버전이 증가했다면 최신 값 다음을 사용한다. 여정/행성 데이터의 기본 형식을 불필요하게 변경하지 않고, 같은 seed라도 생성기 변경 전후 형상이 다를 수 있음을 결과에 명시한다.

## 9. 검증과 완료 조건

### 9.1 생성 표본과 화면

여정 seed 612101·1·77을 사용해 일반 행성의 0.7·1·1.5·2배, 총 12개 조합을 비교한다. 행성 seed와 역할도 기록한다. 이 중 1배와 2배는 같은 데이터·구도의 적용 전후 화면을 남긴다. 별도로 시작·도착 행성, 기존 반경 5.3m를 기준으로 하는 공통 생성의 작은/큰 행성도 준비해 예외가 없는지 확인한다.

단순 확대 화면뿐 아니라 실제 카메라, 행성 전체, 반대편을 포함한다. 높이 색 진단이나 최종 Collider 높이 샘플을 사용해 텍스처 무늬와 실제 굴곡을 구분한다. 새 디버그 패널을 만들 필요는 없다.

균등한 구면 방향으로 높이를 샘플링해 P10/P50/P90과 최솟값·최댓값을 기록한다. 큰 구역별 높이 범위도 비교한다. 초기 시각 조절 목표는 전체 P90−P10 약 `0.7×q m` 이상이며, 정이십면체의 큰 20구역 중 약 14구역 이상에서 `0.35×q m` 이상의 높이 범위가 읽히는 것이다. 이 값은 **수동 튜닝 가이드**이며, 매 생성마다 강제로 만족시키려고 지형을 반복 수정하는 런타임 조건이 아니다. 미달 표본과 최종 조절값을 솔직하게 기록한다.

### 9.2 실제 이동과 진행

- 0.7·1·2배 중 대표 표본에서 기본 이동으로 언덕을 오르내리고 분지에서 복귀하며 강을 양방향으로 건넌다. 그래프 판정과 실제 결과가 다르면 둘을 따로 기록한다.
- 첫 챕터 해금 전 상태에서 해금 지점에 접근해 E로 능력을 얻는다. 같은 지형에서 각 능력이 정상 동작하고 착지 시 자원이 회복되는지 확인한다.
- 바오밥이 허용된 후보에 생성되고 양으로 처리·회수되는지 확인한다. 물이나 접근 불가 영역에 생성된 사례는 실패로 기록한다.
- 실제 여정에서 세 챕터의 시작·일반·도착 행성을 방문한다. 기존 F12 스킵으로 대기 시간을 줄일 수 있지만 지도·해금·전환 자체를 우회한 것으로 검증을 대신하지 않는다.
- R 리스폰, M 지도 이동, F12 기능 허용과 일시정지, 전환 실패 보존 및 떠난 월드 자원 해제를 확인한다.
- Windows 개발 빌드에서 새 지형·잔디/흙·강이 표시되고 시작 및 다음 행성 이동이 동작하는지 확인한다. 에디터 확인과 빌드 확인 범위를 구분한다.

| 이전 개념 제거 | 플레이용 지형 생성·배치·검증에서 예약 보행로와 능력별 필수 코스를 사용하지 않는다. 길 안내선과 해당 코스 안내도 남아 있지 않다. |

| 조절 가능성 | Inspector의 지형·강 수치를 바꾸고 같은 seed를 다시 생성하면 바뀐 수치가 적용된다. 실제 사용한 스냅샷과 실패 위치를 재현할 수 있다. |

결과 문서는 `Docs/NaturalPlanetTerrainImplementationResults.md`에 작성한다. 확인한 seed·크기·씬·빌드·스크린샷, 최종 파라미터, 연결 분석의 한계와 남은 수동 튜닝 항목을 포함한다. 새 구조의 구현 완료와 최종 재미/난이도 검증 완료를 구분한다.

## 10. 구현 순서

1. 현재 작업과 설정을 보존하고 적용 전 화면·생성 시간·기본 기능을 기록한다.
2. 자연 지형 프로필과 전역 높이장을 연결한다. 새 생성 경로의 통로 평탄화·원형 둔덕·필수 코스 호출을 제거한다.
3. 지형 기반 강과 최종 지면/물/Collider를 연결한다.
4. 배치용 표면 분석과 스폰·기존 상호작용·바오밥 필터를 연결한다.
5. 능력별 코스 요구, 기존 강의 여울 전제, 고정 좌표 배치와 길 안내선을 정리한다.
6. 실제 세 생성 설정과 메인 플레이에 반영하고, 같은 seed의 수동 튜닝·회귀·빌드를 확인한다.

각 단계는 구현 순서다. 이번 요청의 납품 범위는 6단계까지이며 전역 노이즈만 구현한 실험 씬에서 중단하지 않는다. 별도 자동 보정·네비게이션 시스템까지 범위를 넓히지 않는다.

## 11. 워커 전달용 프롬프트

> `C:\Dev\B612\Docs\NaturalPlanetTerrainImplementationSpec.md`를 기준으로 실제 게임에 구현해줘. 현재 작업 폴더의 변경을 보존하고, 전역 연속 지형과 지형을 따르는 강을 먼저 생성하도록 바꿔줘. 예약 보행로·고정 우회로·대쉬/더블점프/활공 전용 코스와 그 강제 검증·길 안내선을 플레이용 생성에서 제거해줘. 지형 생성 뒤 안전한 스폰과 기존 해금/조사/만남 지점, 바오밥 후보를 배치하고, 배치용 연결 분석을 지형을 깎는 기능으로 사용하지 말아줘. 능력·챕터 해금·기존 조작·물 감속·바오밥·양·지도·R/F12와 텍스처를 유지해줘. 설정을 노출해 같은 seed로 수동 튜닝할 수 있게 하고, 런타임 자동 지형 보정은 추가하지 말아줘. 명세의 1~6단계를 메인 플레이와 세 생성 설정에 연결하고, 대표 seed/크기와 Windows 빌드 검증 후 `Docs/NaturalPlanetTerrainImplementationResults.md`에 전후 화면·최종 수치·확인 범위·남은 문제를 기록해줘.
