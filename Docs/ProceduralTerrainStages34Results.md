# 절차적 지형 3~4단계 구현·검증

2026-11-11. `ProceduralTerrainTraversalDesign.md` 15절의 3~4단계를 대상으로 한 이동·성장 시제품이다. 1단계 고정 실험실과 2단계 생성 비교 씬을 유지한다.

## 실행

- 씬: `Assets/B612/Scenes/B612_ChapterJourney.unity`.
- WASD 이동, Space 점프/추가 점프/홀드 활공, Shift 대쉬, R 현재 행성 리스폰.
- 금색 기둥에 다가가 지면에 선 상태에서 E: 해당 챕터 능력 해금. 민트색 선은 기본 보행 통로와 장애물 우회로다.
- 초록색 작물 조사·파란색 안내 지점에서 E: 방문 기록과 도착 이후 게임 시간·보행 거리 기록.
- 바오밥 생성 종료 후 M: 연결된 미방문 행성 선택. 잠긴 능력이 필요한 출발은 해금 후 가능하다.
- 도착 행성에서 생성 종료 후 M → 다음 챕터로. 3챕터 도착 행성에서는 여정 완료를 표시한다.
- 빠른 확인: F12 → 바오밥 페이즈 스킵 → 닫기 → M. 체크박스는 정식 해금된 능력에만 적용한다.

## 3단계: 연결 지역과 물길

`TerrainRegions`는 구면 방향을 입력으로 고도 E, 거칠기 Q, 습윤도 M을 서로 다른 seed 흐름에서 계산한다. 챕터의 평지/언덕/골짜기 기본 가중치에 필드 적합도를 적용해 6~18개의 분산된 지역 씨앗을 선택하고, 실제 타일 이웃을 따라 제한된 다중 시작점 영역 확장을 수행한다. 각 타일의 지역·씨앗·부모·E/Q/M·보호 통로 정보를 생성 계획에 남긴다. 가중치는 면적의 정확한 할당 비율이 아니다. 작은 표본에서 특정 지형이 없을 수도 있다.

표시/충돌 형상은 타일별 높이를 붙이지 않고 구면 방향의 연속 필드와 부드러운 지역 커널을 사용한다. 논리 타일 경계와 무관한 공유 정점 메시이며, 지면 MeshFilter와 MeshCollider는 같은 최종 메시를 참조한다. 원본 팔레트와 지면 색 적용은 유지한다.

`TerrainWater`는 별도 습윤도 후보와 방사 방향 고도를 사용해 짧은 상류→하류 분지의 연속 중심선 21개를 정한다. 강 폭 0.9m, 깊이 0.04~0.16m로 시작하며 기본 통로의 여울은 바닥 고도 −0.06m/물 −0.02m다. 곡률을 따른 강바닥과 매끄러운 물가를 지면 높이에 합성하고, 물 표면은 별도 소유 메시로 표시한다. 물 Collider는 만들지 않는다.

얕은 물에 지면을 딛고 있을 때 보행 목표 속도는 0.65배다. 점프·대쉬·체공 자원은 별도 규칙을 유지하며, 물 표면 위에 발판이 생기지 않는다. 강이 장애물/스폰/상호작용 공간을 침범하거나 안전한 높이 보정 예산을 넘으면 최대 128번의 후보 검사 뒤 제외한다. 수영·유체·침식·동굴·다층 다리는 구현하지 않았다.

## 4단계: 챕터와 정식 해금

`ChapterTerrainDefinition` 에셋 3개로 진입 보장 능력·보상·지역 가중치·요소 예산을 나눈다.

| 챕터 | 진입 능력 | 시작 행성 현장 해금 | 평지/언덕/골짜기 기본 가중치 |
| --- | --- | --- | --- |
| 1 | 보행·일반 점프 | 대쉬 | 65 / 25 / 10 |
| 2 | 대쉬 | 추가 점프 | 50 / 30 / 20 |
| 3 | 대쉬·추가 점프 | 활공 | 45 / 30 / 25 |

이는 설계안에서 선택한 변경 가능한 기본값이다. 이번 시제품은 챕터당 기존 6노드·7링크 DAG 하나를 사용한다. 각 행성의 seed·색·크기와 챕터 조건을 미리 확정하고, 챕터 시작 행성의 기본 통로 18% 지점에서 E로 1회 해금한다. 기본 통로의 42%/72%에는 작물 조사·안내 지점을 둔다. 모든 지점은 최종 Collider에 투영하고 추가 발판 Collider를 만들지 않는다.

`RunProgressData.unlocked`가 정식 해금을 소유한다. 실제 능력 허용은 해금 AND 개발 Allow다. 개발 체크박스만으로 잠긴 능력을 배울 수 없으며, 해금 때 이동 자원을 무료로 재충전하지 않는다. 리스폰·행성·챕터 이동에서 해금과 개발 허용을 유지한다. 새 Play와 패배 재시도는 새 여정이다. 파일 저장·복원은 없다.

기본 동선은 능력 없이 보행으로 통과한다. 익숙한 4.2m 골짜기·2m 턱과 후반 7m 기준 활공 구간을 고정 월드 크기로 사용한다. 충분히 큰 3챕터 행성에 활공 출발대·낮은 착지대·복귀길을 배치하고, 작은 행성에서는 큰 요소를 제외한다. 능력 증가에 따라 모든 장애물을 확대하지 않는다.

해금·지도·다음 챕터 요청은 게임오버 확정 후 처리한다. 다음 월드 준비가 성공하기 전에는 현재 챕터·항성계·경로·양 카드를 변경하지 않는다. 성공하면 지난 항성계 객체와 선택 경로를 보존하고 같은 카드로 회수한다. 각 챕터의 지도는 재구축하되 EventSystem은 재사용한다. 기존 시제품처럼 생성 종료 후 잔여 바오밥이 있어도 출발할 수 있으며 잔여 위협은 계속 패배를 일으킬 수 있다.

## 이동 검사와 복구

최종 지면 Collider를 격리된 PhysicsScene에 복사하고 현재 씬의 실제 플레이어 캡슐·이동/능력 설정으로 검사한다. 기본 통로 양방향, 요소별 우회 양방향·골짜기 탈출을 보행으로 확인한다. 지름길은 기본 점프로 실패하고 해당 능력으로 성공해야 하며, 실제 틱으로 측정한 지름길 시간이 우회보다 짧아야 채택한다. 결과는 계획의 `mainRouteSeconds`, `traversalCosts`에 남긴다. 착지에 따른 자원 회복은 기존 모터가 처리한다.

실패 시 해당 요소 제거 → 필요시 강 제거 → 지역/요철 없는 안전 평지의 순서로 유한하게 보완한다. 메시 준비는 최대 5회이며 여전히 실패하면 현재 행성으로 복구한다. 최종 형상 뒤에만 바오밥 후보를 준비하고 물가·주요 통로·상호작용 지점·요소 예약 공간을 제외한다. 지도 재열기·F12·해금은 지형을 재생성하지 않는다. 지면/물 메시·소유 재질은 실패/전환/종료 시 해제한다.

생성기 4, 데이터 형식 1, 프로필 `terrain.regional.v1`이다. 이전 생성기 입력은 거부한다. 예전 결과 문서의 버전/물길 미구현 설명은 당시 2단계 기록이다.

## 검증 기록

검증 도구는 `AgentScripts/ChapterJourneyValidation.cs`, `AgentScripts/ChapterJourneySceneValidation.cs`다. 결과는 `Temp/ChapterJourney`에 남긴다.

- 3챕터 × seed 612101/1/77 × 0.7/1/1.5/2배의 계획 **36건 통과**. 지역 부모 연결·타일 개수·정확한 seed 재현·내리막 물길·여울·물 메시/노멀·높이를 고려한 감속을 확인했다. 34건에 강, 9건에 활공 요소가 배치됐다. 강 생략은 유한 후보 검색의 정상 결과다.
- 각 챕터의 0.7/1/2배 **최종 월드 9건 통과**. 이 표본은 모두 1회 준비에 성공했다. 기본 통로 왕복·각 요소 우회/복귀·기본 실패/능력 성공·시간 이득·공유 충돌 메시·안전 바오밥 후보를 확인했다. 크기에 따라 약 0.66/1.27~1.35/4.80~4.88초였다. 큰 행성은 준비 중 화면 정지가 수 초 발생할 수 있으며 비동기 생성 최적화는 하지 않았다.
- 1배 기준 대쉬 우회 8.82초→지름길 3.22초, 추가 점프 9.60초→3.76초, 활공 12.48초→5.46초. 최적 기록이나 사람의 플레이 시간이 아니라 동일 모터의 제어된 0.02초 틱 비교다.
- **실제 씬 3챕터 연속 통과**. 가상 키보드 E로 각 시작 행성 해금, 잠긴 개발 체크박스·중복 보상 차단, 작물 조사/안내 방문, R 뒤 해금/개발 허용 유지, 다른 분기 선택, 총 11회 전환·12행성 경로·이전 항성계 2개 보존, 최종 완료·4챕터 차단·EventSystem 1개를 확인했다. 위치 이동은 해금 입력 검사의 준비에만 사용했고 지형 통과 검사는 별도 실제 모터 검사다.
- 다음 챕터 준비의 지면 템플릿을 일시 제거해 실패를 주입했다. 현재 월드·메시·챕터·경로·해금을 유지하며 지도로 돌아왔고, 템플릿 복원 후 정상 진입했다. 에셋에는 잘못된 설정을 저장하지 않았다.
- `ChapterJourneyEdgeValidation.cs`로 잠긴 실제 모터의 추가 점프/대쉬 차단, 해금 뒤 자원 소비와 다시 잠글 때 자원 미회복, 같은 프레임 게임오버에 의한 대기 해금 취소도 통과했다. 새 씬은 Build Settings에 등록해 씬 재시도가 가능함을 확인했다.
- 이 에디터 세션은 포커스 없는 Play 루프가 멈춰, CLI로 Editor 프레임 진행·일시정지 해제와 입력 업데이트를 수행했다. 실제 Update/LateUpdate·물리·전환 코루틴을 진행하며 검사했으며 Computer Use는 사용하지 않았다. 화면은 CLI 캡처와 카메라 재렌더링으로 확인했다.

보관한 원시 결과와 최종 화면은 `Artifacts/ChapterJourney`에 있다. 화면 검토 뒤 Play를 종료하고 백그라운드 실행 설정을 원복했으며, 새 씬은 저장된 Edit 상태로 남겼다.

## 적용 범위

바오밥 120초·동시 6개·위험도·양 먹기 시간·모델·먹기 진행 UI와 카메라를 그대로 사용한다. 작물 조사와 안내는 이동 비용을 관찰하기 위한 실제 방문 상호작용이다. 작물 수확·양털 지급/소비·NPC 대화/퀘스트 경제·최종 B612 이야기까지 구현했다는 뜻은 아니다. 그 내용은 기존 목표 기획의 후속 기능이다.

고정 시드·크기 표본의 자동 이동 검사는 모든 플레이어 조작·모든 seed의 안전이나 재미를 보증하지 않는다. 2분 위협과 수확/퀘스트 경제가 통합된 최종 난이도, 장시간 체감·카메라 가림의 수동 플레이 평가는 계속 조정해야 한다.
