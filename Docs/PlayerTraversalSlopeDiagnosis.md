## 1. 접지 기준의 방향과 문턱이 잘못 결합됨

현재 `GravityWalker.cs`의 `TickTraversal`:

```csharp
Vector3 gravityUp = pull.sqrMagnitude > .000001f ? -pull.normalized : Up;
bool support = TraversalSupport(gravityUp, out var hit);
Grounded = support && (
    Vector3.Dot(velocity, gravityUp) <= .05f
    || traversal.CanFollowGroundDash(velocity, previousUp)
);
```

`gravityUp`은 행성 중심에서 바깥을 향하는 방향이며, `hit.normal`은 실제 지면의 법선이다. 울퉁불퉁하거나 위쪽이 평평해진 행성에서는 두 방향이 다르다.

순수하게 경사면을 따라 이동해도 `Dot(velocity, gravityUp)`은 양수가 될 수 있다. 이것만으로 발이 바닥에서 떨어졌다는 뜻은 아니다.

예를 들어 중력 반대 방향이 `(0, 1, 0)`이고 20도 경사를 2m/s로 걸어 오르면:

```text
이동 속도 = (2cos20°, 2sin20°, 0) ≈ (1.879, 0.684, 0)
중력 반대 방향 속도 = 0.684m/s
현재 조건 = 0.684 <= 0.05 → false

지면 법선 = (-sin20°, cos20°, 0)
지면 법선 방향 속도 = Dot(이동 속도, 지면 법선) = 0
```

즉, 지면을 전혀 이탈하지 않는 이동도 현재 조건에서는 공중으로 판정된다. 하향 접지 힘을 일부 더해도 이 예시의 양의 성분은 0.05m/s보다 훨씬 크다. `maxGroundAngle = 60` 안쪽인 20도 경사에서도 발생할 수 있어 경사 허용각만 올려서는 해결되지 않는다.

## 2. 공중 오판이 경사 추종과 중력을 바꿔 문제를 확대

같은 함수의 후속 동작:

1. `Grounded == false`이면 `Up = gravityUp`으로 즉시 바뀐다.
2. 이동 입력과 속도를 실제 지면 접선이 아닌 바뀐 `Up`의 접선 평면으로 계산한다.
3. 지상 가속도 12 대신 공중 가속도 5를 사용한다.
4. 중력 반대 속도가 양수이고 Space를 누르지 않으면 상승 중 버튼 해제 추가 중력을 적용한다.

현재 `shortHopGravity = 2.2`에서는 이 추가 중력 경로가 기본 중력의 3.2배가 된다. 일반 걷기에도 이를 적용하면, 경사를 따라 움직이는 데 필요한 위쪽 성분이 줄고 입력 방향이 지형 안쪽을 향할 수 있다. 물리 충돌 해소와 다음 틱의 속도 지정이 반복되어 경사 진입 실패·속도 저하·덜컥거림으로 이어질 수 있다.

따라서 문턱값 하나를 크게 만드는 것보다 접지 유지, 실제 점프 상승, 착지에 의한 자원 회복을 분리해야 한다.

## 3. 같은 `Grounded` 값이 걷기 모션을 중단

`PrinceCharacterAnimator.cs`는 매 프레임 다음을 실행한다.

```csharp
animator.SetBool(GroundedId, walker.Grounded && !walker.Suspended);
```

`Assets/B612/Generated/Prince.controller`는:

- `Grounded == false`이면 `Locomotion → Air`, 전환 시간 0.12초.
- `Grounded == true`이면 `Air → Locomotion`, 전환 시간 0.10초.
- 두 전환 모두 Exit Time을 기다리지 않는다.

따라서 지면 위에서 접지 값이 바뀌면 걷기/달리기 재생이 공중 자세 전환으로 끊겨 보일 수 있다. 카드 HUD의 접지 표시 변화와 Animator의 입력이 같은 상태를 공유한다.

추가 관찰: 걷기 Blend Tree 문턱은 약 0.516m/s, 달리기는 약 1.579m/s이고 키보드 목표 이동 속도는 2m/s다. 정상 상태에서도 걷기는 짧은 가속 구간에만 나타나고 곧 달리기로 넘어간다. 사용자가 의미한 '걷기 스킵'이 정지에서 곧바로 달리는 느낌까지 포함한다면 이는 접지 복구 후 따로 조절할 항목이다.

## 수정할 구조

### A. 걷기 접지 유지와 착지 자원 회복 분리

- 물리 접지는 발밑 지지, 실제 지면 법선, 지지체와의 상대 속도, 명시적인 점프 이륙 상태로 판단한다.
- 지면으로부터 멀어지는 속도는 우선 `Dot(playerVelocity - supportPointVelocity, hit.normal)`을 사용한다. 단순 행성 반지름 방향 속도를 발 이탈의 직접 조건으로 쓰지 않는다.
- 접지 유지에는 작은 접촉 오차를 허용하되, 점프 승인 직후에는 바닥 탐색이 남아 있어도 재접지/재충전하지 않도록 이륙 차단을 적용한다.
- `LandingRecovered`는 실제 비행을 거친 뒤 연속 지지와 이륙 차단 조건을 만족한 경우에만 한 번 발생시킨다. 걷기용 `Grounded` 자체를 재충전 타이머로 바꾸지 않는다.

### B. 지면 이동 계산과 자세 완화 분리

- 지지 중의 이동은 실제 지면 법선에 투영한다. 목표 속도의 입력 크기는 투영으로 불필요하게 줄지 않도록 처리한다.
- 캐릭터의 시각적 자세를 부드럽게 만드는 `Up` 보간과 물리적으로 경사를 따라가는 이동 평면을 구분한다.
- 삼각형 경계에서 짧게 탐색이 흔들린 경우 지면 추종을 보완하되, 실제 절벽 이탈·점프를 바닥에 붙이는 처리로 바꾸지 않는다.

### C. 짧은 점프 중력의 적용 범위 명시

- 버튼 해제로 상승을 줄이는 추가 중력은 실제 일반/추가 점프가 발생한 상승 구간에 적용한다.
- 단순히 중력 반대 속도가 양수라는 이유만으로 경사 걷기에 적용하지 않는다.
- 활공·대쉬·낙하·이동 발판 등과의 우선순위를 유지한다.

### D. Animator는 접지 복구 후 확인

- 먼저 모터의 오판을 고친 뒤 Animator 전환이 안정되는지 확인한다.
- Animator에서 무조건 `Grounded = true`를 넣어 가리는 방식은 사용하지 않는다.
- 필요하면 짧은 표시용 완화를 둘 수 있으나, 표시용 값으로 기술 재충전이나 양 소환을 허용하지 않는다.
- 걷기와 달리기의 비중은 접지 버그와 별도 조절한다.

## 검증 보완

기존 `PlayerTraversalValidation`의 기본 바닥은 중력과 법선이 정렬된 평면이거나 완전한 구다. 위치/전체 방향을 바꾸는 검증만으로는 지면 법선과 중력 방향이 다른 경사 이동을 검증하지 못한다.

후속 수정에서 필요한 검증:

1. 중력 방향은 유지하고 바닥만 15·30·45도 기울여 점프 없이 오르막/내리막/횡방향 이동. 실제 지지가 있는 동안 접지와 이동 속도가 안정적이어야 한다.
2. 평면 바닥과 별개로 중력원이 옆에 있는 평탄한 행성 윗면, 실제 변형 메시의 삼각형 경계와 능선에서 반복 이동.
3. 각 조건에서 지지 여부, 법선 이탈 속도, 반지름 방향 속도, `Grounded`, `Up`, 실제 변위, Animator 현재/다음 상태를 함께 기록.
4. 같은 경사에서 일반 점프·추가 점프·대쉬·활공과 착지를 확인. 오르막 걷기는 공중으로 오판하지 않고, 실제 점프에서는 자원이 조기 회복되지 않아야 한다.
5. 벽·천장 접촉과 절벽 이탈에서 접지 유지 보정이 잘못 붙거나 자원을 회복시키지 않는지 확인.
6. 키보드 최대 속도에서 걷기 Blend Tree 구간이 짧은 문제는 모터 복구 후 의도에 맞게 별도 판단.

현재 분석에서 직접 확인한 것은 영상의 접지 HUD 변화, 코드·Animator 전환 경로, 20도 경사 속도 분해의 수학적 반례다. 후속 수정 및 Unity 실행 검증은 아직 수행하지 않았다.
