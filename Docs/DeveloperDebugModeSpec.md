- `GamePauseCoordinator`는 디버그 UI와 별도 씬 루트에서 소유자별 DebugOverlay/GameOver 요청을 함께 관리한다. 최초 정지 직전의 실행 속도를 보존하고 마지막 요청이 해제될 때만 복구한다. 게임오버 중 닫기·Enter가 패배를 풀지 않는다. 재시도에서 실제 씬을 새로 로드하며 이전 소유권을 정리한다.

- `AgentScripts/DeveloperDebugBuilder.cs`로 기존 씬 전체를 재생성하지 않고 참조와 UI만 추가했다. 런타임 소스는 `AgentScripts/runtime/`에 동기화했다.

## 1. 요구 사항과 기본 동작

2026-11-09 후속 요구인 바오밥 페이즈 스킵은 `DeveloperBaobabSkipImplementationSpec.md`에 별도 명세로 정리했다. 기존 세 기술 Toggle 아래에 1회 실행 버튼을 추가하고 현재 행성의 위협 정리·지도 해금까지 연결하는 제안이다. 이 후속 기능은 **문서만 작성했으며 아직 구현하지 않았다.** 아래의 구현 결과와 첫 화면 범위는 기존 디버그 모드에 관한 기록이다.

사용자가 정한 사항:

- F12를 누르면 게임을 일시정지하고 개발자 디버그 모드를 켠다.
- 대쉬, 더블점프, 활공을 각각 독립된 체크박스로 켜고 끌 수 있다.

첫 구현 기본안:

- F12를 다시 누르거나 `닫기 · 계속하기` 버튼을 누르면 디버그 화면을 닫는다.
- 다른 정지 사유가 없으면 화면을 연 시점의 게임 속도로 재개한다.
- 처음 시작할 때 세 항목은 모두 켜져 있다.
- 체크박스 변경은 즉시 실제 허용 설정에 반영하며 별도 적용 버튼은 두지 않는다. 게임 시간과 물리 진행은 닫기 전까지 정지한다.
- 디버그 모드 종료 후에도 설정을 유지하고, 다시 열면 현재 값을 표시한다.
- 같은 씬에서의 R 리스폰은 설정을 유지한다. 새 Play 세션과 재시도로 씬을 새로 로드할 때는 모두 켜짐으로 시작한다. 첫 구현에는 영구 저장을 추가하지 않는다.
- 개발용 기능이므로 Unity Editor와 Development Build에서 사용 가능하게 하는 안을 권장한다.

대쉬·추가 점프 횟수와 활공 예산 등 기존 이동 규칙은 `PlayerTraversalImplementationSpec.md`를 따른다.

## 3. 현재 코드와 충돌하는 부분

구현 전에 다음 연결을 확인한다.

| 현재 코드 | 확인한 동작 | 디버그 구현 시 필요한 처리 |
| --- | --- | --- |
| `PlayerController.Update` | `Time.timeScale <= 0`이면 `ClearControls()` 실행 | 디버그 정지 중의 비파괴 입력 차단을 먼저 처리 |
| `PlayerController.OnDisable` | 입력과 기술을 취소 | 화면을 열기 위해 컴포넌트를 비활성화하는 방식을 피함 |
| `PlayerTraversalAbilities.SetInputEnabled(false)` | `CancelInputAndActions()` 호출 | 기존 강제 취소와 디버그 정지용 입력 차단을 구분 |
| `CancelInputAndActions()` | 요청·유지 시간을 지우고 대쉬·활공 종료 | 요청만 지우는 별도 경로가 필요 |
| `GravityWalker.FixedUpdate` | 기술 컴포넌트가 비활성화되면 기존 모터 경로 사용 | 체크박스로 컴포넌트의 `enabled`를 변경하지 않음 |
| `BaobabThreatMeter` | 게임 오버에서 시간을 0으로 만들고 입력 비활성화 | 디버그 닫기가 게임 오버 정지를 풀지 않도록 정지 소유권 통합 |
| `BaobabThreatHUD.Update` | 게임 오버 중 Enter로 재시도 | 디버그 패널을 조작할 때 뒤쪽 재시도가 입력을 받지 않게 차단 |

디버그 정지 자체는 진행 중 기술의 상태·잔량·쿨다운을 보존한다. 기술을 체크 해제하면 해당 기술의 종료 부작용만 의도적으로 적용한다.

## 4. 기술별 허용값과 부작용

`PlayerTraversalAbilities`에 다음 논리 설정을 추가하는 안을 사용한다. 컴포넌트 활성 여부나 기술의 실행 중 상태와 구분한다.

```text
AllowDash = true
AllowAirJump = true
AllowGlide = true

IsAllowed(TraversalFeature feature)
SetAllowed(TraversalFeature feature, bool allowed)
```

UI는 `SetAllowed`를 호출하고 실제 기술 진입점이 허용값을 검사한다. UI에서 체크만 바뀌고 게임 입력 경로는 그대로인 구현을 완료로 보지 않는다.

| 항목 | 끄면 | 다시 켜면 |
| --- | --- | --- |
| 대쉬 | 새 대쉬와 대기 중 대쉬 요청 차단. 진행 중이면 종료하고 모터의 종료 감속 경로 사용 | 기존 자원·쿨다운이 허용할 때 새 입력으로 사용 |
| 더블점프 | 공중 추가 점프만 차단. 일반 지면·코요테 점프와 기존 지면 점프 버퍼는 유지 | 현재 남은 공중 점프 횟수만 사용 가능 |
| 활공 | 새 활공 차단. 진행 중이면 종료하고 재개 후 일반 낙하로 연결 | 남은 활공 시간과 새 입력 조건을 만족할 때 사용 |

세부 계약:

- 체크박스 변경으로 `ResetForTeleport`, 초기화 메서드, 가짜 착지 또는 전체 자원 회복을 호출하지 않는다.
- 공중 점프를 이미 썼으면 껐다 켜도 0회다. 대쉬를 썼으면 자원과 쿨다운을 유지한다. 활공 예산을 다 썼으면 껐다 켜도 0초다.
- 기능이 꺼져 있는 동안에도 실제 유효 착지에 따른 기존 자원 회복은 정상 적용한다. 기능 허용값과 자원의 유무는 별개다.
- 대쉬/활공 중 화면을 열고 체크를 바꾸지 않으면 진행 상태를 보존한다. 체크 해제로 취소한 기술은 같은 정지 중 다시 체크해도 자동 재시작하지 않는다.
- 대쉬를 끄는 순간 UI가 Rigidbody 속도를 직접 쓰지 않는다. `EndDash`와 모터의 `ClampResidual` 같은 기존 정리 경로를 통해 다음 물리 틱에 정상 속도로 연결한다.
- 더블점프를 끄기 전에 이미 발생한 상승 속도를 취소하거나 캐릭터를 아래로 떨어뜨리지 않는다. 이후의 추가 점프 요청만 막는다.
- 새 허용값은 공중 추가 점프 분기에 적용한다. `Jump()` 전체를 막아 일반 점프까지 꺼지게 하지 않는다.

## 5. 일시정지와 게임 오버의 정지 소유권

첫 구현에서도 디버그 정지와 게임 오버 정지는 함께 관리한다. 디버그 화면이 닫힐 때 무조건 `Time.timeScale = 1`을 쓰지 않는다.

작은 `GamePauseCoordinator`를 두고 소유자별 정지 요청을 관리하는 안을 권장한다.

```text
AcquirePause(owner, DebugOverlay 또는 GameOver)
ReleasePause(owner)
IsPaused
HasReason(reason)

정지 요청이 하나 이상 → timeScale = 0
요청이 모두 해제됨 → 최초 정지 직전의 실행 속도로 복구
```

- F12 열기는 디버그 소유자의 요청 하나만 추가한다. 닫기는 그 요청만 제거한다.
- 게임 오버는 별도 요청을 소유한다. 이미 시간이 0이어도 게임 오버 요청을 추가한다.
- 다른 정지 중 추가 요청을 받았다고 '이전 실행 속도'를 0으로 덮어쓰지 않는다.
- 이미 게임 오버인 상태에서도 F12 화면은 열 수 있다. 닫으면 게임 오버 정지와 화면을 유지한다.
- `BaobabThreatMeter`의 독립적인 `previousTimeScale` 저장/복원은 정지 조정 경로로 연결한다. 두 시스템이 서로 다른 이전 값을 복원하게 두지 않는다.
- 게임 오버의 기술 취소는 디버그의 상태 보존보다 우선한다. 이미 확정된 게임 오버를 디버그로 되돌리지 않는다.
- 컴포넌트가 원래 비활성화돼 있었다면 디버그 닫기가 강제로 활성화하지 않는다.
- 재시도 시 이전 디버그 화면과 정지 요청을 정리한 뒤 새 씬의 정상 실행 상태로 시작한다. 패배 중 정지 속도 0이 새 씬에 남지 않게 한다.
- 씬 언로드/디버그 컨트롤러 파괴 시 자신의 요청을 해제한다. 다른 소유자의 정지를 해제하지 않는다.

월드 정지는 게임 시간·물리·바오밥 성장·생성·먹기·양 수명·기술 타이머를 모두 멈춰야 한다. UI 입력과 F12 감지는 계속 동작해야 한다. 이번 구현에서 `fixedDeltaTime`을 0으로 바꾸거나 게임 시계를 별도로 계속 진행시키지 않는다.

## 6. 입력과 진행 상태를 보존하는 방식

F12 처리는 `PlayerController` 바깥의 `DeveloperDebugController.Update`에서 수행한다. 플레이어 입력 비활성화·게임 오버·`timeScale = 0`에도 닫기가 가능해야 한다. 한 번 누름을 감지하고 키 유지로 반복 토글하지 않는다.

### 열기

1. 디버그 컨트롤러가 플레이어의 일반 `Update` 입력보다 먼저 F12를 처리한다. 실행 순서 또는 공용 입력 라우팅으로 보장한다.
2. 디버그 정지와 게임 입력 차단을 함께 설정한다.
3. 대기 중 점프·대쉬 요청을 지운다. 현재 속도, 대쉬 진행 시간, 공중 자원, 활공 잔량과 실행 상태는 보존한다.
4. `PlayerController`는 디버그 정지 분기를 기존의 `Time.timeScale <= 0 → ClearControls()` 분기보다 먼저 처리한다. 게임 오버·발사 별·포커스 상실의 기존 강제 취소는 계속 유효하다.
5. 패널을 열고 체크박스를 실제 허용값과 동기화한다.

요청만 비우는 `ClearPendingRequests`와 진행 중 기술까지 취소하는 기존 `CancelInputAndActions`를 구분한다. 디버그 정지는 `PlayerController`/`PlayerTraversalAbilities`를 비활성화하거나 `Suspend(true)`로 구현하지 않는다.

### 패널 조작 중

- F12와 디버그 UI 입력만 받는다. WASD·Space·Shift·Q·R·숫자·휠·카메라 드래그가 게임 명령으로 새로 기록되지 않는다.
- UI의 Space/Enter 조작은 캐릭터 점프나 뒤쪽 게임 오버 재시도로 전파되지 않는다.
- UI가 이벤트를 받는 것과 키보드/마우스를 직접 읽는 게임 스크립트는 별개이므로, 전체 화면 배경의 Raycast 차단만으로 완료했다고 판단하지 않는다.
- 디버그 UI 갱신과 필요한 UI 동작에는 실제 시간 또는 프레임 입력을 사용한다. 게임 시간 기반 타이머로 F12를 검사하지 않는다.

### 닫기

- 패널에서 발생한 입력과 닫힌 프레임의 게임 입력을 폐기한다. 대기하던 점프·대쉬가 자동 실행되지 않게 한다.
- 정지 전부터 해제 없이 계속 유지하던 Space는 기존 활공 유지 입력으로 이어갈 수 있다. 정지 중 새로 누르거나 다시 누른 Space/Shift는 해제 후 새로 눌러야 새 기술이 실행된다.
- 이를 위해 정지 직전의 유지 상태와 정지 중 해제 여부를 기록한다. 실제 Space가 해제됐다면 재개 후 활공은 정상적으로 종료된다.
- 마우스 버튼을 누른 채 닫았을 때 패널 클릭이 카메라 회전으로 이어지지 않도록 버튼 해제와 입력 재수집 경계를 둔다.
- 카메라/플레이어는 새 입력 프레임부터 정상 제어를 받는다. 닫기가 실제 착지나 자원 초기화 이벤트를 발생시키지 않는다.

## 7. UI 구성과 연결

기존 HUD의 uGUI를 따른다. 현재 HUD 빌더는 Screen Space Overlay와 기준 해상도 1600×900, Match 0.5를 사용한다. 새 화면도 같은 기준을 사용한다.

```text
DeveloperDebugRoot                 ← F12 컨트롤러, 항상 활성
└─ DebugCanvas                     ← Overlay / 기존 HUD보다 높은 순서
   └─ DebugPanelRoot               ← 평소 숨김, CanvasGroup
      ├─ Backdrop                 ← 전체 화면 입력 차단
      └─ Panel                    ← 중앙 정렬
         ├─ Header                ← 제목, 일시정지 표시
         ├─ AbilityToggles        ← VerticalLayoutGroup
         │  ├─ DashToggle
         │  ├─ AirJumpToggle
         │  └─ GlideToggle
         ├─ Hint                  ← F12로 닫기
         └─ CloseButton
```

- `UnityEngine.UI.Toggle` 세 개와 TMP 텍스트를 사용한다. 체크 표시와 행 라벨을 함께 클릭할 수 있게 한다.
- 한글 라벨이 표시되는 TMP 폰트/폴백을 확인하고 기존 프로젝트의 폰트 구성을 활용한다.
- 기존 EventSystem과 InputSystemUIInputModule을 재사용하고 중복 EventSystem을 생성하지 않는다. 현재 게임 오버 UI 빌더가 EventSystem을 준비한다.
- 새 Canvas에는 GraphicRaycaster를 설정한다. 패널이 열렸을 때만 보이고 상호작용·Raycast 차단이 켜지도록 한다.
- 제목·장식 텍스트는 불필요하게 Raycast를 막지 않게 하고, 배경은 뒤쪽 UI 클릭을 차단한다.
- 커서는 열 때 표시·잠금 해제한다. 닫을 때 다른 UI가 커서를 소유하지 않으면 이전 상태로 복원한다. 게임 오버 UI가 남으면 그 UI의 커서 상태를 유지한다.
- 열기/동기화에는 `SetIsOnWithoutNotify`를 사용해 값 표시만으로 기술 취소 콜백이 실행되지 않게 한다.
- 이벤트는 한 번만 연결하고 해제한다. F12를 여러 번 눌러도 콜백이 누적되지 않는다.
- Player/기술 구성 참조가 없으면 해당 체크박스를 비활성화하고 짧은 상태 문구를 표시한다. F12 닫기는 계속 동작해야 한다.

## 9. 최소 수용 조건

| 검사 | 기대 결과 |
| --- | --- |
| F12 1회/유지/다시 누름 | 열고 정지, 유지 중 반복 없음, 재누름으로 닫기 |
| 정지 중 기다리기 | 바오밥·양·물리·대쉬 시간·쿨다운·활공 잔량 변화 없음 |
| 세 체크박스 8조합 | 각 기술만 독립적으로 허용/차단 |
| 더블점프 끄고 지면 점프 | 일반 점프·코요테·착지 버퍼 유지 |
| 대쉬/활공 중 열고 그대로 닫기 | 시간·잔량 보존. 입력 조건이 이어지면 진행을 계속함 |
| 대쉬/활공 중 해당 체크 해제 | 그 동작만 취소. 재개 시 종료 속도/일반 낙하로 연결 |
| 공중 자원 소모 후 OFF→ON | 점프 횟수·대쉬 자원·활공 잔량이 늘지 않음 |
| 체크 해제 후 실제 착지 | 기존 유효 착지 규칙은 유지. 다시 켜면 정상 회복된 자원 사용 |
| 패널에서 Space/Shift/Q/R/휠/Enter | 게임 동작이나 재시도 실행·버퍼 적립 없음 |
| 여러 번 열고 닫기 | 값 유지, 이벤트 중복 없음, 컴포넌트·커서 상태 정상 |
| 게임 오버 후 F12 열고 닫기 | 게임 오버 유지, 시간 0 유지 |
| 디버그 정지와 게임 오버가 같은 프레임에 겹침 | 각각 정지 요청 보유, 닫기로 패배 정지가 풀리지 않음 |
| 게임 오버 재시도/씬 재로드 | 이전 정지 요청이 남지 않고 새 씬에서 정상 시작 |
| 원래 비활성 컴포넌트/다른 실행 속도 | 디버그 닫기가 강제 활성화하거나 속도를 1로 고정하지 않음 |
| 여우·기본 이동·기존 경사 수정 | 기술 스위치와 별개로 정상 동작 |

단순 체크박스 표시뿐 아니라 실제 키보드/게임패드 요청과 기술 실행 결과를 확인한다. 자동 검증과 실제 Play 검증의 수행 여부·결과를 구분해 기록한다.
