# 이동 지형 1단계: 고정 테스트 행성

2026-11-09. `ProceduralTerrainTraversalDesign.md` 15절의 **1단계만** 구현했다. 실제 모터에 맞춘 수작업 지형과 능력 전후 비교가 목적이다.

## 실행과 비교

`Assets/B612/Scenes/B612_TraversalTest.unity`를 열고 Play한다. 처음에는 확장 능력 세 개가 모두 꺼져 있다.

- **1 / 2 / 3**: 골짜기 / 높은 턱 / 활공 구간의 출발점으로 이동한다. 같은 씬에서 걷기로도 다른 구간에 갈 수 있다.
- **R**: 현재 구간을 다시 연습한다. 선택한 능력 허용값은 유지하며 위치·체공 자원·측정을 명시적으로 초기화한다.
- **F12**: 기존 대쉬·더블점프·활공 체크박스를 독립적으로 켜고 끈다. 열린 동안 일시정지하며 지형은 바뀌지 않는다.
- **민트색**은 기본 보행 우회로, **금색**은 능력 지름길이다. 푸른 출발 지점과 금색 도착 지점을 연결한다.
- **WASD / Space / Shift**는 기존 이동·점프/유지·대쉬다. 카메라는 마우스 드래그·Z/C, Ctrl+휠을 사용한다.

각 구간을 먼저 전부 끈 상태로 우회한 뒤 대응 능력만 켜서 다시 시도한다. 골짜기는 점프 후 Shift, 턱은 Space를 두 번, 활공은 Space를 누른 채 점프해 하강을 이어간다. Space를 유지하면 허용된 활공이 자동 진입하므로, 짧은 점프·대쉬만 비교할 때는 활공을 끄거나 버튼을 놓는다.

화면은 실제 허용값·규격·구간 시간을 표시한다. 출발점에서 0.45m 벗어나면 측정을 시작하고 도착 원에 접지하면 끝낸다. 디버그 정지 시간은 제외한다. 측정 중 능력을 바꾸면 혼합 기록을 남기지 않고 취소해 R 재측정을 안내한다. 숫자 이동과 R은 연습용 리셋이며 일반 플레이의 착지 회복 규칙을 변경하지 않는다.

## 고정 지형 규격과 구현

기준 반경 **12m**, 중력 **3.4m/s²**의 독립 테스트 행성 하나에 세 구간을 120도 간격으로 배치했다. 메인 게임의 행성 배율/생성 데이터와 연결하지 않았다. 구면의 방사 방향 높이 필드를 수작업 수치로 정의하고 Editor에서 메시 에셋으로 굽는다. 한 방향에 기본 지면은 하나이며 표시 메시와 MeshCollider가 같은 에셋을 사용한다.

| 구간 | 고정 규격 | 기본 동선 | 대응 지름길 |
| --- | --- | --- | --- |
| 골짜기 | 기준 폭 4.2m, 깊이 2m, 양 끝 0.16m의 짧은 경계 면 | 북쪽 가장자리를 따라 우회. 바닥에서 북쪽 경사로로 탈출 가능 | 일반 점프 + 공중 대쉬. 추가 점프로도 횡단 가능 |
| 높은 턱 | 방사 높이 2m, 앞면 폭 0.2m, 정상 평탄부 | 옆의 경사로를 올라 정상에 도착. 반대쪽에도 하강 경사 | 추가 점프로 정면 진입 |
| 활공 | 출발 높이 +2.6m, 착지 높이 +0.4m, 기준 간격 7m, 계곡 바닥 -1.4m | 출발대 옆으로 내려가 계곡을 우회하고 착지대로 접근 | 점프 유지 → 하강 활공. 바닥에 떨어져도 보행 복귀 가능 |

폭·간격과 지면 표시 경로는 **반경 12m 기준의 구면 호 길이 좌표**다. 높이는 방사 방향 월드 미터다. 실제 공중 이동과 충돌은 3D PhysicsScene에서 측정한다. 활공 양 끝의 경계 면은 각각 약 0.15m이며, 높이가 다른 두 점 사이의 직선 거리를 위 기준 간격과 같다고 취급하지 않는다.

측정에 사용한 기존 플레이어는 보행 2m/s·점프 속도 3.1m/s·캡슐 반지름 0.13m/높이 0.78m다. 대쉬 8m/s·0.18초, 추가 점프 3m/s, 활공 2.6m/s·총 2.5초를 유지했다. `GravityWalker`, `PlayerTraversalAbilities`, 기존 입력·애니메이션·착지 회복 코드를 변경하지 않았다.

씬 전용 카메라는 피치 **55도**, 거리 **6.4m**로 두어 낮은 착지대를 살펴볼 수 있게 했다. 활공 시작 위치에서 착지대 앞부분을 향한 실제 Collider 시선 검사에서 가림이 없고 화면 안에 들어왔다. 공통 카메라 코드는 유지했다. 안내는 한글 글리프를 구운 독립 정적 TMP 폰트와 기존 규격의 uGUI를 사용한다. EventSystem은 기존 하나다.

메시는 95,056정점·187,872삼각형이며 경계 위치를 표본에 명시해 턱이 거친 메시 간격 때문에 낮아지지 않도록 했다. 경도 이음선/극점은 같은 방향·높이·미분 법선을 사용한다. `TraversalTestCourseGeometry.CreateMesh`는 Editor 빌더에서만 호출한다. Play·F12·능력 변경·연습 리셋 중 지형을 재생성하지 않는다.

테스트 씬에서는 바오밥·양·지도 진행 루트를 비활성화해 이동만 반복한다. 원본 `B612_EmptyPlanet`과 그 생성 경로·생성기 버전은 유지한다. 노이즈·무작위 요소 배치·타일 가중치·물길·챕터 해금·도달성 그래프·자동 수정은 이번 단계에 포함하지 않았다.

## 실제 측정

Unity `6000.3.23f1`, Unity CLI `1.0.0-beta.17`. 열린 Editor에서 컴파일을 완료하고, 구워진 동일 메시 Collider·기존 모터·실제 캡슐 설정을 별도 3D PhysicsScene에 연결해 **0.02초 틱**으로 26개 조건을 비교했다. 테스트는 `AgentScripts/TraversalTestCourseValidation.cs`이며 원시 결과는 `Temp/TraversalTestCourseValidation.json`이다.

아래 시간은 스크립트가 정해진 입력으로 출발부터 목표 근처까지 움직인 값이다. 직접 플레이 HUD의 시작/도착 판정 범위와는 구분한다.

| 구간 | 기본 보행 우회 | 대응 능력 지름길 | 기본 점프 직진 | 전체 능력 직진 |
| --- | ---: | ---: | --- | ---: |
| 골짜기 | 8.86초 | 대쉬 3.24초 | 실패·골짜기 바닥 착지 | 5.42초 |
| 높은 턱 | 9.62초 | 추가 점프 3.88초 | 실패·턱 아래 착지 | 4.66초 |
| 활공 | 12.54초 | 활공만 허용 5.50초 | 실패·계곡 바닥 착지 | 6.30초 |

- 대응 능력은 우회 대비 약 **2.73배 / 2.48배 / 2.28배**의 시간 이득을 보였다. 원 설계의 1.3~1.8배는 제안값이며, 이 격리 실험실에서는 경로 차이를 읽기 쉽게 두었다. 바오밥 실전 밸런스로 확정한 비율이 아니다.
- 기본 우회로 세 개 모두 점프 없이 통과했고 **공중 판정 틱 0**이었다. 경사 최대 관측값은 약 **10.1도 / 29.0도 / 29.3도**다.
- 골짜기·활공 계곡 바닥에서 확장 능력 없이 각각 약 **2.90초 / 3.68초**에 탈출했다. 별도 복귀 경사의 최대 관측값은 약 **35.8도 / 22.0도**로 모터 한계 60도 이내였고 이 검사에서도 공중 판정 틱은 0이었다.
- 골짜기 대쉬 시점 0.55/0.65/0.75초, 높은 턱 추가 점프 시점 0.60/0.70/0.80초에서 성공했다. 골짜기 대쉬와 활공의 점프 출발 위치를 각각 ±0.1m 바꿔도 착지했다.
- 단독 대쉬는 2m 턱과 활공 간격의 해법이 되지 않았고, 추가 점프만으로도 활공 간격은 통과하지 못했다. 전체 프로필은 통과하지만 입력 시퀀스에 따라 체공이 길어져 대응 능력만 쓴 경우보다 느릴 수 있다.
- 공중 추가 점프는 해당 조건에서 1회만 발생했고, 중간 지지에 의한 추가 자원 회복으로 성공한 경우는 없었다. 활공은 총 2.5초 예산 안에서 처리했다.

`AgentScripts/TraversalTestCourseSceneValidation.cs`는 실제 Play 프레임에서 기존 체크박스의 `onValueChanged`, 숫자 구간 선택, 가상 Input System 키보드의 **W/Space/Shift**로 세 지름길을 통과했다. 지면 점프는 구간당 1회, 추가 점프 구간에서만 공중 점프 1회였고 활공 구간은 Space 유지로 실제 활공에 진입했다. 최종 테스트 씬 구도에서 다시 실행했으며 결과는 `Temp/TraversalCourse/LiveInput.txt`다. R 재시작의 타이머 초기화·능력 허용값 유지도 이 검사에 포함한다.

세 구간의 Game view와 안내 한글·기본 우회 표시를 CLI 캡처로 확인했다. 개발/Release Player 빌드, 다양한 반경/seed, 여러 해상도, 원래 게임 전체 회귀는 실행하지 않았다. 이번 수치는 이 고정 반경·지형에서의 초기 검수 규격이며 사람의 반복 플레이에 따른 재미·불쾌감 평가는 후속 조절 대상이다.

## 변경 소스와 재생성

- `Assets/B612/Scripts/TraversalTestCourse.cs`: 구간 선택·연습 리셋·안내·측정. 대응 사본은 `AgentScripts/runtime/TraversalTestCourse.cs`다.
- `Assets/B612/Scripts/TraversalTestCourseGeometry.cs`: 고정 수작업 수치와 Editor 베이크용 메시 구성. 대응 런타임 사본도 동기화했다.
- `Assets/B612/Shaders/TraversalCourse.shader`: 높이와 경로의 정점 색을 읽는 단순 표시 재질.
- `AgentScripts/TraversalTestCourseBuilder.cs`: 원본의 별도 씬 사본에서만 작업하며 `Assets/B612/Generated/TraversalTest/`에 독립 메시·재질·안내 폰트를 저장한다. 기존 테스트 씬을 열고 `Build`를 재실행하면 해당 실험실만 다시 굽는다. 전체 `B612Builder`는 사용하지 않는다.

실행 예:

```powershell
unity command run_script --caller plugin --skill unity-cli --file AgentScripts/TraversalTestCourseBuilder.cs --entry TraversalTestCourseBuilder.Build
```
