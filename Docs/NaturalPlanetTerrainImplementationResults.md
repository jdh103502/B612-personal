# 자연 지형·강 우선 행성 생성 구현 결과

2026-11-21. Unity 6000.3.23f1. 생성기 버전 8, 프로필 `terrain.natural.v1`, 행성 데이터 형식 버전 1. 여정/행성 seed를 고정해도 버전 7과 버전 8의 형상은 달라진다.

**같은 날 후속(생성기 버전 9):** 사용자 승인으로 지면 메시를 등각 cube-sphere로 바꿨다. 높이장·강·배치 규칙과 아래 설정 표는 그대로이며, 지면 메시 정점 배치만 달라진다. 측정과 검증은 [버전 9 절](#생성기-버전-9-등각-cube-sphere-지면-메시)을 따른다. 아래 본문의 정점 수·준비 시간은 버전 8 당시 기록이다.

**같은 날 후속(생성기 버전 10):** 사용자 승인으로 높이 노이즈를 gradient(simplex) noise로 바꾸고 지역별 거칠기 마스크를 추가했다. 측정과 검증은 [버전 10 절](#생성기-버전-10-gradient-noise와-거칠기-마스크)을 따른다. 아래 설정 표의 크기·진폭 값은 그대로 쓰인다.

**같은 날 후속(생성기 버전 11):** 사용자 승인으로 강을 흐름 누적 기반으로 바꾸고 강 끝에 얕은 연못을 두었다. 측정과 검증은 [버전 11 절](#생성기-버전-11-흐름-누적-기반-강과-연못)을 따른다. 위 본문의 "강 끝이 지면 아래로 들어간다"는 버전 10까지의 설명이다.

## 플레이용 생성

`ChapterJourneyGeneration`, `EmptyPlanetGeneration`, `ProceduralTerrainTestGeneration`에 동일한 자연 지형 프로필을 연결했다. 시작·일반·도착 행성은 설정 스냅샷 → 전역 높이장 → 낮은 방향의 강 → 최종 메시와 충돌체 → 보행 연결성 추정 → 스폰·상호작용 지점·바오밥 후보 순으로 준비한다. 과거 보호 통로·원형 둔덕 배치·능력별 코스·강제 우회로 검사·고정 여울·길 안내선은 이 경로에서 사용하지 않는다. 양 소환 범위와 목표 싹 표시는 기존 조작에 쓰인다. `B612_TraversalTest`와 이전 실험용 생성 코드는 비교용으로 보존했다.

강 중심선은 독립 파생 seed로 고른 수원에서 방사 고도가 낮아지는 쪽을 추적한다. 평활화는 주변 고도 사이에 들어가는 점에 적용한다. 최종 수면도 중심선의 비증가 고도를 따라가고, 강 양 끝은 깎이지 않은 지면 아래로 들어간다. 강이 맞지 않는 경우 시도 횟수와 원인을 Plan에 남기고 강을 생략한다.

배치 분석은 최종 Collider 위에서 경사, 캡슐 여유, 이웃 사이의 중간 접지와 양방향 고도 변화량을 검사한다. 물길이 좁아질 때 이웃 사이의 검사 간격도 줄인다. 표본의 입체각·실제 반경·경사를 반영해 연결 영역 면적을 추정한다. 해당 영역에 스폰과 마른 상호작용 위치를 고르고, 경사·캡슐·수면·간격 조건을 통과하는 기존 논리 타일 후보를 준비한다. 배치 기준을 충족하지 못하면 원인을 보고하고 준비를 종료한다. 지도 이동은 준비 성공 뒤 확정되며, 배치 분석으로 골짜기를 깎거나 평탄화하지 않는다.

## 최종 설정

| 항목 | 반경 12m 기준 |
| --- | --- |
| 넓은 층 공간 크기 / 진폭 | 12m / 1.4m |
| 중간 층 공간 크기 / 진폭 | 5m / 0.30m |
| 높이 예산 | `min(2m, 0.17 × 반경)` |
| 강 | 최대 1개, 길이 8~18m, 수면 폭 0.9m, 목표 수심 0.12~0.20m, 양쪽 강둑 전이 폭 각각 1.2m |
| 강 탐색 | 수원 최대 64회, 추적 최대 256단계 |
| 배치 분석 | 간격 약 0.6m, 최대 30,000노드, 배치 경사 상한 `min(35°, 모터 상한−5°)` |
| 배치 조건 | 연결 면적 최소 60%, 지점 간격 2m, 지점당 최대 64후보 |

반경 12m 미만에서는 `q = R / 12`를 두 층의 공간 크기와 진폭, 강 길이·폭·깊이·강둑 폭에 적용한다. 진폭 합이 예산을 넘으면 두 층을 같은 비율로 줄인다. 두 노이즈와 강, 배치, 표면 색의 seed를 분리했다. 유한한 연속 높이장 두 층을 사용하며 warp와 ridge를 합성하지 않는다. 텍스처는 기존 2m 반복, 행성 대표색과 고도·경사·강가 혼합을 사용한다.

같은 시드로 튜닝하려면 씬의 `StarSystemFlowController`에서 `randomizeRunSeed`를 끄고 `runSeed`를 고정한 뒤 생성 에셋의 **Natural Terrain** 값을 수정하고 새로 Play한다. 기본값으로 두 차례 준비한 메시 정점과 스폰 방향은 일치했다. 같은 시드에서 넓은 층 진폭을 임시로 10% 낮춘 시험에서는 메시가 달라졌다. 프로젝트 기본값은 표의 수치다. R은 현재 확정 월드에서 정해진 위치로 리스폰한다.

## 생성·모터 검증

여정 612101·1·77의 일반 행성 0.7·1·1.5·2배 12건, 세 챕터의 시작·도착 행성 6건, 기준 반경 5.3m 설정의 소·대 행성 2건, 12m 시험 씬 설정 1건을 포함해 21건을 준비했다. 21건 모두 강이 생겼고 필요 지점과 바오밥 후보가 배치됐다. 연결 영역은 99.16~100%, 승인 후보는 2,541~10,240개였고 후보가 없는 논리 셀은 없었다. 렌더와 충돌에 같은 지면 메시를 썼다.

행성당 균등 방향 4,096개에서 최종 Collider 높이를 읽었다. 일반 행성 12건의 `(P90−P10)/q`는 1.13~1.46m였고, 각 표본의 20개 구역에서 모두 `0.35×q m` 이상의 높이 범위를 측정했다. 각 행성의 P10/P50/P90·최솟값·최댓값, 강 길이, 연결 면적과 배치 방향을 별도 기록했다. [생성 표본](../Artifacts/NaturalPlanetTerrain/Samples.json)

시드 1076931390의 1배 표본에서 전체 P90−P10은 0.97 → 1.14m, 0.35m 기준을 넘긴 구역은 17 → 20개였다. 2배 표본에서는 0.26 → 1.29m, 9 → 20개였다. 비교 전 높이 표본은 같은 에디터에서 기존 프로필을 재생성해 측정했다. [이전 프로필의 높이 기록](../Artifacts/NaturalPlanetTerrain/BaselineHeight.json)

실제 캐릭터와 같은 캡슐·`GravityWalker`로 독립 PhysicsScene의 최종 Collider를 걸었다. 시드 1076931390의 0.7·1·2배에서 언덕 오르내리기, 분지 진입·복귀, 양방향 강 횡단이 각각 통과했다. 강 횡단의 왕복 편도 시간은 1.80~2.38초였다. 세 크기 모두 수면 메시 높이가 하류 방향으로 증가하지 않았고 양 끝은 지면 아래에 들어갔다. 별도 수면/바닥 표본에서 속도 배율 0.65를 확인했다. 이 검사는 플레이 중 배치 조건으로 실행되지 않는다. ## 에디터의 실제 여정

`B612_ChapterJourney`, 여정 612101에서 기본 보행과 E 입력으로 세 시작 행성의 해금·조사·만남 지점 9곳을 방문했다. 해금 전에는 인접 행성을 선택할 수 없었고, 같은 메시에서 대쉬·더블점프·활공을 실제 입력으로 한 번씩 쓰고 안정 착지 뒤 자원 회복을 확인했다. M으로 연 지도의 행성 버튼과 다음 챕터 버튼으로 시작·일반·도착 행성 12곳을 방문했다.

R은 같은 메시의 확정 스폰으로 돌아왔고 F12의 일시정지·능력 허용·페이즈 스킵이 동작했다. 승인된 후보에 나온 싹을 Q로 소환한 양이 먹고, 만료된 양에게 걸어가 같은 카드를 회수했다. 유효하지 않은 자연 지형 설정으로 준비 실패를 주입했을 때 출발 행성·진행 경로·지도 상태가 유지됐다. 성공한 11회 전환에서는 떠난 지면·물 메시와 지면 재질이 해제됐다. [실제 여정 로그](../Artifacts/NaturalPlanetTerrain/EditorJourney.txt)

`B612_EmptyPlanet`과 `B612_ProceduralTerrainTest`도 각각 실제 Play로 열었다. 두 씬에서 자연 지형 프로필, 강, 확정 스폰과 바오밥 후보가 로드됐다. [보조 씬 시작 기록](../Artifacts/NaturalPlanetTerrain/OtherScenes.json)

## 생성기 버전 9: 등각 cube-sphere 지면 메시

2026-11-21 시험 구현 → 같은 날 사용자 승인으로 기본값 채택. 생성기 버전은 9다. 버전 8과 같은 seed라도 지면 정점이 달라지므로 버전 8 입력은 기존 규칙대로 거부한다.

- `NaturalTerrainSettings.equalAngleMesh`(기본 `true`)는 지면 메시의 각 면 좌표에 `tan`을 적용한 등각 cube-sphere를 쓴다. 세 생성 에셋에도 `true`로 기록했다. `false`는 버전 8의 정규화 cube 매핑을 비교용으로 재현할 때만 쓴다.
- 높이 함수·강·배치 규칙·물 메시는 바꾸지 않았다. 렌더와 충돌은 계속 같은 지면 메시를 쓴다.
- 기존 방식은 면 중앙의 정점 간격이 0.18m이고 면 모서리로 갈수록 촘촘해진다(면적 기준 약 5배). 등각 방식은 가장 넓은 간격을 같은 0.18m로 유지하고 `frequency = ceil(πR / (2 × 간격))`로 정한다. 면 경계 정점은 기존처럼 정수 키로 공유하므로 이음새에 틈이 없다.

### 준비 비용

여정 612101, 2챕터 `system_02_B`(행성 seed 1076931390)를 같은 Editor Play 세션에서 3회씩 준비한 평균이다. 시간은 `PlanetWorldHost.Prepare` 전체이고 실행마다 수 % 차이가 있다. 위 버전 8 표와는 다른 세션의 측정이므로 절대값보다 같은 세션의 비율로 비교한다.

| 크기 | 지면 정점 (v8 → v9) | 메시·Collider | 전체 준비 |
| --- | ---: | ---: | ---: |
| 0.7배 | 53,018 → 32,858 (−38%) | 102 → 67ms | 159 → 124ms |
| 1배 | 107,738 → 66,152 (−39%) | 216 → 139ms | 303 → 223ms |
| 2배 | 427,736 → 264,602 (−38%) | 1,046 → 640ms | 1,521 → 1,091ms |

연결 분석·후보 시간은 메시 방식과 무관해 거의 변하지 않았다. 2배에서는 이제 연결 분석이 전체 준비의 약 3분의 1이다.

### 검증

검증 스크립트는 `AgentScripts/NaturalTerrainMeshValidation.cs`다. Play 모드에서 행성 하나씩 `Compare`(v9 기본과 v8 매핑 비교)와 `Walk`(v9 기본 메시 보행)를 실행한다.

```
unity command run_script --file AgentScripts/NaturalTerrainMeshValidation.cs --entry NaturalTerrainMeshValidation.Compare --args "[612101,2,\"system_02_B\",1]"
```

## 생성기 버전 10: gradient noise와 거칠기 마스크

2026-11-21, [후속 개선 제안](NaturalTerrainImprovementProposals.md)의 A·B를 사용자 승인으로 구현했다. 생성기 버전은 10이다. 같은 seed라도 버전 9와 지형 형태가 다르다.

### 설정

| 항목 | 값 |
| --- | --- |
| `noiseBasis` | `Simplex` (`Value`는 v9 비교용) |
| simplex 보정 | 출력 ×2.26, 입력 주파수 ×0.40 (코드 상수) |
| `roughnessScaleMeters` | 18m (반경 12m 미만은 `q` 적용) |
| `roughnessRange` | 0.2~1.6배 (중간 층 진폭에 곱함) |

- **기존 설정의 의미 유지:** 크기·진폭 설정의 의미가 바뀌지 않도록 simplex 출력을 두 가지로 보정했다. 출력에 2.26을 곱해 P10~P90 폭을 v9 value noise와 맞췄다(0.983 대 0.436). 입력 주파수에 0.40을 곱해 RMS 기울기도 맞췄다(1.150 대 2.26×1.265). 두 보정 모두 40만·20만 개 무작위 점에서 측정했다(`NaturalTerrainMeshValidation.NoiseSpread`).
- **주파수 보정이 필요한 이유:** 출력 폭만 맞춘 첫 시도는 무늬가 2.5배 촘촘해졌다. 15° 이하 면적이 50~62%로 떨어지고 최대 경사가 38~45°까지 올라가서 채택하지 않았다.
- **거칠기 마스크:** 매우 낮은 주파수의 마스크로 중간 층(5m)의 진폭만 조절한다. 넓은 층은 바꾸지 않는다. 높이 예산 `min(2m, 0.17R)`은 최대 배율 1.6을 포함한 최고 높이로 계산한다. 반경 12m에서 1.4 + 0.3×1.6 = 1.88m로 예산 안이다.
- **제안보다 강한 배율:** 제안서의 0.35~1.0배는 측정 효과가 약했다. 잔잔한 구역의 국소 기복이 8곳 중 6곳에서만 약 5~15mm 작았다. 그래서 0.2~1.6배로 정했다.
- **v9 재현:** `noiseBasis = Value`, `roughnessRange = (1, 1)`이면 v9 식을 그대로 쓴다. 행성 8곳에서 지면·물·배치·후보 해시가 v9와 비트 단위로 같았다(`TerrainPrepFingerprint.RunV9Noise`).

### 검증

행성 8곳(반경 8.4~24m)에서 v9와 v10을 같은 seed로 비교했다(`NaturalTerrainMeshValidation.Relief`).

| --- | --- | --- |

- **국소 기복:** 한 지점의 높이와 주변 2.5m 여섯 방향 평균 높이의 차이다. 두 버전 모두 v10 마스크 기준으로 같은 구역을 나눠 쟀다.
- **생성:** 여정 612101·77의 세 챕터 행성 36곳(반경 8.7~23.9m)에서 강·스폰·상호작용 지점·바오밥 후보가 모두 준비됐다. 강은 36/36곳에 생겼고 연결 면적은 99.97% 이상이었다.

## 생성기 버전 11: 흐름 누적 기반 강과 연못

2026-11-21, [후속 개선 제안](NaturalTerrainImprovementProposals.md)의 C를 사용자 승인으로 구현했다. 생성기 버전은 11이다. 같은 seed라도 버전 10과 강의 위치·모양이 다르다.

### 동작

1. 약 0.6m 간격(`flowSpacingMeters`, 반경 12m 미만은 `q` 적용)의 구면 삼각형 셀 그래프에 높이장을 표본화한다. 이웃과 이웃의 이웃(최대 9곳) 중 가장 가파른 내리막으로 물길을 잇는다.
2. 높은 셀부터 면적을 아래로 넘겨 누적 유량(집수 면적)을 구한다. 더 내려갈 곳이 없는 셀이 분지 바닥이다.
3. 분지 바닥에서 낮은 셀부터 물을 채운다. 더 낮은 바깥 셀이 나타나는 넘침 지점, 최대 수심 0.25m, 최대 반경 3.5m 중 먼저 닿는 곳에서 멈춘다. 물가 둘레 48방향의 지면이 모두 수면보다 2cm 이상 높은 원판 반경을 연못 범위로 정한다.
4. 넘침이 빨라 얕은 분지는 가운데를 최대 0.15m(최대 수심의 60%)까지 판다. 파는 깊이는 수면 위 높이에 따라 줄고 연못 테두리에서 0이 되므로, 물가는 지형의 등고선을 따른다.
5. 연못으로 들어오는 가장 큰 물줄기를 상류로 따라가 길이 8~18m(`q` 적용)의 강을 만든다. 후보가 여럿이면 집수 면적에 seed별 0.8~1.2배를 곱한 값이 큰 순서로 시도한다.
6. 셀 경로의 모서리를 깎고 약 1.5m 범위로 부드럽게 다듬는다. 강둑 아래에 머무는 하강 수위를 맞추고, 연못 물가 띠에 닿는 지점에서 강을 끝낸다. 강물은 연못 수면보다 낮아지지 않는다.
7. 맞는 후보가 없으면 버전 10의 추적기로 대체하고, 그 이유를 `riverStatus`에 남긴다.

### 연못 규칙

- **얕은 물:** 강과 같다. 걸어 들어갈 수 있고 충돌체는 없다. 물속 이동 속도는 65%다.

- **배치 제외:** 젖은 지면 판정(`IsWet`)이 연못을 포함하므로, 스폰·상호작용 지점·바오밥 후보 제외는 강과 같은 여유 폭으로 적용된다. 물가에는 강가와 같은 젖은 흙색이 칠해진다.

## 물길을 따르는 습도 색 (2026-11-21, 렌더링 전용)

사용자 승인으로, 식생이 물을 따라 자라는 패턴을 지면 색에 넣었다. 물이 모이는 골짜기·분지·저지대는 풀이 짙고, 물이 빠지는 능선과 볼록한 곳은 흙이 드러난다. 높이·충돌·강·배치는 바뀌지 않으므로 생성기 버전은 11 그대로다.

### 방법

- `NaturalTerrainFlow.Build`가 만든 흐름 그래프(약 0.6m 셀)를 강 계획과 함께 쓴다. 강 방식이 `Trace`여도 습도를 켜면 흐름 그래프를 만든다.
- 셀마다 습도(0~1)를 세 신호로 섞는다.
  - **물 공급 40%:** 상류 셀 수의 로그(3~60개). 물길과 분지에서 높다.
  - **지형 위치 30%:** 반경 약 3m 평균 높이보다 낮은 오목한 곳은 젖고, 볼록한 능선은 마른다. 0.15m(`q` 적용) 차이에서 끝값에 닿는다.
  - **저지대 30%:** 행성 전체에서 낮은 땅일수록 젖는다.
- 셀 단계에서 약 3m 범위로 한 번 부드럽게 번지게 한 뒤(`moistureBlurMeters` 1.5의 2배), 정점은 가까운 셀(셀 간격의 1.5배)만 보간한다. 두 단계 모두 병렬로 실행한다.
- 결과는 지면 메시의 두 번째 UV 채널(`TEXCOORD1`)에 넣는다. 기존 정점 색·법선은 그대로다.
- 셰이더(`PlanetGround`)는 풀/흙을 고르는 `fertility`에 `moistureStrength × (습도 − 행성 평균 습도)`를 더한다. 평균을 빼므로 행성 전체의 풀 비율은 거의 유지된다.
- **기존 높이 규칙:** 기존의 "높은 곳은 풀, 분지는 흙" 규칙은 습도와 반대로 작용해서, 습도 세기만큼 줄인다(세기 1에서 0). 물가의 진흙 띠(강가 규칙)는 유지한다.

### 설정

| 항목 | 값 |
| --- | --- |
| `moistureStrength` | 1.0 (0이면 v11 색) |
| `moistureBlurMeters` | 1.5m (반경 12m 미만은 `q` 적용) |

### 검증

- **결과 동일:** 행성 8곳에서 습도를 켜고 끈 결과를 비교했다. 지면 정점·색·법선·인덱스, 물, 배치, 바오밥 후보 해시가 모두 같았고, 두 번째 UV 채널만 추가됐다(`TerrainPrepFingerprint.RunNoMoisture`). 행성 평균 습도는 약 0.4였다.
- **화면:** 2챕터 `system_02_B` 1·2배를 세기 0·0.6·1.0·1.4로 같은 구도에서 촬영했다. 세기 1.0에서 강 골짜기와 연못 분지를 따라 풀이 이어지고 능선은 흙색이다. 연못 둘레는 진흙 띠 바깥으로 풀밭이 이어진다. [촬영 폴더](../Artifacts/NaturalPlanetTerrain/MoistureColor/)
- **시도 과정:**
  - 물 공급만 쓴 첫 시도는 녹색 줄이 너무 가늘어서 행성 전체에서 잘 읽히지 않았다.
  - 지형 위치를 더한 두 번째 시도는 기존 높이 규칙 때문에 강이 지나는 저지대가 여전히 흙색이었다.
  - 그래서 저지대 신호를 넣고, 기존 높이 규칙을 습도 세기만큼 줄였다.
- **준비 시간:** `system_02_B` 기준 1배 약 240ms, 2배 약 765ms다. v11(약 172ms / 660ms)보다 70~105ms 늘었다. 습도 계산과 정점 보간 때문이다.
- **확인하지 않은 것:** 플레이어 빌드, 낮 조명과 실제 플레이 시점에서의 인상, 다른 seed에서 풀 비율이 치우치는지.

## 생성기 버전 12: 물길을 따르는 얕은 도랑

2026-11-21, 사용자 승인으로 구현했다. 물이 모이는 경로를 따라 얕은 마른 도랑을 파서, 노이즈 지형이 물에 깎인 땅처럼 보이게 한다. 지형 높이가 바뀌므로 생성기 버전은 12다. 같은 seed라도 v11과 형태가 다르다.

### 방법 (`NaturalTerrainErosion`)

1. 침식 전 높이장으로 흐름 그래프(약 0.6m 셀)를 만든다. 상류 셀이 `erosionMinCells`(40개, 약 12m²) 이상인 셀을 물길 셀로 본다.
2. 물길 머리에서 출발해 아래로 따라가다 이전 도랑과 만나거나 분지에 닿으면 멈춘다. 경로는 0.15m 간격으로 촘촘히 하고 약 0.8m 범위로 부드럽게 다듬는다.
3. **깊이:** 상류 셀 수의 로그에 따라 머리에서 0, 상류 셀 240개(40의 6배)에서 `erosionDepthMeters`(0.2m)다.
   - 단면은 `(1 − t²)²` 모양이다. 반폭은 깊이의 6.5배 이상(최소 `erosionWidthMeters` 1m 기준)이어서 추가 경사가 약 13°를 넘지 않는다. 가운데와 가장자리의 기울기는 0이다.
   - 도랑이 겹치는 곳은 가장 깊은 값을 쓴다.
4. **분지 근처:** 분지 바닥에서 `pondMaxRadiusMeters` + 1.5m 안에는 도랑이 없고, 그 바깥 3m에 걸쳐 깊어진다. 물이 느려지며 퇴적되는 곳을 흉내 내고, 연못이 될 분지의 테두리를 지킨다.
5. **바닥 높이:** 하류로 가며 바닥이 다시 높아지는 곳은 상류 쪽 깊이를 줄여서, 도랑 바닥에 새 웅덩이가 생기지 않게 한다.
6. 이후 `FreeHeight`가 도랑을 포함한 높이를 돌려준다. 흐름 그래프를 침식된 높이로 다시 만들어 강·연못·습도 색을 계산하므로, 강은 골짜기를 따르고 도랑은 습도 색에서 풀 줄로 보인다.

`erosionDepthMeters = 0`이면 침식 단계를 건너뛰고 v11과 비트 단위로 같다(행성 8곳, `TerrainPrepFingerprint.RunNoErosion`).

### 조정 과정

- **처음 설정(상류 셀 15개부터 도랑):** 반경 12m 행성에 도랑이 84개, 총 약 480m로 너무 촘촘했다. 분지로 들어가는 도랑이 연못 테두리를 열어 흐름 기반 강이 실패하는 행성도 있었다.
- **분지 근처 도랑 감쇠:** 감쇠만으로는 얕아지는 구간에서 바닥이 하류로 높아져 새 웅덩이가 생겼다. 그래서 바닥 높이 보정을 추가하고, 감쇠 시작을 연못 최대 반경 바깥으로 옮겼다.
- **최대 깊이 기준:** 처음에는 상류 셀 800개(20배)에서 최대 깊이에 닿게 했는데, 셀이 3,920개뿐인 작은 행성에서는 거의 파이지 않았다. 그래서 6배로 낮췄다.
- **기본 깊이:** 0.15·0.2·0.25를 비교해 0.2로 정했다. 밤 조명에서 0.15는 거의 보이지 않고, 0.25는 명암 경계와 윤곽에서 갈라지는 도랑이 뚜렷하다.

### 검증

- **생성:** 여정 612101·77의 세 챕터 행성 36곳 모두 흐름 기반 강과 연못이 생겼고, 추적 방식으로 대체된 곳은 없었다.
  - 강 길이는 8.4~17.1m, 연못 반경은 2.5~4.4m였다. 연결 면적은 99.97% 이상이다.
  - 도랑은 반경 8~12m 행성에서 26~33개(총 130~180m), 반경 21~24m 행성에서 97~117개(500~730m)였다.
- **경사:** 행성 8곳의 15° 이하 면적은 96.5~99.4%(v11 97.0~99.6%), 최대 메시 경사는 27.6~34.4°였다. 30° 초과 면적은 0.01% 이하다. 20개 구역 기준과 `(P90−P10)/q` 1.21~1.69m도 v11 범위다.
- **보행:** 실제 `GravityWalker`로 행성 8곳에서 80개 경로(언덕·분지 왕복, 강 양방향 횡단, 연못 출입)를 기본 이동만으로 걸었고 모두 통과했다.
- **준비 시간:** `system_02_B` 기준 1배 약 240~260ms, 2배 약 850~960ms다(습도 색 버전 약 240ms / 765ms). 침식 전·후 흐름 그래프를 두 번 만들고 높이 계산마다 도랑을 조회하는 비용이다. 도랑 조회는 공간 칸 8개만 보도록 줄였다(결과 동일).
- **화면:** 2챕터 `system_02_B` 1·2배를 깊이 0·0.15·0.2·0.25로 같은 구도에서 촬영했다. [촬영 폴더](../Artifacts/NaturalPlanetTerrain/ErosionV12/) · [검증 로그](../Artifacts/NaturalPlanetTerrain/ErosionV12Validation.txt)
- **확인하지 않은 것:** 플레이어 빌드, 실제 플레이 시점과 낮 조명에서의 인상, 도랑 위 바오밥 후보의 체감 분포.

## 남은 검증과 튜닝

- 연결 영역은 경사·지면·캡슐 검사를 표본화한 추정치다. 임의의 두 지점 사이를 모든 실제 입력과 카메라 조건에서 걸을 수 있음을 보장하지 않는다.
- 21개 표본에서는 강이 생겼다. 다른 시드나 수동 설정에서는 적합한 물길을 찾지 못할 수 있으며 Plan에 탐색 결과가 남는다.
- 버전 8의 2배 표본에서는 생성 완료까지 약 2.3초가 걸렸다(버전 9의 같은 세션 비교는 위 표). 손으로 플레이하는 장기 난이도, 더 넓은 시드 표본에서의 강·배치 성공률과 생성 시간 분포는 별도로 확인할 항목이다.
